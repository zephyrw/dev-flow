# DevFlow

**极简的模型调度器，也是你的 AI 开发工作流。**

让擅长思考的模型负责规划与复核，让擅长执行的模型负责开发和测试。

不必在多个模型之间反复复制需求、计划和错误日志。DevFlow 把这些步骤连接起来，让你在一个工作台确认计划、查看进度、反馈问题和验收结果。

## 少做交接，多关注结果

**模型各司其职。** 选择谁负责规划与复核，谁负责开发与测试，任务衔接交给 DevFlow。

**同一个需求持续推进。** 从计划确认到开发、测试和复核，发现问题就在原任务中继续处理，不必重新整理背景。

**看得见，也能控制。** 查看 AI 正在做什么，方向不对就停止并反馈；需要授权和功能确认时，由你决定。

**交付前能看清改动。** 聚焦本次修改，验收通过后再落到本地任务分支；推送或发布仍由你另行提出。

## 开始使用

> **当前为开发预览，正式安装包尚未发布。** GitHub Releases 尚无公开版本，下列“一行安装”是发布后的目标入口，**现在还不能用来安装**。

### 发布后将提供的一行安装（尚未上线）

正式发布并完成匿名安装验收后，将提供如下命令（当前请勿视为可用）：

macOS / Linux（目标形态）：

```bash
bash -o pipefail -c 'curl -fsSL https://github.com/zephyrw/dev-flow/releases/latest/download/install.sh | bash'
```

Windows PowerShell（目标形态）：

```powershell
irm -ErrorAction Stop https://github.com/zephyrw/dev-flow/releases/latest/download/install.ps1 | iex
```

安装后会打开工作台，按页面提示连接编程助手、选择模型并完成必要授权。日常打开使用统一入口 `devflow`（发布后提供）。固定版本安装、本地完整成品安装与更新/恢复说明见 [安装与升级](docs/guide/安装与升级.md)。

### 当前开发预览怎么跑

在具备源码与开发工具链的前提下，从源码构建并启动本地服务，再打开工作台。步骤与版本要求见 [开发指南](docs/development/开发指南.md)。这是给开发者和早期试用者的路径，不是普通用户的默认安装方式；`scripts/install-windows.ps1` 仅作**开发者源码安装**兼容入口，不作为用户默认入口。

## 试试第一个任务

当前已验证的使用入口是 **Codex**：在 Codex 中打开你要修改的项目，新建任务并输入：

> 用 DevFlow 帮我修复客户列表筛选的问题：选择负责人后，列表没有变化。请先给我计划，等我确认后再开始修改。

在工作台确认计划后，继续查看开发与测试过程。发现问题可反馈修复，功能符合预期后再确认验收。

更完整的步骤（计划审批、授权、暂停与反馈、验收、恢复）见 [使用指南](docs/guide/使用指南.md)。其他编程助手已有适配层，但真实工作流尚未逐项认证，详见 [客户端兼容性](docs/guide/客户端兼容性.md)；不要把未验证路线当成与 Codex 同级的完整可用入口。

## 从需求到验收

```mermaid
flowchart LR
    A[提出需求] --> B[确认计划]
    B --> C[AI 开发与测试]
    C --> D[代码复核]
    D -->|需要修改| C
    D --> E[你实际验收]
    E -->|发现问题| C
    E --> F[最终复核与本地交付]
```

上图为简化的用户视角，不改变计划审批、两阶段代码质量审查和人工功能确认的真实规则。

## 核心收益

| 你关心的 | DevFlow 怎么帮 |
|---|---|
| 模型分工 | 规划与复核、开发与测试可以交给不同助手/模型，减少手工传话 |
| 自动交接 | 计划、开发、测试、复核在同一需求里续接，问题在原任务继续修 |
| 实时可控 | 过程可见；可暂停、授权、反馈，需要时停止 |
| 问题续修 | 验收前发现问题就反馈，修复不必另起炉灶 |
| 交付边界清晰 | 聚焦本次变更；本地提交与你另行要求的推送/发布分开 |

平台负责调度与过程呈现，不核验测试证明，也不代替你做功能验收。

## 工具与系统支持

**编程助手（八种）**：Codex、Antigravity CLI（agy）、Claude Code、Cursor Agent、Kimi Code、Grok Build、Qoder、OpenCode 均有适配已实现；**真实工作流未认证**（`live_workflow_verified: false`）。发现客户端 ≠ 已完成真实模型任务。当前文档以 **Codex** 为已验证入口。

**平台**：`win32-x64` 为本地回归已测（`local_regression_tested`）；`win32-arm64`、`darwin-x64`、`darwin-arm64`、`linux-x64`、`linux-arm64` 为 `unverified`。矩阵与证据类型见 [客户端兼容性](docs/guide/客户端兼容性.md) 与仓库根目录 `compatibility.json`。

**打开应用**：开发预览下双击安装/源码目录中的“打开 DevFlow”，或在服务运行时访问 `http://localhost:4810`。关掉浏览器不会停止任务。

## 常见问题

**DevFlow 送模型账号或额度吗？**  
不送。模型账号、订阅和额度来自你使用的编程助手/模型提供方；能否复用订阅以该工具的实际授权为准。

**本地运行是不是等于项目内容绝不外发？**  
不是。DevFlow 应用与工作台在本机运行，但调用云端模型时，会按所用客户端/模型的既定方式发送任务所需内容。不要把“本地安装”理解为“任何内容都不会离开这台机器”。

**安装 DevFlow 要自己编译源码吗？**  
正式发布后不需要。开发预览阶段需要源码与开发工具链，见 [开发指南](docs/development/开发指南.md)。跑**你的业务项目**仍可能需要 Git、语言运行时和数据库等，这与是否安装 DevFlow 是两件事。

**关掉浏览器任务会停吗？**  
不会。关闭网页不等于停止任务；要停止请在任务页使用“暂停”。

**会不会自动推送或发布生产？**  
不会。本地任务分支提交与推送/发布保持既有授权边界：需要推送、合并或发布时，由你明确提出。

**更新或出问题怎么办？**  
见 [安装与升级](docs/guide/安装与升级.md) 与 [使用与恢复指南](docs/guide/使用与恢复指南.md)。
