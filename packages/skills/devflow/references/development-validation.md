# 开发验证与交付边界

本约定供规划、开发、执行测试和提交角色使用。检查由执行阶段完成，不新增平台关卡、测试证明工具或规划复核审计。

## 分开检查与报告

源码或测试代码变更完成并整合后，执行模型分别完成项目正式类型检查、生产构建及受影响测试。使用项目原生工具；JavaScript/TypeScript 项目必须确认类型检查包含产品代码、测试夹具和测试导入模块。Vitest、Playwright 或其他工具仅转译后运行断言时，测试通过不能代替类型检查；排除 tests 的生产编译不能代替全项目检查。没有类型系统的项目不凭空新增 TypeScript 要求。

类型检查与构建不是测试套件，不受“每条测试命令一个目标”的筛选限制。需要编译产物的测试先使用当前源码构建；独立测试仍按具体文件、类或用例执行，不退回无筛选全量套件。不得机械复用固定的少数集成文件而漏掉本轮改动、新增测试及关联回归。纯文档或技能说明变更按内容、引用、格式和技能结构验证，无需运行无关源码构建与测试。

测试夹具跟随正式接口更新：必需字段、字面量类型、构造依赖、取消与结果句柄和模型/账号作用域都应完整有效。JavaScript 模块被 TypeScript 导入时提供与真实导出匹配的类型边界。不得以关闭 strict、泛化 any、错误强制断言、删除场景、skip、恒真断言或 continue-on-error 隐藏失败。

## 结果必须仍适用于待交付代码

验证结论对应实际验证的代码状态、检查范围和环境。检查后修改代码或合并其他变更时，由执行模型判断影响，重跑受影响的检查；源码、测试或类型边界变化影响全项目类型检查时补跑该检查。未受影响的已通过目标保留，不要求重跑整个套件。其他 worktree、旧提交或旧构建的通过结果不能直接套给当前候选代码。

类型检查、生产构建、单元、集成、E2E、适用的 OpenTabs 与跨平台 CI 分别报告通过、失败、未执行或不适用。报告已有实际命令、范围、结果及限制即可，不创建签名、账本、哈希证明链或测试真实性审计系统。部分测试通过、进程已启动、构建成功、本地更新成功和四平台 CI 通过是不同结论。

已知必需检查失败或未执行时，不能宣称验证完成、正常交付就绪或发布验证通过。先定位并修复本任务及必要关联问题，再定向验证。历史失败也须明确说明对当前候选的影响，不能仅标为“既有错误”后带病完成；无关问题或真正超出授权的修复不擅自扩展，报告受阻部分并继续独立工作。用户已明确接受的范围限制按原授权保留，不能隐瞒失败，也不反复请求已给出的授权。纯保存进度或明确授权的未验证提交，须说明用途和未验证项，不能冒充完成交付。

## 职责与发布

规划阶段为本任务写清所需检查和影响范围；执行开发、自测、整改、功能修复及 executor_test 负责实际检查和必要重跑。规划质量复核仍只审代码质量；可指出夹具不符合接口等静态代码缺陷，不追查测试报告或执行声明。planner_takeover 不跑测试、构建或类型检查，改完交执行测试。planner_commit 只按已交接的范围暂存提交，不自行补跑检查或修代码；交接已有未解决的必需检查失败时，说明阻塞并回执行处理，不把提交本身说成验证完成。

GitHub 或其他 CI 已报红时，不能说该候选已通过 CI；继续使用当前正式质量流程。推送、重跑远程 jobs、真实付费模型调用和发布仍按用户已有授权，不因补检查扩大授权。原职责路由、人工功能确认和平台轻量调度保持不变。
