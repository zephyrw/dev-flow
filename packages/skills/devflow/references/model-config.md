# 工具、模型与授权边界

系统默认只有规划、执行两个槽位。审查、审查整改、功能修复是任务级三项高级覆盖，默认跟随规划或执行，不能写进系统默认。

保存后从下一次派发生效；当前正在运行的一轮继续使用已冻结配置，不会中途换模型。不能因为目录里出现“更合适”的条目就自动更换工具或模型。

首次对某工具/账号/模型组合的授权验证成功后，后续任务与后续轮次复用该结果，不是每轮再探测。工作模型不能自行改变全局默认，也不能切换自己正在使用的模型。

四层状态互相独立，不能互相冒充：

1. 目录成功：工具可列出模型，不代表已登录。
2. 登录成功：客户端已登录，不代表当前模型可调用。
3. 访问成功：该模型已通过授权验证，不代表本次业务已经跑通。
4. 业务验证成功：当前任务的测试与验收通过，与模型目录或登录状态不是同一回事。

`--tools` 只用于客户端配置和 Skill 分发，不代替默认规划/执行角色。旧外部规划会话不能被平台原地换模型；若要用平台新模型重新规划，走现有规划反馈入口触发新 Run。
