## 指定计划为执行依据，禁止执行模型另建计划

首次需求没有计划时制定计划；已有用户指定/批准的原计划及正式引用继续作为执行依据。恢复、审批、普通修复和整改不能覆盖原计划；明确授权的范围变化在原文中补充，不另建版本或副本。

完整读取原文并保留原路径和任务/验收编号。禁止另建 implementation_plan.md、客户端计划工件或局部实施计划替代原文，禁止借细化缩减范围、接口链路或验收条件。同一模型兼任多个角色也不能自行批准改变范围。

允许在原计划更新 checkbox、事实状态和问题说明；只有实际完成才将 `[ ]` 改为 `[x]`，已派发、阶段推进或口头声明不等于完成。已有过程记录可按原编号说明实现、测试和未完成原因，不替代原计划，也不为恢复再建一份计划。

原文确有不可实施的设计冲突时，提交原章节、代码事实和影响，只暂停受阻部分。规划角色保留原文并补充必要说明；改变业务需求/批准范围才取得用户确认，范围内普通修复不重新规划或重做已完成工作。

以 MCP `devflow_submit_plan` 暴露的参数 Schema 为结构参考，不要求业务项目包含 DevFlow 自身源码。按接口传递工作流 ID、并发版本、幂等键和 `plan`；内部审批身份与并发字段不等于要求文档版本或副本。

先读取登记项目的完整配置；每个仓库基线必须是已核实的 commit ID。

## 开发说明书的详细设计

先说明背景、现状、目标、制定原因和总体方案。依据真实代码、表结构、接口及调用链确定改动和复用点，说明关联影响、必须保留的行为以及选择该方案的依据。区分已核实的现状与拟议设计。按实际影响写下列内容，密集的技术细节可放在对应任务之后或正文附录。

- **数据库设计。** 逐表标注新增、修改或复用。新增或修改的表给出完整目标结构，包括字段名和含义、类型、长度或精度、可空性、默认值、主键、唯一约束、索引及列顺序、表关系和完整性规则。复用的表写清涉及字段和读写约束。涉及迁移时按实际数据库方言给出迁移 SQL 或等效迁移定义，说明历史数据回填规则、迁移校验、上线顺序、兼容窗口和失败后的回滚或恢复。
- **接口契约。** 逐个列出新增、修改或废弃的接口与受影响调用方。写明 HTTP 方法和路径，或非 HTTP 接口的名称、签名或消息主题。给出请求、响应及错误的字段、类型、必填、默认值、取值和校验，明确返回状态和错误码、认证、权限、数据隔离及兼容策略。按需写清分页、排序、幂等键等约定，保留容易误解的请求或响应示例。
- **流程、规则与边界。** 对关键步骤写清触发条件、处理顺序、数据读写及可观察结果。按实际范围覆盖空数据、非法或临界输入、权限和隔离、重复提交、并发、超时、重试、部分失败及历史数据。涉及事务时写明哪些修改一起成功或回退。涉及异步任务或状态流转时，写清进入条件、允许的转换、幂等、重试终止和失败恢复。每个关键分支给出验收预期。
- **页面需求。** 写明入口、角色、展示数据及来源、可操作条件、完整交互流程和适用的加载、空、错误、成功等状态。写清操作后的可见结果与验收方式。用户指定的界面要求纳入计划，其余布局、样式、动效和组件选型由执行模型决定。

按功能或用户流程拆成细项 checkbox 任务。保留稳定编号，每项说明用途、具体行为、真实依赖、对应设计和可观察的完成条件。执行模型负责内部代码组织、具体写法和必要接线，遵守用户明确的权限、数据保护和环境边界。`task.paths` 可省略，填写时只用于定位。`plan.scope` 和旧路径字段只作兼容元数据，不得划定文件或目录修改白名单。

提交前逐任务检查，确认执行模型无需补做业务行为、数据结构、接口契约、边界处理和验收的设计判断即可实现。规划模型自行解决能从代码和已知需求确认的问题，只向用户澄清确实无法推导且影响实现的业务取舍。仅为本次涉及的领域写详细设计。

新计划优先使用 `task_model: "native-v2"`。在 `native-v2` 下：
- 正文保存完整需求和详细设计。结构化的需求、模块 `modules`、任务 `tasks`、验收项 `tests` 与依赖只作精简索引；
- 验收项使用稳定业务编号，规定验证层次、场景和预期结果；具体测试名称、命令参数不在规划阶段锁定，由执行模型编写具体测试用例；
- 索引不重复存储整段正文，执行模型通过原生文件工具直接阅读完整设计正文。

测试责任覆盖 unit、integration、e2e 三层；存在前端影响时，增加 OpenTabs 仿人工真实浏览器核验责任，正文写清真实操作场景、截图/可见数据预期与认证策略（身份无关优先匿名/免密开发会话；依赖角色/租户规划真实测试身份；确需人工登录时走通用人机交互）。不适用的测试层需填写具体理由并随计划批准。计划正文、图解和索引用于表达与展示，不强制增加 machine-readable 测试证明字段，不作为角色切换质量门槛。人工功能确认另行保留。

实际测试遵守 devflow-test：按实际条件安排多个子 Agent 并行测试独立目标，每条命令只指定一个测试类、文件或用例，各自修复和定向重跑；只有真实依赖或资源冲突局部串行，禁止无筛选全量套件。保留已完成且未受影响的结果。此为 Skill 中的执行约定，不要求复制到计划正文，不添加核验字段或交接门禁。

调用 submit_plan 后给用户审批地址并结束当前回合。

开发和审查的独立范围仍按对应 Skill 并行分工，主 Agent 协调共享接口与真实依赖；审查只读，主审汇总跨模块问题，不核验测试声明。正文只需说明本任务必要的协作边界，不粘贴通用调度纪律，不增加平台门禁。
