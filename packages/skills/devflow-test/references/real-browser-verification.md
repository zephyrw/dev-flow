# OpenTabs 仿人工真实浏览器核验规范

> 本规范指导执行模型在完成前端相关开发后，使用 OpenTabs 原生工具对真实浏览器进行仿人工核验。此职责由执行模型自主落实，不属于平台质量关卡或工作流拦截器。

---

## 1. 触发范围与原则

1. **触发条件**：
   - 凡变更涉及用户在页面上的操作、数据展示、视觉效果或状态反馈，必须执行 OpenTabs 真实浏览器核验。
   - 包括但不限于：组件、页面布局、CSS 样式、路由与跳转、表单与交互控件、前后端数据接线、WebSocket 实时推送、权限与角色展示、以及后端接口变动导致的页面行为改变。
2. **纯后端任务说明**：
   - 若任务确认纯属后端且不影响任何前端页面行为，执行模型须在测试记录中说明“不适用”及调用链事实依据。
   - “未安装浏览器”、“工具未连接”、“本地服务启动失败”均属**环境阻塞**，严禁标记为“不适用”或假冒通过。
3. **与三层自动测试的关系**：
   - 自动测试仍按单元、集成、E2E 三层组织，三层测试不降级、不被替代。
   - 普通 Playwright/Cypress 等自动 E2E 不能替代本轮 OpenTabs 仿人工核验。本轮重点是执行模型亲自操作真实浏览器、观察真实渲染截图与显示数据。

---

## 2. 执行时序与并行规则

1. **时序要求**：
   - 正式计划中的全部功能、接线、边界处理及测试代码全部完成后，再进入测试阶段。
   - OpenTabs 核验在开发完成后进行，被核验页面与对应后端必须是完整、当前、可运行的版本。
2. **多 Agent 协作与浏览器资源控制**：
   - 共享同一个浏览器实例或连接时，必须由单一操作负责人负责“前台切换—操作—截图—核验”。
   - 其他子 Agent 可并行执行单元测试、集成测试或非浏览器的独立测试目标。
   - 严禁多个 Agent 同时抢操同一个浏览器标签页，避免会话串扰与状态竞争。

---

## 3. 标准核验十步法

1. **读清验收依据**：以原批准计划和验收项为准，逐项列出本轮涉及的页面场景、输入、预期展示与受影响回归，不另立计划。
2. **确认环境身份**：核对工作目录、前后端端口、API 代理、数据目录与构建版本，确认浏览器访问的是当前 worktree 隔离实例，而非主工作区或其他实例。
3. **准备数据与会话**：准备确定性的测试数据；按《本地免密与认证策略规范》选择无交互访问方式。业务操作必须随后在 UI 界面真实触发。
4. **连接工具**：发现本机原生客户端提供的 OpenTabs 工具及其参数定义，记录使用的连接与标签页信息。
5. **从页面入口实际操作**：真实点击按钮、输入表单、展开菜单、触发校验、提交、筛选、翻页、刷新或返回；覆盖正常流、禁用态、加载态与异常流。
6. **核对业务结果**：检查操作后页面实际呈现的数据与状态；对有持久化要求的场景执行刷新或重新进入，验证数据确实落盘。
7. **实际查看截图**：在关键步骤和状态调用截图工具，并将生成的图片交由模型的视觉能力实际查看，检查布局间距、文本溢出、遮挡、层级和响应式表现。严禁只存图不看。
8. **读取可见数据**：通过 DOM/脚本/CDP 能力读取实际渲染的文本、表单值与控件状态，核对格式与业务值；必要时观察实际网络请求与 WebSocket 消息。
9. **修复与定向重跑**：发现问题由负责 Agent 修复并定向复测失败场景，不因单个问题重复跑无关测试。
10. **收尾与资源清理**：关闭本次测试创建的标签页，清理网络捕获和模拟配置，保留等待用户登录的标签页；不清理用户的其他页面。

---

## 4. 工具使用原则与红线

1. **基于发现的能力调用**：
   - 常见工具如：`browser_open_tab`、`browser_click_element`、`browser_type_text`、`browser_screenshot_tab`、`browser_get_tab_content`、`browser_execute_script`、`browser_enable_network_capture` 等。
   - 工具名和参数以本机发现为准。严禁私自开启无认证的外部远程调试端口。
2. **严禁前端造假**：
   - DOM 与脚本执行主要用于只读观察和定位。
   - **绝对禁止**使用脚本直接修改 React/Vue 内部状态、直接调用前端全局 store、直接调用业务保存 API，或直接操作 DOM 写入假数据来假冒操作完成。
3. **登录页隐私保护**：
   - 涉及密码输入、短信验证码、扫码或第三方 OAuth 登录时，必须停止对该页面的抓包与截图。
   - 严禁记录密码、验证码、Token、Cookie 等敏感凭据。
   - 用户确认完成登录后，执行模型必须重新检查当前 URL、登录状态和页面可访问性，确认无误后方可继续业务链路。用户点“确认”不等于系统直接判定测试通过。
