---
name: devflow-project-onboard
description: 调查新项目的真实运行方式，确定仓库、环境隔离和测试配置并生成可审批接入合同
---

1. 读取用户指定仓库及项目规则，登记单仓/多仓、真实 Git common directory 与基线。
2. 从实际配置、脚本和代码定位技术栈；不假设前后端框架或默认端口。
3. 查明启动、构建、单元、集成和 E2E 命令及真实报告格式。
4. 确定命令入口、参数数组、cwd、环境变量和依赖，不允许任意 shell 文本。
5. 明确数据库、缓存、消息、注册中心、定时任务及外部服务的测试隔离规则。
6. 明确动态端口、前端 API 目标和运行身份标记的最小接入修改。
7. 按 `../devflow-test/SKILL.md` 确定真实 E2E 入口、浏览器/后端/测试数据隔离、测试账号引用和新需求及旧功能回归范围；Web E2E 自带真实浏览器验证，不另设 OpenTabs 测试层。保留用户功能确认清单。
8. 对业务行为和环境归属的已知疑问先询问用户，随后形成唯一确定配置。
9. 根据 devflow_register_project 的参数合同生成项目配置和测试命令，直接登记；新项目不要求 browser_scenes，使用其默认空列表。用户不填写或导入 JSON。
10. 回到 devflow_start，为原始需求制定同一个完整计划。端口、前端代理和健康检查所需的最小代码适配一并列入计划，在人工批准后由执行模型完成。
11. 配置登记本身不执行命令；环境在实施完成后准备。将运行配置和数据范围写入审批正文。不得重装 OpenTabs、覆盖个人模型配置或创建/切换 Windows 用户。
