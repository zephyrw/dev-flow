# DevFlow 安装与灾难恢复指南

本文档依据《DevFlow跨平台通用平台实施复核与详细整改要求-20260916.md》编写。平台兼容实现与实际验证状态以 compatibility.json 和最新验收记录为准，不能把跨平台源码或本机测试视为已完成 macOS 实机认证。

## 一、安装与环境就绪

### 1. 自动引导安装
平台支持通过 bootstrap 脚本执行安装并自动配置宿主守护进程及 6 个 DevFlow 官方 Skill：

- **Windows (PowerShell)**:
  ```powershell
  .\scripts\bootstrap\install.ps1 -Source . -SelectedTool agy
  ```
- **macOS / Linux (Shell)**:
  ```sh
  ./scripts/bootstrap/install.sh --source . --tool claude-code
  ```

### 2. 退出码含义
- `0`: 安装/升级自检完成，服务健康可用。
- `10`: 服务与 Skill 已安装，但所选客户端缺失、探测超时或需要登录；不能当作全部组件及真实模型认证完成。
- `20`: 源码或资产下载/哈希校验失败。
- `30`: 配置冲突（如受管文件已被用户修改且存在未提交差异）。
- `40`: bootstrap 不支持当前操作系统或缺少引导工具。安装包缺项或运行时版本不满足要求返回 `20`。
- `50`: 守护进程或 HTTP 服务健康探测失败。

## 二、运行状态恢复与容灾机制

### 1. 进程树强杀与超时容灾
Go 宿主进程通过原生 JobObject（Windows）或独立进程组（POSIX）纳管所有被派发子进程：
- 当任务触发 `TimeoutMs` 超时或收到用户显式停止指令时，宿主会一次性级联清理整棵子进程树；
- 管道流将主动关闭并触发 EOF，避免 Windows 命名管道或异步任务挂起。

### 2. 崩溃重启恢复
- 平台基于 SQLite WAL 模式与事务隔离；
- 服务重启时，调度器处理尚未启动的持久化派发意图；已经开始但无法确认结束的运行进入恢复检查，不重复执行，也不自动恢复用户暂停的任务。

### 3. Git 暂存与工作区保护
- 在主工作区直接交付模式下，DevFlow 使用临时独立 `GIT_INDEX_FILE` 构建提交，绝对不会对用户的工作区执行 stash、reset 或将用户原有的 staged/unstaged 修改混入交付 commit 中；
- 若提交或合并中断，恢复流程将从落盘的 `CommitIntent` / `IntegrationIntent` 继续对账推进。
