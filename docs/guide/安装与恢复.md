# DevFlow 安装与灾难恢复

安装、更新与日常恢复入口见 **[安装与升级](安装与升级.md)**。本文说明容灾机制与失败后的恢复边界。平台兼容实现与实际验证状态以 [客户端兼容性](客户端兼容性.md) 和仓库根目录 `compatibility.json` 为准，不能把跨平台源码或本机测试视为已完成 macOS 实机认证。

> **当前为开发预览，正式安装包尚未发布。** 成品安装命令见 [安装与升级](安装与升级.md) 中的“发布后目标形态”（尚未上线）。开发预览请从源码构建，见 [开发指南](../development/开发指南.md)。`scripts/install-windows.ps1` 仅为**开发者源码安装**入口。

## 一、安装与环境就绪（概要）

普通用户在正式发布后使用一行安装，不需要 Node、pnpm、Go 或 C/C++ 编译工具来构建 DevFlow。开发期从源码安装时：

- **Windows (PowerShell，开发者源码安装)**:
  ```powershell
  .\scripts\bootstrap\install.ps1 -Source . -SelectedTool codex
  ```
- **macOS / Linux (Shell，开发者源码安装)**:
  ```sh
  ./scripts/bootstrap/install.sh --source . --tool claude-code
  ```

上述 `--source` 路径属于开发者/本地成品安装，不是“clone 后自动构建”的别名，也不是用户默认入口。参数契约见 [安装与升级](安装与升级.md)。

### 退出码含义（bootstrap）

- `0`: 安装/升级自检完成，服务健康可用。
- `10`: 服务与 Skill 已安装，但所选客户端缺失、探测超时或需要登录；不能当作全部组件及真实模型认证完成。（兼容保留；模型未配置在默认安装中属于待设置状态，不以 10 作为全局失败语义的唯一来源，详见 [安装与升级](安装与升级.md)。）
- `20`: 源码或资产下载/哈希校验失败。安装包缺项或运行时版本不满足要求也返回 `20`。
- `30`: 配置冲突（如受管文件已被用户修改且存在未提交差异）。
- `40`: bootstrap 不支持当前操作系统或缺少引导工具。
- `50`: 守护进程或 HTTP 服务健康探测失败。

## 二、运行状态恢复与容灾机制

### 1. 受管进程树与超时容灾

DevFlow 使用 **Node 运行时**与平台 native 层（Windows 经 `koffi` 调用系统接口）纳管派发子进程，不再使用旧 Go Host（历史说明：早期方案曾规划 Go 宿主，现已移除，见技术栈整改记录）。

- 当任务触发超时或收到用户显式停止指令时，受管进程按所有权清理对应子进程树；不使用 `taskkill /IM node.exe`、`pkill node` 之类全局杀进程。
- 进程状态未知时保持未知，不能为让安装/升级继续而假定退出。
- 管道流将主动关闭并触发 EOF，避免异步任务挂起。

### 2. 崩溃重启恢复

- 平台基于 SQLite（`better-sqlite3`）WAL 模式与事务隔离；
- 服务重启时，调度器处理尚未启动的持久化派发意图；已经开始但无法确认结束的运行进入恢复检查，不重复执行，也不自动恢复用户暂停的任务。

### 3. Git 暂存与工作区保护

- 在主工作区直接交付模式下，DevFlow 使用临时独立 `GIT_INDEX_FILE` 构建提交，不会对用户的工作区执行 stash、reset，也不会将用户原有的 staged/unstaged 修改混入交付 commit 中；
- 若提交或合并中断，恢复流程将从落盘的 `CommitIntent` / `IntegrationIntent` 继续对账推进。

普通用户日常使用不必手工操作 `GIT_INDEX_FILE` 或手改 YAML；上述机制由平台内部处理。

### 4. 更新失败与数据边界

更新/升级事务、备份与“禁止盲目回滚数据库”等规则见 [安装与升级](安装与升级.md)。默认卸载只移除本应用入口与程序文件，保留任务数据、业务项目与账号保险库。

### 5. 历史文档

旧架构（Go Host、旧认证 Host）与迁移说明保留在 `docs/plan/`、`docs/design/` 与 `docs/process/` 的历史文档中，仅供追溯，不再作为安装或恢复的操作依据。
