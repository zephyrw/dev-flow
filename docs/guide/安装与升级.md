# DevFlow 安装与升级

> **发布状态：当前为开发预览，正式安装包尚未发布。** GitHub Releases 目前没有公开版本；下文“一行安装”是发布后的**目标形态**，在脚本作为正式 Release 资产发布并按原样验收前**不可当作可用命令**。开发预览请从源码构建，见 [开发指南](../development/开发指南.md)。

用户得到的应是可安装的应用，而不是要求先成为维护者的源码工程。正式发布后：照 README 执行一行命令安装并打开应用，之后在界面完成编程助手接入、必要的官方授权和模型设置；打开、更新和恢复都不需要回到源码目录执行构建。

## 1. 一行安装（目标形态，尚未上线）

仅在安装脚本作为正式 Release 资产发布、且按原样完成匿名安装验收后启用。GitHub 的 latest 资产入口对应正式版；草稿与预发布不能作为 latest。

macOS / Linux：

```bash
bash -o pipefail -c 'curl -fsSL https://github.com/zephyrw/dev-flow/releases/latest/download/install.sh | bash'
```

Windows PowerShell：

```powershell
irm -ErrorAction Stop https://github.com/zephyrw/dev-flow/releases/latest/download/install.ps1 | iex
```

约束（发布实现须满足，文档不提前宣称已满足）：

- 保留外层 `pipefail`，使下载失败不会被空 Shell 掩盖。
- PowerShell 入口不得以顶层 `exit` 终止用户的交互窗口；失败应可被严格自动化调用方识别。不修改全局执行策略，不要求关闭系统安全功能。
- 正式脚本带入该版本的不可变标签或可信 manifest 绑定信息，**版本解析只做一次**：用户经 latest 得到脚本后，脚本固定下载同一标签下的 manifest 与成品，不在安装中途再次解析 latest。
- 稳定版不悄悄安装预发布；预发布必须指定版本。
- 同源 SHA-256 校验保证包与清单一致（不等同于发布者独立签名）。
- 安装不要求管理员权限。下载中断、磁盘不足或校验失败不得改变现用版本。

默认首页只展示各平台的一条命令，不并列多套互相冲突的主入口。高级路径见下文。

## 2. 安装参数（目标契约）

| 用户目的 | Shell 参数 | PowerShell 参数 | 约束 |
|---|---|---|---|
| 普通安装 | 无参数 | 无参数 | 装好即打开；客户端和模型可稍后配置。 |
| 固定版本 | `--version` | `-Version` | 严格匹配标签、版本及平台，不回退 latest。 |
| 指定目录 | `--install-dir` | `-InstallDir` | 支持空格、中文，不改写业务项目目录。 |
| 无浏览器启动 | `--no-open` | `-NoOpen` | 完成服务安装并打印地址。 |
| 严格就绪检查 | `--require-ready` | `-RequireReady` | 仅此模式把未完成工具设置作为非成功状态。 |
| 安装本地完整成品 | `--source` | `-Source` | 不是 clone 仓库自动构建的别名；离线安装不暗中联网补依赖。 |

已有工具与模型参数继续兼容高级使用；普通安装不默认替用户配置 Codex。“不指定客户端、稍后设置”应是合法状态。默认安装的成功条件是软件可运行；模型未配置是 onboarding 状态。内部旧调用依赖退出码 `10` 的语义须保留兼容，不能全局改掉 `10`。

高级路径还包括：

- **先下载、审阅后运行**：将脚本与清单下载到本地核对后再执行。
- **固定版本安装**：指定标签，适合复现与回滚到已知版本。
- **本地完整成品安装**：对已下载的平台成品执行离线安装。

## 3. 支持条件

| 项 | 说明 |
|---|---|
| 普通使用 | 不需要安装 Node、pnpm、Go 或 C/C++ 编译工具来构建 DevFlow；成品内置运行环境与生产依赖。 |
| 原生依赖 | 成品须正确分发 `koffi`、`better-sqlite3` 等平台匹配依赖，不要求用户 `npm rebuild` / `pnpm install` 补齐。 |
| AI 客户端 | 按需安装编程助手并完成其官方登录/授权；未安装客户端不阻止软件安装，只影响该工具接入。 |
| 业务项目 | 可能仍需要 Git、语言运行时、数据库等；这是项目自身要求，不是打开 DevFlow 的前置阻塞。 |
| 平台 | 当前发布矩阵候选为 `win32-x64`、`darwin-x64`、`darwin-arm64`、`linux-x64`；**只有验收通过的平台才公开标注可用**。现状见 [客户端兼容性](客户端兼容性.md)（目前仅 `win32-x64` 为本地回归已测，其余 unverified）。未知或 32 位架构不得一律映射成 x64。 |
| 路径 | 安装目录支持中文与空格。 |

DevFlow 自身依赖、AI 客户端的安装授权、业务项目的 Git/语言/数据库是三件不同的事。

## 4. 安装后打开

- 日常入口：统一命令 `devflow`（发布后提供；默认打开工作台，`devflow open` 为显式别名）。Windows 创建开始菜单入口；macOS/Linux 使用平台可用的桌面入口。安装后可通过绝对路径立即打开，不依赖当前终端 PATH 已刷新。
- 管理入口（少量）：`status`、`doctor`、`stop`、`update`、`uninstall`。`--help`、`--version` 在配置损坏和数据库不可用时仍应能工作。
- 浏览器未自动打开时：按安装输出的地址访问，或再次运行 `devflow`。关掉浏览器不停止任务。
- 首次设置：选择编程助手、选择“规划与复核 / 开发与测试”分工、按需官方登录并验证模型访问，然后使用第一条任务示例（见 [使用指南](使用指南.md)）。默认成功语义是“软件已安装并打开设置页”，不是“全部模型已就绪”。

当前开发预览下的打开方式：双击“打开 DevFlow”，或在服务运行时访问 `http://localhost:4810`。

## 5. 更新

更新遵循与安装相同的事务边界（细节由安装器实现，本文为用户视角）：

1. 预下载并校验候选包，不修改当前状态。
2. 确认当前服务属于本安装；若有活动或待派发任务，提示“等待任务结束后更新”或“暂停并更新”，由你明确选择；禁止新派发后再交接。
3. 停稳后备份配置、版本指针与数据库，再切换到新版本并验证实际运行构建。
4. 同一应用版本、不同包摘要：拒绝覆盖，保持当前版本，并提示改用新版本号或独立开发目录。
5. 更新成功后保留至少一个已知可用版本及必要备份；清理旧版本前确认无进程、桥接或引导引用。

失败边界（不承诺任何失败都自动无损降级）：

| 失败阶段 | 默认处理 |
|---|---|
| 下载、摘要、包内自检失败 | 不碰当前版本和数据库；清理临时目录，可重试。 |
| 配置准备失败且尚未写业务状态 | 可按本事务备份恢复；不覆盖你并发修改过的文件。 |
| 已可能写入业务状态后失败 | 保留现场与备份，进入恢复引导；**禁止**自动拷回旧数据库掩盖新写入。 |
| 客户端配置部分写入 | 按变更收据恢复或继续，不留下指向不存在版本的入口。 |
| 进程/资源状态无法确认 | 阻止升级并提供对账；不把 unknown 批量改成已退出。 |

命令行：`devflow update`（发布后）。开发者源码路径的更新不走本节用户契约，见 [开发指南](../development/开发指南.md)。

## 6. 恢复与卸载

- **应用可打开但任务中断**：见 [使用与恢复指南](使用与恢复指南.md) 的“电脑重启或任务中断”。
- **更新后需要恢复**：说明数据已保留；可使用“修复当前版本 / 查看备份与诊断 / 重试目标服务 / 审查后按匹配快照恢复”等入口。新版本已写入业务状态后不自动降级数据库。
- **配置或指针损坏**：引导层应给出可诊断错误，不执行不可信路径，也不偷偷选择另一版本。
- **卸载**（`devflow uninstall`）：默认只移除本应用程序、PATH 区块与系统入口，**保留**任务数据、业务项目与账号保险库。清除任务数据或账号记录须分别明确选择并说明范围；永不删除用户项目目录来“清理工作区”。

容灾机制细节见 [安装与恢复](安装与恢复.md)。

## 7. 当前预览期如何安装

1. 获取源码，安装与 `package.json` engines 一致的工具链（Node ≥ 22.23.2、pnpm 11.7.0）。
2. 按 [开发指南](../development/开发指南.md) 安装依赖并构建。
3. 启动本地服务并打开工作台。

`scripts/install-windows.ps1` 与 `scripts/bootstrap/*` 的 `--source` 模式属于**开发者源码/本地成品安装**，不是本页第 1 节的用户一行安装，也不表示 Releases 已可下载。
