# DevFlow 客户端兼容性

本文按**构建与证据**说明工具、角色和平台支持，不把“适配已实现”写成“真实工作流已认证”。权威数据在仓库根目录 `compatibility.json`（矩阵版本 `3.0.0`，字段已与 Node 运行时/credential worker 对齐；本文描述读取时现状；**不要**用本文替代或手改该 JSON）。

## 1. 四种验证分开看

| 验证类型 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 包构建和 native 加载 | 某系统架构的包可生成，依赖能加载 | 不能证明完整安装、进程生命周期或账号可用。 |
| 安装与工作台 smoke | 可以安装、启动、打开页面、重新打开 | 不能证明真实模型能完成任务。 |
| 工具访问验证 | 指定工具/账号/模型可被实际访问 | 不能证明全部角色、子 Agent 和恢复能力。 |
| 真实工作流验证 | 指定版本和组合完成了规定任务路径 | 不能推广为所有平台和所有模型均支持。 |

验证证据应包含：应用提交、平台、工具版本、模型标识、测试日期、测试类型、结果和可检查的报告位置。未经测试的组合保持 `unverified`；仅有替身（mock/隔离 CLI）测试的项目不标 `live_workflow_verified: true`。

当前策略原文（`compatibility.json`）：*Discovery is not live workflow certification; use dated test evidence.*

| 平台 | 状态 | 含义 |

| `win32-x64` | `local_regression_tested` | 本地回归已测；**不等于**公开安装包已发布，也不等于真实工作流全量认证。 |
| `win32-arm64` | `unverified` | 未验证。 |
| `darwin-x64` | `unverified` | 未验证。 |
| `darwin-arm64` | `unverified` | 未验证。 |
| `linux-x64` | `unverified` | 未验证。 |

发布矩阵候选为 `win32-x64`、`darwin-x64`、`darwin-arm64`、`linux-x64`（见改造计划 §5.5）。脚本能识别某架构不代表已有对应包；Windows arm64、Linux arm64 不因识别能力自动进入首发。Linux libc、最低系统版本与 macOS 最低版本须以实际构建和实测为准，不能把某一发行版通过写成“所有 Linux 可用”。

## 3. 编程助手（工具）

八种工具当前均为：**适配已实现**（`adapter_implemented`）、**真实工作流未认证**（`live_workflow_verified: false`）。

| 工具 ID | 显示名 | 适配 | 真实工作流 | 角色（声明） | 模式 |
|---|---|---|---|---|---|
| `codex` | Codex | 已实现 | 未认证 | planner, executor, tester, reviewer | single, composite |
| `agy` | Antigravity CLI | 已实现 | 未认证 | 同上 | 同上 |
| `claude-code` | Claude Code | 已实现 | 未认证 | 同上 | 同上 |
| `cursor-agent` | Cursor Agent | 已实现 | 未认证 | 同上 | 同上 |
| `kimi-code` | Kimi Code | 已实现 | 未认证 | 同上 | 同上 |
| `grok-build` | Grok Build | 已实现 | 未认证 | 同上 | 同上 |
| `qoder` | Qoder | 已实现 | 未认证 | 同上 | 同上 |
| `opencode` | OpenCode | 已实现 | 未认证 | 同上 | 同上 |

说明：

- 「角色」表示适配层在配置上可承担的槽位，**不是**该工具已在真实任务中走完对应职责的证明。
- 版本/帮助探测只表示发现了客户端。子 Agent 发现、暂停、附件等能力按实际探测显示，未知保持 unknown。
- 用户文档与示例当前以 **Codex** 为已验证使用入口；其他工具可接入，但不要在未标注状态的情况下当作与 Codex 同级的完整可用路线。
- 能力状态只能通过带日期的实测更新，不能通过 README 或营销文案直接升级。

## 4. 角色与验证维度

规划与复核、开发与测试可以落在同一工具或不同工具。系统默认两槽（规划、执行）+ 任务内三项覆盖（审查、审查整改、功能修复）。下列四件事相互独立，不可用一个绿色标志混淆：

1. **目录成功**：能列出模型。
2. **登录成功**：对应客户端已登录。
3. **访问成功**：该模型已通过授权验证。
4. **业务验证成功**：当前任务的测试和人工验收通过。

应用版本、配置 schema、运行后端（当前 `layers.runtime_backend: node-v1`）、runner 协议（`layers.runner_protocol.version: 1.0.0`，对应 build-info 的 `runner_protocol_version`）与 credential worker 协议（`layers.credential_worker_protocol.version: 3.0.0-node`）是不同版本轴，不要混用（见改造计划 §5.4、§10.1）。

## 5. AGY 账号能力（Windows）

`compatibility.json` 的 `agy_accounts` 当前结构如下（schema 迁移**未**抬高任何验证等级）：

| 项 | 当前值 |
|---|---|
| `platform_scope` | `win32` |
| `credential_worker_protocol` | `3.0.0-node` |
| `feature_boundary` | `serial_operations_required: true`；`dual_quota_enrollment_required: true`；`unused_account_background_probe_allowed: false`；`fail_closed_off_platform: true` |

**`verifications[]`（四项均为 `unverified`，`evidence` 为空）：**

| `type` | 状态 | 含义 |
|---|---|---|
| `capability_probe` | `unverified` | credential-worker 的 capabilities 探测（DPAPI / 凭据管理器 / named mutex）可存在；探测成功 ≠ 账号登录、双窗口认证或跨账号续接。原「能力未验证前禁用」状态以本项 `unverified` 表达。 |
| `official_cli_dual_window` | `unverified` | 原布尔假值迁移而来；字段迁移不升级。 |
| `cross_account_resume` | `unverified` | 同上。 |
| `account_switch_serial_safety` | `unverified` | 串行账号操作与双额度录入门禁仍是边界；schema 迁移不认证串行安全或录入门禁。 |

**`process_capability_model.capabilities`（实现能力清单，不是账号认证）：**

- 通用：`managed_runner_spawn`、`suspended_spawn_resume`、`job_object_*`（`kill_on_close` / `assign` / `terminate` / `active_query`）、`process_group_terminate`、`named_mutex`、`controller_flock`、`clean_process_environment`、`credential_native_probe`
- `by_platform.win32`：managed_runner_spawn、suspended_spawn_resume、job_object_*、named_mutex、clean_process_environment、credential_native_probe
- `by_platform.posix`：managed_runner_spawn、process_group_terminate、controller_flock、clean_process_environment

说明：二进制构建与安装**不是**账号切换认证；不支持的主机应失败关闭且不影响其他适配。旧 Host 接口名（诊断命令、挂起创建/关闭时终止标志、`job-status` 查询串）**不是** Node CLI 上的活命令，也不得伪造；已由上表 node-native 能力名替代（挂起创建→`suspended_spawn_resume`，kill-on-close→`job_object_kill_on_close`，job status→`job_object_active_query`；诊断命令不属于进程能力——面向用户的 CLI `doctor` 是独立命令，见 [安装与升级](安装与升级.md)）。在带日期证据补齐前，**不能**宣称账号切换可用。详见 [使用指南 · AGY 账号](使用指南.md#agy-账号与额度管理)。

## 6. 运行时（实现事实，非用户卖点）

进程管理与 Windows 凭据由 Node 实现；Windows native 层经 `koffi` 调用系统接口，数据层为 `better-sqlite3`。成品须分发平台匹配的原生依赖。不使用 Go Host，也不要求用户安装 Go/.NET 来构建 DevFlow。

## 7. 如何更新支持声明

1. 在隔离环境完成对应验证类型，并保存带日期的证据（提交、平台、工具/模型版本、结果）。
2. 更新 `compatibility.json` 中对应状态字段（由兼容性专项/负责流修改，勿在文档里“口头升级”）。
3. 同步本文摘要表。
4. 未测试组合保持 `unverified` / `live_workflow_verified: false`。
