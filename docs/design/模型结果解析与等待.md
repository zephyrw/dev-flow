# 模型结果解析与等待

DevFlow 接受模型当前调用的结果，按明确意图调度，不检查代码、测试或交付是否真实完成。用户要求完成可做部分后等待，执行模型使用 `need_user` 报告已完成项、待完成项和外部条件。

## 结果提取

`packages/runtime/src/round-output.ts` 为执行和质量复核提供统一提取器。按当前调用的原生结构化输出、当前 Run 结果文件、最终回复文本依次尝试；有效高优先级来源不会被低优先级说明覆盖。损坏或无结果意图的文件不阻止继续读取最终回复。平台不扫描历史会话、工具日志、用户提示词或附件。

支持纯 JSON、带前后文字的 JSON 围栏、带前后文字的裸 JSON，以及同一回复重复输出结果。围栏按独立 delimiter 行解析，接受 json、无语言标记、反引号和波浪线；其他语言代码块不产生结果。裸 JSON 扫描识别字符串、转义和括号层级，只提取完整外层对象，不从数组、测试条目或父对象中提升子对象。

提取后严格使用 JSON.parse，不修补单引号、注释、尾逗号或截断括号。执行读取 status/verdict 及 delivery 中的状态；复核读取 verdict/status 及 quality.verdict。明确携带的 workflow_id、run_id、plan_revision、plan_hash 必须对应当前 Run。选结果只依赖交接意图，附加材料损坏不会丢弃清楚的停止意图。

重复对象按键序无关的表示去重。多个同级候选状态一致时选择完整的一份，不拼接材料；状态冲突或对象内顶层与嵌套状态冲突时保留原文，等待用户决定。文本上限为 16 MiB，候选上限 128，嵌套上限 128；不能在超过上限或存在未闭合候选时选择局部结果。

运行目录保存 raw-result.txt 原文；run_result_parse 保存来源、候选数和解析问题摘要。它们只用于诊断，不构成额外平台关卡。

## 等待与恢复

need_user 复用通用用户交互，缺少 user_interaction 时从摘要、说明和问题降级生成请求。无法识别或冲突结果进入 WAITING_INPUT，保留原始回复、原用途、阶段和会话，生成“本轮结果需要确认”请求；不自动创建补问 Run 或调度任务。

关闭弹窗或稍后处理保持等待；明确选择“仅补充结果说明”后恢复原会话的 intent_clarification，仅说明上一轮结果，不重新开发或测试。重复提交按原请求幂等，服务重启不解除等待。手动暂停优先于迟到结果。执行过程区分等待确认、补充结果说明和实际继续开发。

## 验证与交付

unit/round-output 使用混合文本、所有来源、冲突、归属、严格语法、解析上限与本次实际回复夹具。integration/round-output-waiting 使用真实受控 CLI 子进程及隔离 SQLite，验证结果文件损坏后的文本回退、等待、不续跑、控制器重建、人工确认幂等和迟到结果。用户交互浏览器回归验证关闭、刷新、重新打开及明确确认。

执行阶段分别完成正式类型检查、生产构建及受影响测试。构建可通过 DEVFLOW_BUILD_OUTDIR 写入隔离输出；本地源码验证不代表运行服务已经更新。发布时核对实际 build_revision 和前端资源，保持原来暂停或等待的任务状态，不因升级自动恢复。
