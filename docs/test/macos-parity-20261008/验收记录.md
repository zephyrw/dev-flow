## macOS 冷启动修复

原生 Keychain 能力检查可能等待系统密码/授权。此前该等待发生在 HTTP 服务监听之前，会让安装器误报启动失败。现在 macOS 工作台先完成启动，后台检查原生能力并更新快照；账号操作继续要求实际能力就绪。新增等待授权的启动回归通过，本地成品首次安装和候选升级通过。

能力矩阵保留真实认证门禁，未把平台代码存在或夹具成功标记成官方登录、双额度或跨账号续接认证。

## 2026-10-09 续测发现与修复

1. 关闭自动轮换后，手动切号被执行器的 `running` 检查拒绝，真实操作错误为 `operation_not_owned`。执行器现在允许持真实域锁、自动轮换关闭的显式手动操作；停止中、代次冲突、取消和失锁仍阻断。新增自动开/关两种状态的切换回归通过。
2. macOS Keychain 重复弹窗有三个原因：删除重建条目丢失永久允许；每次写回重设 `SecAccess` 丢失已有授权；可信程序列表与签名分区是两个独立门禁，仅加入 Apple `security` 的程序路径不能覆盖 Node 专属签名分区。本轮只读检查确认 `gemini` 的解密 ACL 已包含 worker 和 `/usr/bin/security`，但分区仍仅为 `teamid:HX7739G8FX`，官方 CLI 读取 8 秒后超时。Apple 的 `ItemImpl::updateSSGroup` 即使只更新值也会移除旧签名分区并按写入程序重新生成，所以最终实现统一使用与 AGY 相同的 Apple `security` 程序读写官方凭据，秘密仅走 stdin/stdout 管道，宿主仍只接收元数据。本机测试中遗留的旧条目通过一次性脚本保留原授权并补齐 `apple-tool:`；脚本只修改签名权限，不改写登录内容。最终产品读取凭据或身份元数据时不会修改系统权限。后续不再由 Node 写回官方条目，登录清空使用空值保留条目。vault 主密钥仍不开放给官方 reader。6 项原生回归覆盖授权保留、重启、创建、清空恢复、系统访问拒绝、官方 4096 字节边界/控制字符拒绝和密文保护；真实迁移尚未确认，不能声称永久免弹窗已实测通过。[go-keyring 源码](https://github.com/zalando/go-keyring/blob/master/keyring_darwin.go)、[Apple SecAccess API](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_keychain/lib/SecAccess.h)、[Apple 签名分区说明](https://github.com/apple-oss-distributions/Security/blob/main/SecurityTool/macOS/security.1)、[Apple 更新时重建签名分区的实现](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_keychain/lib/Item.cpp)。
3. 切号写入/回滚结果未确认时，原逻辑可能清除待恢复操作。现在保留 `before_secret_ref`、安装意图和 pending operation，将域置为 blocked，禁止新执行许可，供恢复核验继续处理。新增域锁丢失、恢复失败回归通过。
4. 账号页原先静默丢掉失败的切换结果。现在显示最新失败/阻断原因，可以关闭提示；下一轮轮询不重复显示已关闭的同一操作。真实 OpenTabs 页面和两项 Playwright 回归均确认提示可见。
5. 两项旧额度选择/FIFO 测试仍按全局 pending 状态或同模型不同池名建立阻断，与现有按模型额度池语义不一致。夹具改为验证当前所需池资格和真实互斥账号白名单，两个文件重跑通过，未为测试改变生产选择规则。
