唯一验收定义见[完整方案第 17 节](../plan/DevFlow跨平台通用工作流平台实施方案.md#17-验收合同与测试策略)，包括 LF-01 至 LF-46、六平台检查、32 个单工具真实闭环、16 个循环组合闭环和 2 个 Kimi 规划 + Claude 执行指定组合。

## 必需验证

- 当前原生改造的 B01–B08 / S01–S14 回归，按现有代码重新核对。
- 网页与 Skill 双入口、所有输入的 @ 文件/目录引用、规划反馈、功能问题逐项复验、隔离 /btw。
- 两道质量关卡、第三次不合格接管、复审输入失效和功能回验。
- 先吸收再合回、主工作区既有改动保护、直接提交模式、冲突/漂移/部分失败/清理恢复。
- 保留当前布局的三分辨率截图、几何与原有交互回归。
- 主方案第 13 节资源预算：CPU、RSS、日志/DB 写入、额外进程、页面查询、引用检索和指纹次数。
- 八工具、七 Skill、选定组件闭包、一行安装、跨平台 Host、升级/回滚/卸载。
- 可重建的自有开源源码与完整发布候选。

## 报告与真实性

测试由执行模型原生调用，平台导入报告后追加测试执行次数必须为零。原始报告、实际命令和退出事实、批次内容摘要及环境版本均应保留；人工确认与代码质量结论另列。

必要测试失败、跳过、缺失报告、旧输入、伪退出码、错误归属和运行未结束都不能通过。已有测试全绿不能代替独立代码检查。部分模块通过可以保留，但不能把未认证平台或缺模型账号的格子标为成功。

本次只校验计划文本、引用和图解，不声称任何新增产品功能、真实模型闭环或跨平台安装已经通过。
