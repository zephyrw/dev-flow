# C08 资源预算与验收标准

日期：2026-09-22
状态：待测量

## 1. 验收要求

| 项目 | 验收要求 |
|------|----------|
| 自维护语言/构建工程 | 删除 Go 模块、C# 项目；应用逻辑只有 TS/JS |
| SDK/runtime | 开发和安装不要求 Go/.NET/C++ 工具链 |
| 新直接依赖 | 仅 Koffi 一个；不得再引入 FFI 框架、队列或守护进程管理器 |
| 后端选择 | 无 Host 路径、无 go/dotnet/node 三选一开关、无静默 fallback |
| 空闲进程 | 控制器锁不再产生额外进程；无任务且账号关闭时没有 runner 或凭据子进程 |
| 活动进程 | 每个实际管道运行最多一个 Node 启动器；每服务最多一个凭据子进程；不为状态查询启动子进程 |
| 生命周期 | 本次测试结束后，自建启动器/凭据子进程、Job 句柄、临时资源均回到基线 |
| 资源比较 | 同机、同 Node、同工作负载下测现有配置和新实现；单独统计 DevFlow 管理开销，不能用大型模型 CLI 掩盖回归 |

## 2. 资源预算阈值

Node 启动器可能比 Go Host 占用更多内存。W01 先测单任务及 3 个并发合成任务各 5 轮，W07 再测完整服务。

### 2.1 内存预算

- 空闲内存不得高于原方案 10%
- 3 并发时 DevFlow 管理进程的总 private bytes 增量不得超过 64 MiB

### 2.2 启动时间预算

- 启动 p95 增量不得超过 300 ms
- 无忙轮询

### 2.3 测量方法

1. 同机、同 Node、同工作负载下测现有配置和新实现
2. 单独统计 DevFlow 管理开销
3. 不能用大型模型 CLI 掩盖回归
4. 热身一次后各测五轮
5. 记录 p50/p95、进程数、private bytes/对应平台 RSS、句柄/FD 和清理结果

## 3. 测量计划

### 3.1 W01 测量 (初步)

**测量场景:**
- 空闲状态
- 单任务 (合成 CLI)
- 3 并发合成任务

**测量指标:**
- 内存: private bytes (Windows) / RSS (Linux/macOS)
- 进程数: 自建进程总数
- 启动时间: 从 start 到 ready 的时间
- 清理: 退出后进程数和句柄数

**测量工具:**
- Windows: Task Manager, Process Explorer, PowerShell Get-Process
- Linux/macOS: ps, top, /proc/[pid]/status

### 3.2 W07 测量 (完整)

**测量场景:**
- 空闲状态
- 单任务 (真实模型 CLI)
- 3 并发真实任务
- 完整服务 (含账号管理)

**测量指标:**
- 同 W01，但使用真实工作负载
- 额外指标: CPU 使用率、网络 I/O

## 4. 资源预算检查清单

### 4.1 空闲状态
- [ ] 控制器锁不产生额外进程
- [ ] 无任务且账号关闭时没有 runner 或凭据子进程
- [ ] 内存使用稳定

### 4.2 单任务
- [ ] 每个实际管道运行最多一个 Node 启动器
- [ ] 启动时间在预算内
- [ ] 内存增量在预算内

### 4.3 3 并发
- [ ] 管理进程总 private bytes 增量 ≤ 64 MiB
- [ ] 启动 p95 增量 ≤ 300 ms
- [ ] 无忙轮询

### 4.4 生命周期
- [ ] 测试结束后，自建进程全部退出
- [ ] Job 句柄全部关闭
- [ ] 临时资源全部清理
- [ ] 回到基线状态

## 5. 失败处理

如果资源预算不通过:

1. 先在确定的 Node 路线内减少加载、数据复制、子进程寿命和重复查询
2. 未通过前不切换 live
3. 不能为了消除语言数量而交付明显更卡的版本
4. 不能自动恢复 Go/.NET 为永久方案
