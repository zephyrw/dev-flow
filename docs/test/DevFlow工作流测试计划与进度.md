## 测试环境与证据规则

使用临时演示仓库，实际联调包含 Node API、Node HTTP 前端及按工作流隔离的数据目录；DevFlow 控制台本身使用 React/Vite。创建同仓两个 worktree，再创建另一个项目作为第三个并发工作流；另设前后端双仓 fixture 验证多仓提交。不使用生产数据库；真实模型联调使用用户已授权的订阅登录。

- 单元：Vitest；对象边界、状态不变量与负向条件。
- 集成：真实 SQLite、Git、Windows Host/ACL/进程及 MCP；模型协议 fixture 加单独真实模型探针。
- E2E：Playwright，独立 BrowserContext；测试环境可以用虚拟用户验证器，正式环境必须拒绝测试认证模式。
- OpenTabs：复用现有真实浏览器与网关，按场景独占；审批与用户实操由用户本人完成。
- 人工：整套真实模型闭环和三流程并行实际体验，不使用 fixture 取代最终验收。

每次测试先固定 snapshot/environment，使用全新的 check 目录并记录 expected case IDs。留存命令、cwd、参数、受限环境变量名、进程身份、开始结束、退出码、发现/通过/失败/跳过数、报告/trace/截图 hash。用例断言全部通过且证据对应当前快照，才能改为通过。

任何源码、测试、依赖或运行配置变化后，第一版使四层测试、用户验收和复核失效并重跑。失败报告不能覆盖；修复后新增 check ID。重跑通过也要保留初次失败结果以供复核测试有效性。
