# 账号切换后手动恢复与额度误判修复

日期：2026-09-15。主工作区 `D:\Code\system-handle`。

## 实际原因

“继续这个任务”已经发起了新的执行轮次。13:30:46 的新用户步骤之后，模型读取上下文、调用冻结，再于 13:31:36 完成新的阻塞报告。当前工具错误为 `SCOPE_VIOLATION`，指向 `.reports/unit.json`。

但是 AGY 恢复旧会话时，最终汇总继续携带以前的 `Individual quota reached... Resets in 2h49m37s.`。该字符串在不同轮次完全相同，汇总时长也是会话累计时长。平台把这个历史错误判作本轮额度耗尽，并从新时间重新计算倒计时，错误地显示 16:22:14 自动继续。

因此，前一份报告对通用平台“真实额度不足、等到 15:02:53”的判断不成立；当时记录的是平台依据旧汇总作出的错误安排，并非当前账号的额度查询结果。本次不读取或更改账号凭证，依据新的模型响应与实际工具结果纠正判定。

## 修复

- 用本轮新用户步骤界定执行过程。只有明确观察到最后一次工具调用之后的新模型答复完成、没有本轮模型错误、且汇总错误与此前记录完全一致时，识别为历史遗留错误；新的额度错误、未完成答复和缺少新轮次边界的结果继续按失败处理。原始汇总保留。
- 当前模型报告的结构化工具失败优先显示实际原因。完成判定由工作流的代码快照、测试和审批校验执行。
- 手动恢复立即清除旧定时等待并安排执行；额度状态下顶部按钮显示“立即重试”，无需等待旧倒计时或填写指导。
- `.reports/unit.json` 与已保存的 `unparsed-report.txt` 内容哈希一致，但登记报告后来改名为 `portable-unit.json`。清理扩展到专用报告目录里的可验证旧文件名。运行器额外复制的新报告也在归档后处理，避免再次影响快照。已有文件、Git 跟踪文件、内容变化的文件和报告目录外的文件保留。
- 侧栏收起后的未读提示行为保持不变。
