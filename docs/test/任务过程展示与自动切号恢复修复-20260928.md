## 已确认的缺陷

1. 会话树已有持久化 Codex 节点时，未合并未登记的真实 AGY Run；右栏仍看旧复核会话，中间活动却来自当前执行 Run。
2. `run-23738553-7313-421a-9f1e-d4efaad43fe4` 的 AGY 本轮存在 TLS 错误；最终 JSON 的长回复将后置错误挤出前 8000 字符，导致错误分类只看到交付正文，未进入已有连接重试。
3. `run-fbba163e-9b9a-4025-bf39-bc1eb002d067` 在 Codex 接手修复时被 `invalid_json_schema` 拒绝。生成合同的顶层及 delivery.artifacts 使用无类型 items，模型未开始修改。
4. 启动前发现活动账号纯额度耗尽，旧路径只报账号不可用，没有请求自动切换；AGY 1.2.x 的实际额度错误为字符串，旧解析只接受错误对象，也未触发自动切号。
5. 并发准入可能在等待进程枚举时错过新建切号操作；晚加入需求若未合并进模型、额度池和允许账号范围，会与选账号时的需求不一致。
6. 模型恢复两处使用非法 `identityConfidence: verified`，真实切换成功后会在访问缓存校验处失败。启动同步路径还存在提前记成功、错误名称不匹配的问题。
7. 原生任务的测试页只读取旧验收记录，轻量执行结果没有保存逐项测试状态；模型请求人工输入时还会提前退出而丢失可选报告。任务交给复核后仍显示 0/N，无法区分未回传与明确未执行。

## 修复边界

- 以真实 Run 和原生会话编号补会话展示，不创建 CLI 会话或伪造子 Agent；保留历史会话及 aside。
- 保留结构化错误后再截断，真正本轮错误继续判失败，使用已有有限连接重试。
- 只修正 Codex 生成用附件格式，原有结果接收与历史可选材料保持宽容。
- 启动前额度拒绝进入同一次受管切号；等待者没有伪造的 permit 或 PID。停止确认、账号身份核对和用户主动停止规则保持生效。
- 字符串额度错误先查当前绑定账号的官方额度。历史消息、账号不匹配、查询失败或额度仍充足均不据此自动换号。
- 切号开始读取需求前关闭排队加入窗口；已受理需求合并，晚到请求待切号完成再取许可。
- 成功访问记录使用合法身份值，启动补缓存必须在模型验证、许可与身份核对成功后进行。
- 选择可用账号时先按周额度降序，周额度相同则五小时额度多者优先，其后沿用原最近使用排序。
- 删除首页自测次数、最近自测提示；测试页改“测试进度”，命令只留在执行过程与当前活动。
- 保存执行模型和规划接手修复模型明确回传的原计划测试编号、场景编号、状态及说明，按计划版本投影；请求输入和进入复核均保留结果。没有逐项报告显示“未回传”，不以命令成功、映射或进入复核推算通过。页面标注“执行模型上次报告”和时间，不将历史报告冒充当前代码重新验证。
