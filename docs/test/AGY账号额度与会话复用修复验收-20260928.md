## 现场根因

1. **账号服务误锁。** AGY 1.2.12 的真实 `/usage` 输出只有额度，没有邮箱。最后一个执行许可释放时，代码把缺失邮箱当成账号不一致，将 realm 置为 `blocked / external_change`。下一轮只显示泛化的 `AGY_ACCOUNT_UNAVAILABLE`，未发生自动切号。现场成功任务的原生终态为 SUCCESS；另一个任务实际遇到 `tls: bad record MAC`。所查原生日志没有真实额度耗尽事件，不能把此处提示当成已证实额度为零。
2. **第三个账号凭据与额度串号。** `cloudze3210@gmail.com` 的账号标签对应的保存凭据元数据却是 `heemmnm@gmail.com`，两个账号的额度及重置时间也近似重复。“刷新全部”会临时安装每个保存凭据；缺邮箱时旧代码未验证真实身份便回写凭据和额度，且未检查正在运行的 AGY。错误并非单纯进度条计算问题。历史保险库中仍有第三个账号的正确凭据，已在用户授权后激活、真实查询并恢复。
3. **短 OK 会话。** 真实推理探测本来用于验证模型调用能力；已有成功缓存只有读取没有写入，也没有登记同键并发。每次额度刷新又无条件分配新凭据版本，继续使缓存失效。
4. **正式会话追踪。** 两个现场业务任务实际已复用各自原生根；同根绑定的 `latest_run_id` 没更新，已修补。标准创建入口本就先建立 worktree，不需要重构目录流程。
