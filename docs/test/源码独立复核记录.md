### 更新并发窗口修复复查

S6 / P2：静态检查时，安装脚本停止控制器后到依赖同步和构建完成之间，没有阻止自动启动的维护标记。另一 Codex 任务的规划桥接器可在此窗口调用 `ensureService`，重新启动旧 `dist` 控制器，再次占用 Host 可执行文件，或在依赖被替换时继续运行。触发路径为 `scripts/install-windows.ps1` 的停止后构建阶段，与 `packages/service/src/launcher.ts` 的自动启动路径并发。

主代理已增加按状态目录隔离的 `maintenance.lock`：安装脚本使用 `FileShare.None` 持有文件句柄，在停止控制器前获取与启动器相同的 `startup-lock.json`，等待已经开始的启动结束；随后在持锁期间完成停止、依赖同步、构建和配置更新，并在 `finally` 中释放。

独立静态复查确认，`launcher.ts` 在入口、启动锁等待循环和真正创建控制器进程之前均调用 `assertNotUpdating`。维护文件无法打开时明确报告正在更新；能够打开时才按崩溃遗留标记清理。已经越过启动检查的启动器仍持有启动锁，安装方须等其释放后才能停止和更新，因此上述 S6 窗口在当前源码层已处理，未发现这组锁修改新增的确定逻辑缺陷。
