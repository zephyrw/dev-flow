## 故障与根因

涉及任务：`wf-203cb2b8-aff1-4da5-9a22-495dcacafe4a`，标题“排查修复任务提交与阶段更新失败”。

1. 任务工作区 `packages/core/src/engine.ts` 的冻结阶段语句包含字面量 `\"`，产生 TS1127、TS1002 及后续连锁编译错误。
2. 环境启动器只轮询健康检查，没有同时观察服务进程退出；任意错误均重试五次，每次等待约 30 秒，最终健康检查错误遮盖编译原因。实际日志中一次冻结失败后，执行器又修改预览脚本、重新冻结，累计启动九次。
3. 冻结准备失败后任务仍处于 EXECUTING，原执行器仍有权限继续修改和再次启动。
4. 修改前置任务会递归将全部下游实现凭据标为失效，迫使未改动的下游重复提交；页面又把静态实现检查称为“已完成任务”。四份实现声明始终保留，原现场不存在任何通过的测试证据。
5. 15173 来自本机前端验证端口池，与 4810 工作流控制台分开。它是当前任务代码和独立数据的验证副本，供浏览器测试、验收使用。

## 修复行为

- 冻结前先执行注册的 build 命令。构建失败立即阻断本轮，撤销原执行器权限并停止进程，保留原始错误；不再自动循环启动。
- 健康检查与进程退出同时等待；只对明确的 EADDRINUSE 换端口重试，排除已尝试端口。编译错误、进程退出和健康检查失败立即终止。清理进程后保留 failed 状态及首个错误。
- 保留实现提交、时间和说明。仅使修改文件对应的实现失效；下游显示“等待前置核验”，前置修复后可复用未改动的实现。测试证据仍须独立重新生成。
- 页面使用“已提交实现”“待核验实现”“已通过测试”，并将环境入口改为“本机验证副本”，说明 127.0.0.1、独立数据和端口用途。
- 修复历史暂停记录误标为用户操作的问题。
- 修复当前任务工作区的语法错误及测试适配器：直接运行 Node CLI，正确处理 Windows 空格路径；先完整构建且启用 noEmitOnError；预览不再自行重复编译；保留 Playwright 的报告输出配置。
- 修正原任务测试夹具的 Host、截止时间、重复按钮定位，以及 JUnit 用例名称重复 `test` 前缀。
