# 用户界面与细项进度整改验证

日期：2026-09-14。对应[整改方案](../plan/DevFlow用户界面与细项进度整改方案.md)。

## 已落实的使用方式

- 左侧底部提供“使用指南”，支持直接打开和刷新恢复；顶部“如何开始新任务”入口已移除。[指南正文](../guide/使用指南.md)包含自然语言发起需求、看计划、审批、进展、反馈、验收、恢复及并行工作说明和流程图。
- 主页面显示阶段、当前工作、已完成细项和已通过用例，不展示计划 r、环境 v、工作流编号或执行轮次。内部记录放入可展开详情。
- 模块负责分组，细项负责计数。执行器必须明确开始细项，文件修改限定在其批准路径内，提交完成说明后检查计划条件并记录文件哈希。文件变化或相关测试失败会使实现结果需要重新检查，允许返回前置细项修复。
- 测试分母来自批准清单中的用例。重复运行不增加分母；旧计划、旧代码、旧环境、跳过和缺失结果不增加通过数。开发进度和测试进度分别显示。
- 服务与测试日志归入对应活动详情，不以 ServiceOutput 或空“工作流记录”刷屏。启动、就绪、失败由实际生命周期事件表示；概览和执行过程使用同一投影。
- 代码变更默认显示文件列表。单击文件弹出该文件差异，读取时有加载状态；支持关闭按钮、遮罩点击和 Esc 关闭。逐文件查询使用 Git 字面路径，避免特殊字符被当作通配符。

对比分支：`feature-zxw`。对比基准：`4f683629c646731a1ddbf99960561acc7de6b772`。原界面上的 `main` 是仓库标识，不是实际 Git 分支。新版展示实际分支；现有任务始终沿用任务开始前的基准提交。

本轮提交新的细项清单至原计划审批入口，状态为等待修订计划批准，未自动批准或恢复业务执行。旧工作包声明未自动复制成新细项完成记录，因此当前计数是 0 / 42 和 0 / 81。[迁移记录](evidence/redesign-20260914/migration.json)、[新旧映射](../plan/CRM现有工作包与细项映射.md)。

## 代码复核

已检查本轮变更中的计划版本兼容、任务归属、依赖返工、当前证据选择、重复用例统计、文件路径边界、差异基准、事件合并及日志展示。复核中修正了：未创建工作区时读取细项进度报错、返工无法返回前置任务、旧通过证据遮盖较新失败结果、特殊字符文件名被 Git 按模式解释，以及弹窗遮罩和加载状态。相应回归与本机浏览器检查完成后交付。

计划中的文本/方法标记是结构检查，不能单独证明业务正确；执行规范明确禁止用占位代码满足标记。交付仍需要真实测试、用户验收和代码复核，不把“细项已完成”等同于“整个需求已交付”。
