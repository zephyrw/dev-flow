## 为什么上一轮通过测试后仍然停下

上一轮覆盖了模拟启动失败后的恢复流程，但漏测了本机真实 PowerShell → Windows Host → Maven 的环境传递，以及规划模型接口对诊断 JSON Schema 的实际约束。恢复后的短期运行状态不能证明完整自愈链路已经可靠。

1. **平台没有传递必要运行环境。** 受管进程白名单遗漏 `ComSpec`、`PATHEXT`、`JAVA_HOME`。CRM 包装脚本打印启动提示后，`mvn.cmd` 没有真正执行，退出码还可能是 0。现已补充明确的系统与 Java/Maven 运行变量白名单，仍不整体继承令牌和密码。
2. **规划诊断请求本身不合法。** 日志明确记录 HTTP 400 `invalid_json_schema`，嵌套计划中的 `propertyNames` 不受接口支持；规划模型未开始诊断。诊断合同现复用已有复核的严格格式转换；格式拒绝时只回退重试一次普通 JSON 输出，随后本地严格校验，不伪造诊断结果。[接口约束](https://developers.openai.com/api/docs/guides/structured-outputs)
3. **诊断调用失败被错误地交还用户。** 现在保留实际诊断错误，由执行模型继续原范围修复；同一错误连续失败才累计上限。六次同一错误仍无进展时保留现场，可直接“继续自动排查”，不强迫用户解释内部日志。开发阶段主动启动环境与交付冻结失败接入同一机制，避免主动重试绕开计数和规划诊断。扩大计划范围仍须批准。
4. **错误显示混入内部指令。** 工作台主提示改为简短中文原因，详细错误和模型操作指令折叠展示。授权仍展示具体一次性操作，批准或拒绝后续接原任务。
5. **测试报告误伤源码快照。** 运行器现在归档新报告并恢复原文件；历史残留只在“未被 Git 跟踪、内容与不可变归档完全一致、路径属于登记报告位置”时清理。不删除被改过或无法证明来源的用户文件。
6. **额度耗尽没有续接时间。** 提供方明确返回恢复倒计时时，保存与当前任务、轮次及批准计划绑定的自动续接记录；重启保留，到点核实进程与审批后恢复。暂停会取消；未知恢复时间不猜测。
7. **健康诊断缺少实际观测。** 真实 CRM 后端恢复后，健康接口返回 200、MySQL/Redis 为 UP，但重复添加两次任务标识。平台现在立即给模型实际响应头与预期值，拒绝错误身份；暂时返回 503 的服务仍可等待就绪。服务启动等待使用登记超时，真实进程退出仍立即失败。
