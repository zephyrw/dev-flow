# AGY 任务混用模型与配额切换整改方案

日期：2026-10-16。状态：用户已批准实施，代码已整合到当前工作区；本地验证与真实账号验收分别记录于文末。现有任务、会话、账号及其他工作区改动保留。

## 背景与目标

DevFlow 此前要求同时使用 AGY 的任务统一采用 Gemini 类或外部模型类（Claude/GPT）。现在需要取消这项限制，让每个任务独立选择模型，例如任务 A 使用 Gemini，任务 B 使用 Claude，并能同时执行。

当前限制贯穿模型选择、模型核验、执行准入和账号切换，不能只删除截图中的“与当前类别冲突”。同时，多个 AGY 任务共用同一个登录账号；切换账号会影响同一账号域内的任务，需要统一暂停和恢复。

整改目标是：**任务独立选模型；任一模型池配额经确认归零即切换；按先归零的池和窗口选择剩余额度最多的可用账号；切换后各任务继续使用自己的模型。**

沿用现有共享账号和安全切换机制，取消类别互斥，保留模型与配额池的映射。这样既能支持混用，也能避免把 Claude 的消耗归到 Gemini。

## 现状依据（整改前）

以下结论来自本轮主工作区源码核对，未据此宣称线上服务已验证：

| 当前行为 | 代码位置 | 对整改的影响 |
|---|---|---|
| 模型列表、搜索输入和保存操作检查活跃类别，跨类选项被禁用 | `apps/web/src/components/ModelProfileEditor.tsx` | 列表与手工输入必须一起放开 |
| 保存模型、执行准入、模型核验、手工账号切换均存在类别拦截 | `packages/core/src/model-switch-service.ts`、`packages/agy-accounts/src/service.ts`、`packages/runtime/src/agy-workflow-bridge.ts` | 后台和直接接口也必须支持混用 |

现有池名称为 `Gemini Models` 和 `Claude and GPT models`，每池包含周额度与五小时额度。本文“Claude 池”指现有 Claude/GPT 共享池，不拆分新的供应商配额。

## 总体做法

先明确并持久化“触发切换的配额”，再贯通候选排序、切换和恢复；随后取消各入口的类别互斥，并将占用状态改为支持多个类别。账号页面展示两池状态及本次排序依据。本地回归与真实账号验收各自说明结果，未经真实验收不宣称线上切号已验证。

本次保持账号域内只有一个活动账号。任务独立选模型不代表每个任务独立登录账号。

## 一、允许任务独立选模型

这项工作让不同任务可以选择和同时使用 Gemini、Claude，而不会因其他任务的模型类别被拒绝。

- 删除前端类别冲突禁用、红色冲突提示，以及搜索输入、保存和核验中的同类限制。
- 删除后端保存、运行准入、模型核验、手工切换和恢复入口的类别互斥。HTTP、MCP 等入口依赖同一业务规则，不能只放开界面。
- 每个任务继续保存自己的模型配置；每次运行冻结实际模型。修改全局默认模型不覆盖已有任务，切换账号也不改变任务模型。
- 占用状态改为类别集合或按池汇总，支持同时存在 `gemini` 与 `other`。单条任务模型无法映射配额池仍属于未知；合法混用不属于未知。
- 保留模型真实可调用性、凭据身份、进程占用和账号代次检查。模型类别只用于配额归属，不再用于排斥其他类别。

## 二、确定任一配额归零后的切换规则

这项工作保证系统按照用户指定的配额选择账号，并能解释为什么切换。

### 触发范围与先后顺序

自动切换开启时，监测当前活动账号两池的周额度、五小时额度。任一窗口经官方配额核验为 0，或收到绑定当前账号及当前运行的可信配额耗尽事实，即进入同一切换流程。后台配额更新也要检查归零，不能只等待任务报错或下一个任务启动。

“先归零”按系统**首次确认归零的持久化事件顺序**判断，不推断供应商侧无法观测的真实发生时间。同一次采样确认多个窗口为 0 时，优先使用本轮可信报错明确指出的池和窗口；仍无法区分时，按持久化事件序号、池 ID、窗口固定顺序打平，并记录为同时发现。

历史日志文字、网络错误、权限拒绝、读取失败和缺失配额均不等于 0。任务报告耗尽但无法定位池或窗口时，先补充官方核验；仍无法确认则等待诊断，不能猜测排序依据。

### 先筛选可用账号，再按触发配额排序

候选必须身份正确、凭据可用、符合所有待恢复任务的账号白名单，且能调用这些任务的实际模型。**由于本方案监测两池任一归零，目标账号两池的周额度与五小时额度都须经核验大于 0**，避免切到另一个已归零的池后立即反向切号。缺失或未经核验的池先核验，不按满额处理。

在满足上述条件的其他账号中，使用以下排序；另一池的余额不参与主排序：

| 首个确认归零的配额 | 第一排序项 | 相同时比较 |
|---|---|---|
| Claude 池周额度 | Claude 周余额降序 | Claude 五小时余额降序 |
| Claude 池五小时额度 | Claude 五小时余额降序 | Claude 周余额降序 |
| Gemini 池周额度 | Gemini 周余额降序 | Gemini 五小时余额降序 |
| Gemini 池五小时额度 | Gemini 五小时余额降序 | Gemini 周余额降序 |

仍相同时沿用最近最少使用、入池时间、账号 ID 的稳定顺序。自动配额切换排除触发耗尽的当前账号；没有新证据前不重复尝试本轮已确认不可用的候选。

例如：Claude 周额度先归零，账号 B 的 Claude/Gemini 周余额为 80%/20%，账号 C 为 60%/90%；两账号的四个窗口均大于 0 且模型可调用，则选择 B。若 B 的 Gemini 五小时额度为 0，则 B 不满足可用条件，选择 C。

候选初筛、核验后重排、已核验候选回选、重试和定时唤醒必须使用同一排序规则。快照过期先核验，预测重置不能直接替代实测可用性。保留现有候选上限与超时；达到上限仍有可能胜出的未核验候选时，明确未完成择优并等待重试，不能把“已核验中最高”宣称为全部候选最高。

## 三、让切换过程保留所有任务

这项工作让共享账号切换成为一次可恢复的操作，避免混用后重复切号或丢失任务。

1. 原子受理首个有效归零事件，冻结触发池、触发窗口和账号代次；关闭本次切换的新增任务准入。
2. 同一账号代次的后续归零事件加入现有操作，补充任务需求，不覆盖首个触发配额，也不再创建第二次切换。
3. 汇总待恢复任务的实际模型和账号策略，保存各任务的阶段、会话与工作区恢复信息；暂停同一账号域内受管 AGY 任务并确认停止。
4. 按触发配额筛选、核验和选择账号；核验全部待恢复模型后提交新账号身份与账号代次。
5. 各任务按自己的恢复记录继续，保留原模型、会话归属、计划版本、阶段及工作目录。无法复用会话时走现有明确恢复状态，不静默重建对话。
6. 切换期间到达的新任务在提交后重新校验新账号，再申请执行许可。

操作、等待记录和恢复记录持久化触发池、窗口、首次确认时间、事件顺序及来源账号代次。账号服务重启、等待唤醒和候选重试继续沿用这些信息，不重新从“第一个活跃任务”推断触发配额。

没有满足条件的账号时，显示具体缺额池、窗口及可确定的下次核验时间，进入等待；已保存任务不丢失。候选安装或核验失败时，按现有事务恢复凭据并尝试下一候选；停止确认失败、身份不一致或回滚核验失败时保留阻塞状态，不强行恢复执行。用户停止任务、关闭自动切换或旧账号代次失效后，旧事件不得重新触发操作。

自动开关沿用现有账号服务与任务策略。后台监测不得绕过某个受影响任务禁止自动切换的配置；遇到策略冲突保留等待并说明原因。

## 四、让页面说明模型与切号依据

这项工作让用户能看清每个任务用什么模型，以及系统为何选择某个账号。

- 模型选择器允许跨类选择，保留真实不可用、候补和待核验状态。
- 任务显示自己的实际模型；账号页面分别展示两池的周、五小时余额及观测时间，允许同时显示两类占用。
- 切换状态显示“Claude 周额度为 0，按 Claude 周余额选择账号”等具体原因，附目标账号及排序配额余额。
- 无可用账号时说明筛除原因，例如“Claude 配额充足，但 Gemini 五小时配额为 0”；不再显示“模型类别冲突”。

### 必须通过的验收

- Gemini 任务与 Claude 任务能分别保存、核验、启动并同时执行；默认模型修改不覆盖既有任务。
- 两池四种窗口分别归零时都能触发切换，且严格按表中对应余额排序。特别覆盖“另一池余额更高但触发池余额更低”的反例。
- 目标账号另一池为 0、池缺失、模型不可调用或白名单不匹配时被筛除；无候选时保留恢复状态并等待。
- 两任务同时报告耗尽只切换一次；后续事件不改首个触发配额；同次采样的并列顺序稳定。
- 初筛、候选实测回选、失败重试及服务重启后的结果使用同一比较规则。
- 切换后两任务仍使用各自模型、原会话归属和原阶段，已停止任务不会复活；晚到任务绑定新账号代次。
- 网络错误、历史日志、未知配额和旧账号事件不误切；关闭自动切换后不再自动操作。
- 浏览器覆盖截图中的下拉框、搜索自定义模型、保存、两池展示及等待原因。

## 上线与回退

上线前备份必要的运行状态、账号操作记录及凭据引用，按现有维护流程确认受管任务已安全暂停，再替换已验证产物。上线后核对服务与前端版本一致，并确认原任务、模型和恢复记录完整。当前工作区已有的 `runtime-failure` 相关源码和测试修改不属于本方案实现范围。

回退前先关闭自动切换并暂停混用任务；旧版本会把混合占用判为未知，不能直接回退后自动启动。保存新旧版本可识别的恢复信息，恢复上一版本后明确保留任务等待人工处理；不删除任务或强行改成同一类模型。未来实际推送、部署和账号操作按对应执行任务的授权进行。
