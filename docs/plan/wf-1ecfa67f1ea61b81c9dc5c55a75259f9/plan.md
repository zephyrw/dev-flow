DevFlow 额度恢复、任务清单与指导发送修复计划（待批准）

用户在工作流执行和人工验收后的功能修复过程中遇到三个问题：Gemini 额度耗尽后没有自动切换账号；任务清单持续提示不可读取；指导已出现在执行过程里，输入框却仍保留原文字。用户已手动切换账号，本次需要修复这些行为及其恢复路径。

工作包记录了明确的额度错误，后续恢复又出现模型访问核验超时，两者不能视为同一种故障。清单虽可被结构解析，但仍可能不满足计划、任务定义或写入运行的归属约束。当前源码也确认，指导发送要等待详情刷新完成才清理草稿；清单同步则依赖当前运行及写入者状态。额度未切换和清单告警持续的具体触发原因仍需通过对应运行证据及隔离复现确定，不能仅凭错误文案下结论。

目标是：符合既有策略的真实额度耗尽能够切换合格账号并继续原任务、原模型；合法清单恢复后自动更新进度并清除告警；同一条已发送指导首次出现在执行过程时，原提交文字已经离开输入框，同时不丢失失败草稿和发送期间的新输入。由于三个问题分别涉及错误归属、运行交接和异步时序，修复必须覆盖完整调用链及异常分支。

总体安排是先建立隔离复现场景，再分别修复账号恢复、清单同步和发送生命周期，最后由执行阶段完成正式检查、两类浏览器核验并交用户实操确认。工作包没有现有计划，本稿为首版；以下事项均尚未实施。

**关键设计与兼容边界**

账号恢复复用现有失败事实、账号策略、执行许可和恢复记录。额度错误必须归属于真实的当前运行；模型访问核验超时单独处理，不能通过切号掩盖。实际恢复原因应可追溯，但不记录凭据或原始敏感输出。

清单继续以批准计划定义为基础，以最后有效快照保存展示进度。读取异常、结构错误、归属冲突应可区分；告警恢复与进度变化分别判断。读取恢复不授予新的写入权限，清单中的“完成”或“通过”仅表示执行者报告的状态，不新增平台测试审计或验收关卡。

发送过程需要保留按工作流和请求标识关联的提交快照，以及发送中、已接收、失败或结果待确认的状态。新草稿与在途提交独立管理，附件和引用按提交归属处理。优先复用现有接口和持久化机制；如需补充确认字段，保持旧调用兼容。本次不预设新增数据库表或迁移。

关键定位入口为 `packages/runtime/src/profile-runtime.ts`、`packages/runtime/src/agy-workflow-bridge.ts`、`packages/core/src/task-list.ts` 和 `apps/web/src/interactions.tsx`。路径仅帮助定位，不构成修改白名单；执行者可修复完成同一目标所必需的关联问题。截图中的其他工作流业务内容不在本次范围内。

**验证与验收**

- **单元测试：** 覆盖额度错误形态、当前与历史轮次、冲突诊断、清单定义及归属规则、提交快照和草稿恢复。预期是准确分类、拒绝非法归属、不误清新输入。
- **集成测试：** 使用真实运行时、账号桥接、工作流引擎及隔离存储，外部 CLI 可使用明确标注的替身。验证额度识别至切换恢复、人工验收后的功能修复、无合格账号等待、手动切换、清单异常至恢复及运行交接、消息接收与重试去重。预期任务、模型、会话和进度归属一致，故障恢复不重复执行。
- **真实浏览器 E2E：** 连接真实前端、后端及隔离数据。控制实时事件、HTTP 响应和刷新顺序，验证指导首次可见时旧输入已清除；覆盖拒绝、响应丢失、新草稿、附件、/btw 和重复点击。验证清单损坏后保留进度、合法恢复后告警消失，以及账号等待、恢复和超时提示。外部 CLI 替身只模拟外部边界，不用整页模拟数据代替业务链路。
- **OpenTabs 核验：** 另行从隔离实例真实页面输入、发送、切换进度视图并刷新，检查文字、附件、告警、状态、布局及遮挡。与身份无关的场景优先使用隔离本地开发会话，不关闭业务授权。规划时已发现 OpenTabs 工具，但本轮策略阻止读取标签页；执行阶段须重新确认连接，不能把工具存在视为核验通过。
- **真实账号验证：** 仅在已有授权、具备合格账号且可安全复现时，验证真实额度故障后的账号、模型和会话恢复；不为测试主动耗尽额度。条件不足时明确记录未验证范围，替身回归不能代替真实账号结论。
- **人工验收：** 用户在隔离实例发送指导，确认原文字及时离开输入框；查看清单从异常恢复后的内容，刷新后确认状态保留；检查账号故障及恢复提示，并在真实账号条件具备时确认原任务继续。自动测试不代签人工确认。
