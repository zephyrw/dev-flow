# 用户需求原文

现在开发计划默认会显示大纲，这里需要做一下判断，如果这个开发计划文档没有大纲，整个大纲模块需要完全不显示，那个文档大纲/收起大纲的按钮也不要显示，毕竟这个大纲都不存在，显示没有意义。另一个问题是现在如果这个文档默认有章节标题分析出了大纲，那这个大纲也不应该如图2这样直接盖住正文，正文应该在大纲右侧。问答和全屏显示那两个按钮的图标太丑了，特别是全屏显示那个图标线条还是断断续续的，这个需要修改为好看一点的图标，最起码图标不能看着破破烂烂的，具体用什么图标让执行模型自己想办法吧。另外我的鼠标 hover 到左侧任务名称上时，整个名称背景那一块全是白色，加上任务名称也是白色，hover 完全看不出这个任务标题是什么，hover 背景色高亮时也应该是深色，不要整成白色，而且一大块白色的反差也很刺眼。如图片3，点加号后弹窗里那个引用工作区文件或目录那个菜单选项需要去掉，毕竟它在工作区直接 @ 就可以。右下角那个会话的发送按钮太丑了，谁家发送按钮是一个向上的箭头，需要修改为发送信息那种向右的图标，具体图标用什么让执行模型决定。如图4，执行过程这个模块，执行过程这几个字下面的主会话（或者worktree 会话）应该移到已连接那个位置，并且样显示样式需要优化一下，具体怎么优化让执行模型决定，已连接那个状态显示需要去掉，我完全理解不了显示个已连接是什么意思，它要么正常工作，要么出问题了，已连接不是最基础的吗？验证这个系统正常运行还要显示为正常运行状态出来？复制公开文本那个按钮需要去掉。主会话（或者worktree 会话）下面那个主会话 · 正在工作 · Antigravity CLI · gemini-3.8-flash-high · 思考强度   那一行的显示需要去掉，这个完全没提供任何新的信息量。下面输入框的提示里或输入 /btw、/side 临时提问这一部分需要修改为或输入 /btw 临时提问，把 /side 去掉，虽然这个系统支持 /side 但是写两个功能一样的命令出来会让用户困惑。 如图5，代码变更显示代码区域是深色背景，这个深色背景居然带弧角，那个弧角需要去掉，因为现在代码区域的深色背景的弧角导致了它与下面上面有割裂感，注意是去掉深色背景的弧角，不是整个模块的弧角。如图6，代码复核结果那里显示需要优化一下，让执行模型去优化吧，需要更现代化和人性化地展示这些信息。任务进度这里排版也需要优化，不要在任务名称下面加一个查看实现细节与完成条件  按钮，这个按钮需要去掉，点击任务名称就直接展开下面的细节。任务进度前面的勾选框也应该去掉，右边已经显示了状态，不需要显示勾选框来表示状态。整个页面左下角的实时连接已建立那块显示也需要去掉，连接建立是什么意思？是与什么建立连接，是后端没启动吗？这就是一个系统，要么都能用，要么都不能用，你看看谁家的网页会显示出连接已建立，难道用的人还需要考虑连接没建立的情况也就是不能用的情况？左上角的工作流总览需要修改为任务总览。用 DevFlow 工作流完成全部的开发吧。
