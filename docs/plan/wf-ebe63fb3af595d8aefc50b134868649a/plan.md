**DevFlow 接入 Gemini 4 Hydrogen 计划（待批准）**

用户需要在 DevFlow 的所有 AGY 模型选择入口使用 Gemini 4 Hydrogen，并确保模型是否可选取决于实际账号能力。界面应提供 Low、Medium、High、Extra；Extra 必须完整经过保存、恢复和真实派发，其他 Gemini 型号保持原有档位。

当前代码已经具备账号模型探测、目录缓存、模型授权验证、账号切换和冻结执行参数的基础能力。`model-configuration.ts` 尚未登记 Hydrogen；现有已知 AGY 家族主要通过原生型号变体表达思考档位。共用选择器使用 `ModelProfileEditor`，群聊另有独立选择器。两者的前端目录状态目前没有完整体现 AGY 账号变化。自动选号对新鲜目录中的明确缺失会排除账号，但目录缺失或过期时不能据此确认 Hydrogen 能力。

本轮确认本机 AGY CLI 为 1.5.6，帮助列出 `--model` 和 `--effort low|medium|high|xhigh|max`。受本轮只读及网络限制，`agy models` 未取得目录并超时，因此尚未确认 Hydrogen 原生 ID、Extra 的实际编码、支持账号和不支持账号。该失败不能作为任何现有账号不支持 Hydrogen 的证据。Google 发布说明确认 Hydrogen 提供四档思考能力，并向 Antigravity 的付费 Google AI Pro、Ultra 用户开放；具体账号资格仍须查实际目录。[Google 发布说明](https://blog.google/innovation-and-ai/technology/developers-tools/build-with-gemini-4-hydrogen/)

目标是让支持账号在所有入口看到并选择 Hydrogen，不支持账号隐藏；账号切换、自动选号、刷新失败及恢复均不得借用其他账号的能力。仅补静态型号或 UI 文案无法满足这一目标，因此采用“真实协议确认 → 账号目录与能力隔离 → 全入口接入 → 保存及派发校验 → 分层验收”的方案，复用现有账号协调器和模型服务。

**一、模型与思考档位设计**

先通过已有账号服务和当前实际执行的 CLI 获取脱敏目录、版本、可执行文件指纹及帮助信息。逐项记录 Hydrogen 的可调用 ID、可用状态、四档对应关系，以及档位通过型号变体还是独立参数传输。不得由其他 Gemini 型号后缀、CLI 通用帮助或截图猜出 Hydrogen 的启动参数。

确认后，在 AGY 家族映射中登记 Hydrogen，在显示层统一使用 `Gemini 4 Hydrogen`。目录只生成该账号实际列出且可用的条目；静态映射只解释条目，不生成账号资格。家族合并后的档位是当前账号可用变体的集合，不补齐缺失档位。

显示顺序为 Low、Medium、High、Extra。新选择 Hydrogen 时，High 可用则默认 High；编辑已保存配置时保留原档位。Extra 的显示标签与线协议值分离：持久化采用核实后的原生档位值，显示层仅为 Hydrogen 映射为 Extra。若 CLI 使用变体 ID，保存准确 `modelId` 并通过现有 `effort.variants` 解析；若使用独立档位参数，保存对应原生值并由适配器生成 `--effort`。不得未经确认把 Extra 写成 `extra`、`xhigh` 或 `max`，也不得把 CLI 通用枚举全部开放给 Hydrogen。

复用 `ToolProfile.reasoning`、`ModelEffort`、`resolveModelSelection` 和冻结调用结构。选择 Extra 后，模型 ID、档位、启动参数、运行记录及恢复后的调用必须一致。检查 `agyArguments` 的默认 High 路径，确保显式 Extra 不被默认参数覆盖。已有 Gemini、Claude 和 GPT OSS 的档位与派发方式保持原状。

协议核实是型号映射落地的前提。若执行环境仍无法取得真实结果，继续完成不依赖具体编码的账号隔离和测试框架，保留相关任务未完成；不能以猜测映射或模拟调用宣布接入完成。

**二、账号能力、缓存与自动选号设计**

模型资格与额度分别判断：实际目录中的可用 Hydrogen 条目证明账号具备该型号能力；额度池只决定当前是否允许调度。会员等级、`gemini-*` 或全局额度池不能证明 Hydrogen 资格。额度耗尽不等于永久不支持，不删除已有配置，按现有额度等待或切换流程处理。

复用 `AgyAccountService.readActiveModelIds`、账号协调器、身份锁、`ModelCatalogService` 和 `ModelAccessService`，补齐以下规则：

| 场景 | 处理顺序与可见结果 |
| --- | --- |
| 当前账号目录成功 | 在身份锁下读取、核对账号和认证代次、解析可用条目，再提交该账号快照；支持则显示 Hydrogen。 |
| 目录明确缺失或标记不可用 | 隐藏 Hydrogen；服务端拒绝新选择和派发。 |
| 目录缺失、过期、超时或解析失败 | Hydrogen 能力为未知，隐藏可选项并提供刷新提示；不写入“不支持”结论，不使用其他账号或静态目录兜底。 |
| 手动切换 A → B | 切换开始即使旧目录失效；B 身份提交成功后获取 B 的目录。A 的迟到结果不得更新 B 的页面或缓存。 |
| 切换失败并恢复 A | 以最终提交身份为准，重新确认 A 的目录；不得保留候选 B 的能力。 |
| 自动选号或失败换号 | 先按现有允许账号、状态和额度规则形成候选，再核实候选账号对最终型号和档位的能力；仅成功候选可取得执行许可。 |
| 候选能力未知 | 经现有协调器在安全探测阶段刷新候选目录；不能当作支持，也不能无界重试。失败后按原候选队列或等待流程处理。 |
| 无支持账号 | 保留任务、配置和原始目标，提示暂无符合条件账号；不降为 High，不替换成其他模型。 |

缓存及进行中的请求共同按账号隔离。身份范围包含 realm、稳定账号身份、认证代次、凭据修订、CLI 指纹和解析器修订；保留现有 provider/config 范围。目录读取前捕获范围，读取完成和写入前再次核对。并发相同范围读取复用请求，不同范围不得共用结果。

AGY Hydrogen 可选能力的有效期最多采用现有账号能力判断的 15 分钟；超期先刷新。刷新失败可保留原始历史资料供诊断，但不能作为当前 Hydrogen 可选或派发依据。稳定账号授权记录仍按现有策略复用，不因页面打开就重复付费验证；实际目录变更、凭据或 CLI 变化后重新校验相应能力。

额度识别结合真实 CLI 输出确定。若 Hydrogen 使用普通 Gemini 池，沿用该池；若实际报告独立池，则补齐解析、覆盖关系和该池真实窗口要求。不得照搬 Argon 的独立周额度规则，也不得凭名称推定 Hydrogen 与 Argon 共池。

**三、所有选择入口与交互设计**

适用于现有能够配置模型的本地用户，不新增角色或登录流程。覆盖以下入口及其中所有已开放角色槽：

- 全局默认模型设置，包括规划、执行及现有高级角色覆盖。
- 创建工作流时的模型配置。
- 工作流模型设置、工具与模型弹窗或抽屉、任务级覆盖和模型切换。
- 整改模型选择，包括活动区和工具模型面板中的入口。
- 群聊创建、编辑群配置和成员模型编辑的独立选择器，以及同步成员后的会话。

共用入口复用 `ModelProfileEditor` 和 `ModelConfigTabs`；群聊保留现有独立界面，但使用同一套账号目录过滤、家族合并和档位标签规则。检查实际挂载的入口，历史组件不作为漏验现用入口的理由。

复用账号快照及 `/api/agy-accounts/notifications` 通知。收到账号、认证代次或切换状态变化时，清空当前 Hydrogen 可选能力，取消旧请求并递增请求代次；只接受与当前上下文一致的响应。重新打开选择器、页面重新获得焦点及连接恢复时重新核对身份，防止跨标签页或断线后保留旧能力。

加载中显示读取状态并禁止提交尚未确认的 Hydrogen；目录成功后显示该账号支持的模型和档位；无可用模型时显示空状态；失败时显示原因与重试操作。支持账号可以选择 Extra、保存并在关闭重开或刷新后恢复 Extra。

账号不支持时，Hydrogen 不出现在可选列表。已经保存的 Hydrogen 配置以列表外的配置摘要提示“当前账号不可用”或“等待目录确认”，保留原值供恢复，不作为可选项重新插入列表，也不自动改成其他模型或档位。受影响配置的新保存及执行必须经过服务端校验。

**四、接口、数据与派发约束**

复用现有接口，不新增独立 Hydrogen 接口。新增字段均向后兼容；账号身份由服务端解析，客户端不能提交账号指纹来证明资格。

| 接口或内部调用 | 本次契约与兼容要求 |
| --- | --- |
| `GET /api/model-tools/:adapter/models` | 保留可选字符串 `scope_id` 和 `ModelCatalog` 响应。AGY 返回实际当前身份目录，增加可选非空字符串 `accountContextKey`；它是不含凭据的上下文指纹，AGY 新响应必须提供。Hydrogen 仅在身份已确认、目录新鲜且条目可用时返回为可选项。其他适配器不变。 |
| `POST /api/model-tools/:adapter/models/refresh` | 保留必填 UUID `request_id`、可选字符串 `scope_id`；首次接受返回 202，幂等重放返回 200 和原操作。操作绑定发起时的账号范围；身份变化以 `ACCOUNT_CHANGED_DURING_DISCOVERY` 失败，不提交迟到目录。继续通过现有操作查询接口取得状态。 |
| `readAgyModels` 内部回调 | 从无参 ID 列表读取改为接受预期账号上下文，返回实际核实的上下文、可用 ID 和观测时间。`ModelCatalogService` 比较预期与返回范围；不一致不得缓存。直接 CLI 模式也需证明身份范围，无法证明时不开放 Hydrogen。 |
| `POST /api/model-access/verify` | 保留 `request_id`、`profile`、可选 `force=false` 和 `scope_id`；返回 200 缓存结果或 202 验证任务。验证前检查当前账号目录及准确档位；Hydrogen 不允许通过手工候选条目绕过目录。验证结果只归属于发起账号。 |
| `PUT /api/settings/model-defaults` | 保留现有 Profile、预期修订和请求幂等契约。新增 Hydrogen 选择在提交事务内核对账号目录及授权，失败不发布部分默认配置。 |
| `POST /api/workflows/:id/execution-spec`、`model-switch`、`repair-model-assignment` | 保留各接口现有请求及回执结构，所有角色 Profile 共用 Hydrogen 校验。修订冲突沿用现有 409；无效型号或档位拒绝，且不得先停止当前执行再发现新选择无效。 |
| `POST /api/groups`、`PUT /api/groups/:id` | 保留群标题、用户、管理员、成员及版本结构；AGY 成员沿用 `tool`、`model` 和可选 `effort` 字符串。保存前校验 Hydrogen 的型号和档位，读取时原值恢复；失败不部分更新成员。同步成员及执行前复用同一检查。 |
| `resolveModelSelection(profile, entry, capability)` 与账号执行许可 | 保持职责分工。先解析精确型号及档位，再以该型号申请账号许可；许可确定后重新核对目标账号目录与上下文，最后冻结参数并启动。工作流、群聊、重试和账号恢复都执行该顺序。 |

接口认证继续使用现有 `human(req)`、工作流访问控制和既有请求保护。非法请求维持现有 4xx；明确不在目录使用 `MODEL_NOT_LISTED`，档位非法使用 `EFFORT_UNSUPPORTED`，档位信息未确认使用 `EFFORT_METADATA_UNKNOWN`。新增可重试的 `AGY_MODEL_CAPABILITY_UNKNOWN`（409）区分目录未知；账号变化继续使用现有身份冲突错误。目录异步失败保留操作错误码和可读原因，不伪装成功。

HTTP、MCP 和内部服务调用应落到同一校验逻辑，不能只在路由或 UI 限制。已提交请求的幂等重放返回原回执，不重复写配置、切号或调用模型；任何新派发仍重新执行准入检查。

数据库复用现有 SQLite 表，不新增表或 SQL 迁移：

- `entities`：继续使用 `kind,id` 主键和 `kind,owner` 索引；通过 Store 读写 `data` JSON，保留 `version` 并发控制。涉及 `agy_account`、`agy_realm`、模型目录及指针、授权记录、默认配置、执行规格、运行和群聊实体。
- `agy_account.models`：复用 `native_ids:string[]`、`observed_at:string`、`executable_fingerprint:string`、`cli_version:string`；新增可选正整数 `credential_revision`，新探测必须写入，历史缺失表示需要重新确认。`native_ids` 仅包含成功解析的可用型号，空的有效列表与读取失败必须区分。
- 模型目录 JSON：增加可选 `accountContextKey:string`，无默认值；新 AGY 目录必填，历史缺失不可证明 Hydrogen 能力。新缓存与旧上下文分开，不批量修改用户 Profile。
- 默认配置及执行规格复用 `modelId`、`reasoning.mode/value`；群聊复用成员 `model/effort`；运行复用冻结型号、档位、账号和会话绑定。无历史配置自动回填或档位替换。
- `dedup` 和 `events`：继续承载已有请求去重和状态通知，不新增凭据、原始认证响应或完整账号目录日志。

账号目录快照与相关身份核对通过现有协调器完成；提交快照和目录指针使用现有事务能力，并在写入前校验身份仍一致。失败不覆盖其他账号或更新成功时间。旧目录通过解析器修订及上下文缺失自然失效后重新读取；回退代码时只处理本任务新增的可再生缓存，不删除用户配置、凭据或历史任务。

账号切换不能修改已经运行的健康任务。新派发使用最终许可账号；原任务重试和恢复保留原型号与 Extra 意图，在新账号重新确认能力。模型或档位改变时沿用现有会话兼容规则，不复用参数不兼容的会话。Extra 验收必须检查真实启动参数及成功终态，只有退出码 0、页面选中 Extra 或模型自述均不足以证明成功。

**五、执行工作项**

- [ ] **W01 核实 Hydrogen 的真实协议。** 为型号映射提供可靠依据。通过现有账号服务获取至少一个支持账号的目录、可用状态和档位编码，核对实际 CLI 路径、版本与启动方式；另确认至少一个不支持的现有账号。产出脱敏映射及账号能力结论。无法取得的项目明确标记缺口，不推断完成。无前置依赖。
- [ ] **W02 建立按账号隔离的 Hydrogen 能力判断。** 让目录、自动选号及失败恢复使用同一事实。按第二、四部分补齐快照上下文、缓存失效、迟到响应保护、未知能力处理和真实额度池映射。依赖 W01 的协议与目录格式；账号隔离部分可先开发。完成后支持、不支持和未知账号均有确定行为。
- [ ] **W03 接通共用选择器的四档配置。** 让默认配置、创建任务、任务设置、切换及整改入口一致显示和保存 Hydrogen。完成家族名称与档位映射、账号通知接入、加载失败状态和历史配置保护。依赖 W01、W02；完成后各入口可保存恢复 Extra，切换到不支持账号立即隐藏可选项。
- [ ] **W04 接通群聊独立选择器。** 让群聊创建、编辑成员和同步会话成员遵守同一账号规则。补齐独立目录请求的账号范围、标签和保存校验，保留成员身份及版本控制。依赖 W01、W02；完成后群聊入口不会残留其他账号的 Hydrogen 或把 Extra 改成默认档位。
- [ ] **W05 贯通服务端校验和最终执行。** 保证绕过页面也不能错误派发。覆盖默认配置、执行规格、模型切换、整改、群聊、MCP 及内部调用；以准确型号申请许可，在账号落定后校验目录，冻结并派发真实参数。依赖 W01、W02；完成后账号不支持、档位无效或身份变化时均在启动前拒绝，重试恢复不降档、不换模型。
- [ ] **W06 完成分层验证与交付。** 证明完整用户流程和既有型号均可用。依赖 W03、W04、W05，执行下列检查，保留真实调用与模拟回归的区别，交人工确认后按已有 DevFlow 职责提交本任务变更。未完成验收保持未勾选。

路径用于定位，执行阶段可自主补齐实现同一需求所需的关联修改，不将路径清单作为修改白名单。
