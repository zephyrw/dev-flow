# 模型群聊、模型配置统一与任务图片附件开发计划

## 背景、现状与目标

用户在模型群聊中遇到搜索图标与提示文字重叠、点击会话后未显示会话内容、成员模型选择框过宽、无法选择已接入的 CodeBuddy 等问题。同时，全项目的工具、模型及账号切换需要保持一致，手动创建任务需要支持粘贴图片作为需求附件。

本轮只调查和规划，尚未修改代码或运行测试。工作包没有现有计划，因此本计划从用户原始需求制定。

已查到以下关联问题：

- 群聊维护了独立的四工具列表、工具名称和模型缓存，公共目录已包含 CodeBuddy，群聊列表与回复解析均未包含它。
- 群聊模型缓存仅按工具区分，未包含工作区和账号身份；CodeBuddy 的公共模型接口已有工作区作用域。
- 会话切换先写入列表摘要，再按会话版本比较详情。同版本详情可能被摘要挡住，需要结合浏览器复现核实完整影响。
- 搜索输入框的局部内边距规则可能被通用输入框规则覆盖；成员模型选择框采用填满剩余空间的布局。
- 手动创建任务只提交文字和工作区引用；现有附件上传入口绑定已创建任务，首次需求创建尚未接通附件。

目标是让群聊界面和会话加载正常，CodeBuddy 可以完成真实群聊回复，各模块使用相同的工具、模型及账号规则，粘贴图片能够进入新任务的首次规划输入。采用共享服务修复这些关联问题，避免只修复单个页面后再次出现差异。

## 总体思路与范围

先统一工具目录、模型作用域和账号生命周期，再接通 CodeBuddy 群聊。群聊界面、会话加载和创建前附件可以分别开发，完成后统一整合验证。

范围覆盖模型设置、默认模型、手动创建任务、任务角色配置、运行中模型切换、修复模型选择、临时提问及群聊等实际选工具、选模型或使用账号的入口。统一数据来源和判断规则；不同用途确有能力限制时，由共享规则给出限制原因。

保留现有合法配置、用户显式选择、角色继承关系、群聊场景、会话历史、工作区引用和工具权限边界。必要关联修改由执行阶段自行定位，不设文件修改白名单。优先复用现有依赖与服务。

## 开发任务

- [ ] **统一所有入口的工具和模型来源，让同一环境下的选项保持一致。**

  复用公共工具契约、模型目录服务和模型身份解析，替换群聊及其他入口自行维护的工具清单、标签、模型列表和默认值判断。默认模型与预置成员通过共享配置和目录解析，保留有效的既有选择。

  共享目录按工具、工作区、原生配置及账号身份区分缓存。账号或作用域变化后刷新相关目录与访问核验状态，防止迟到请求覆盖新选择。统一处理加载、空目录、过期缓存、读取失败、模型下线及推理强度不支持等状态；历史选择可显示并说明原因，不能静默换成其他模型。群聊所需的具体模型等能力限制统一计算。

  完成后，同一作用域下，各入口的工具名称、模型身份、可选状态和刷新结果一致；目录失败有提示和重试入口。

- [ ] **统一账号切换及其生效规则，让各模块显示和实际使用同一账号状态。**

  复用现有账号服务、模型身份及访问核验机制，将正式任务、临时提问、群聊、目录查询和额度展示接入共同规则。各工具保留其原生 provider、profile 和凭据方式，托管账号继续使用现有许可与切换机制。

  明确手动切换、自动切换、账号不可用、额度不足和切换失败的处理。切换前协调正在使用旧账号的调用，按现有策略等待结束或停止后续接；确认旧进程退出后释放许可。切换成功后刷新目录、访问核验和额度身份，下一次调用使用确认后的账号；失败时保留可恢复状态，不展示虚假的切换成功。取消和重复通知不得造成重复回复、自动复活已取消调用或串用账号。

  完成后，各模块对账号身份、切换状态和生效时点保持一致，群聊不再自行绕过公共切换流程。

- [ ] **接通 CodeBuddy 群聊，使它能够从成员选择一直完成模型回复。**

  将 CodeBuddy 接入共享工具选项、群聊输入校验、成员保存、目录读取、模型访问核验、调用和回复解析。目录查询与实际调用使用同一个群聊工作区；缺少必要工作区时明确引导选择，不能使用其他项目的模型配置。

  验证普通回复、结构化结果及失败输出，保留现有回答与执行权限限制。工具未安装、未登录、模型不可用或额度不足时明确报错，并保留原消息及可重试成员状态。

  完成后，CodeBuddy 成员可保存、重新载入、被 @ 并返回真实回复；其他工具和群聊管理员流程保持可用。

- [ ] **修复搜索框和成员模型选择框，使布局符合用户指定行为。**

  修复搜索图标与输入文字的间距及样式覆盖，确保占位文字、已输入文字、聚焦状态均不重叠。

  新增成员和编辑成员使用一致的模型选择框宽度规则：有模型选项时，按最长实际展示文字加上控件必要留白自适应；没有模型选项时，与上方成员昵称输入框等宽。目录异步返回、切换工具或选项变化后重新计算。窄窗口下限制在弹窗可用宽度内，必要时换行，保持模型与推理强度均可操作。

  完成后，选择框不再无条件拉伸，最长选项可辨认，空目录宽度符合要求，弹窗没有横向溢出。

- [ ] **修复会话点击与详情加载，让选中的会话可靠显示完整内容。**

  区分列表摘要和完整详情，确保同版本详情也能补齐消息、轮次及产物。会话标题、内容和后续操作必须属于当前选中会话。

  处理首次进入、已有会话、新建会话、搜索后选择、快速连续切换及请求乱序。切换后清除前一会话的临时展示，旧请求不能覆盖新会话。加载中显示明确状态；失败时提示并允许重试；会话不存在或已删除时显示相应状态。

  完成后，点击会话名称即可显示对应聊天区域和完整内容，刷新后仍可重新进入；保留历史分页、归档、改名、删除、文档预览和移动端导航行为。

- [ ] **补齐创建前图片附件的存储与绑定，使首次规划能够读取图片。**

  扩展现有附件服务，增加以创建请求标识关联的草稿附件归属。复用文件内容校验、上传状态和限额：最多 10 个附件、单个不超过 20 MiB、总量不超过 100 MiB。

  草稿附件至少记录归属、文件标识、名称、大小、声明及检测类型、上传状态和有效期。新任务创建请求增加附件标识集合；创建时校验文件归属、上传完成状态和模型能力，将附件绑定到首条需求，并在首次规划入队前完成提交。图片内容通过现有材料传递机制交给模型，不能只保存缩略图或浏览器临时地址。

  同一创建请求重试返回同一任务，不重复绑定附件或重复派发。文件提交失败时不得启动缺失附件的规划。旧调用不带附件时保持兼容。取消草稿立即回收未绑定文件；失败可保留供重试，未提交草稿 24 小时过期；已绑定需求的附件按任务材料保留。

  完成后，附件归属和首次需求一致，能够从任务中重新查看，模型首次规划可以实际读取图片。

- [ ] **让手动创建任务支持直接粘贴图片，并保留原有文字与引用操作。**

  在需求描述输入框接入剪贴板图片识别，复用现有图片解析、预览和上传队列能力。粘贴后显示附件预览、名称与状态，支持删除、失败重试和随文字提交；图片与文字同时存在时，文字按光标位置插入。

  上传未完成、失败、超限或必需消费图片的模型不支持该格式时，给出具体原因并阻止提交，保留需求和可恢复附件。切换模型后重新判断能力；提交期间防重复创建，移除或关闭草稿后，迟到上传不能重新挂回附件。

  完成后，用户可以通过 Ctrl+V 将图片作为需求附件引用。普通文字粘贴、中文输入、工作区 @ 引用、名称和工作区校验保持正常。

- [ ] **完成整合后的自动检查，覆盖共享逻辑、失败分支和关联回归。**

  执行阶段使用仓库锁定工具链，分别完成包含测试代码的全项目类型检查、生产构建及定向单元、集成、E2E 测试。测试围绕下述行为补充和选择，不默认运行无筛选全量套件。

  既有群聊开放讨论、小说、方案设计、管理员整理、暂停及取消、历史消息与文档预览，以及模型设置、账号许可、任务创建和原有附件功能均纳入影响判断。检查后若继续修改，重跑受影响检查；必需项失败或未执行时保留未完成状态并说明影响。

- [ ] **通过 OpenTabs 操作真实 Chrome 验收，并交付人工确认所需结果。**

  在隔离预览环境中，使用 OpenTabs 完成新建群聊、新增和编辑成员、新增会话、点击已有会话、搜索、会话内 @ 单人、@ 全员及发送聊天。至少完成一次 CodeBuddy 真实回复，并验证刷新后的配置、历史消息及会话切换；不能用接口调用、脚本注入消息或替身结果代替这些操作。

  同时核验不同窗口宽度下的搜索和模型选择框、各模型选择入口的一致性、账号切换后的展示与下一次调用，以及手动创建任务的真实剪贴板图片粘贴和首次规划读取。真实账号切换在不影响现有任务的可控环境中完成；缺少登录、可用模型或切换账号时明确记录受阻项，不以自动测试代替。

  交付时分别报告类型检查、构建、各层测试、OpenTabs 和待人工确认结果。清理本任务未再使用的测试数据库、截图、日志、上传草稿及预览产物；先核实路径、归属和引用，保留正在使用的数据及必要证据，并报告清理量。本轮规划没有生成临时文件，释放空间为 0。

## 执行前提与完成边界

执行阶段使用隔离工作区、预览服务和测试数据，保护主服务、现有任务、凭据及未提交内容。当前发现的 `.devflow-local-update-01a1bff1` 不属于本任务产物，保留。

OpenTabs 真实 Chrome、可用模型登录及图片剪贴板操作是浏览器验收的必要条件；账号切换还需要可安全使用的账号环境。缺少条件时继续完成独立工作，并准确列出受阻场景。真实模型回复、账号切换和图片读取结果都不能由替身测试推定。

本计划等待用户批准后实施；本轮不启动开发、提交、推送或发布。
