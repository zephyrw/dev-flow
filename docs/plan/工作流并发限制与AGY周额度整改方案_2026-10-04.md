# 工作流并发限制与 AGY 周额度整改方案

日期：2026-10-04（Asia/Shanghai）。本文件是分析及实施方案，本次未修改业务代码、运行配置或数据库，未重启服务、切换账号或运行工作流。

## 1. 结论与证据

### 1.1 独立复核只有一个名额的直接原因

源码已取消执行和复核数量限制，但当前服务运行的编译产物仍执行旧调度逻辑。

- [当前调度源码](C:/Code/system-handle/packages/core/src/engine.ts:3279)不再调用 executor/reviewer capacity；直接获取实际工作目录租约后派发。
- [实际编译产物](C:/Code/system-handle/dist/packages/core/src/engine.js:2487)仍调用 `scheduler.capacity(review ? "reviewer" : "executor", ...)`，满额时写入“等待独立复核名额”。
- [运行配置](C:/Code/system-handle/devflow.yaml:15)仍是 `executors: 3`、`reviewers: 1`、`heavy_tests: 1`、`live_environments: 1`。
- 控制器启动记录指向 `C:\Code\system-handle\dist\apps\api\src\main.js`，记录 PID 20212，启动于北京时间 2026-10-04 07:29:52。进程命令行查询被系统拒绝；该路径依据启动记录、健康接口和实时行为交叉确认。
- 实时只读数据库检查存在 `reviewer:0` 活跃租约，持有者为 `wf-3b0333e6-6c49-46ea-8c24-3141d08bb3a3`，状态 `REVIEWING`；同时存在 `executor:0` 活跃租约。
- 源码 engine.ts 修改时间为北京时间 2026-10-01 01:41:26；dist engine.js 修改时间为 2026-09-30 16:15:46。

旧程序以角色为单位设置全局容量池：所有复核争用 `reviewer:0`。这与是否同项目、同模型或同工作区无关。该结构起到控制本机负载、模型调用数量及费用的作用；现有代码没有证明“复核正确性要求全局只能一个”。准确的原始设计动机不能只凭默认值推定。用户已决定自主控制任务数量后，这类固定池应删除。

浏览器工具两次读取均失败，错误为 `Unable to load browser request-header policy`，本次无法声称已直接看到用户打开页面的 DOM。上述结论针对当前 4810 服务的真实接口和 HTTP 前端资源；最终仍须在用户实际页面完成验收。若用户页面指向其他实例，必须核对该实例的入口、构建标识及响应资源。

### 1.3 尚需补齐的链路

- [CurrentRuntime](C:/Code/system-handle/apps/web/src/components/CurrentRuntime.tsx:117)读取 Run 的 `quota.buckets[].windows`，按 `100 - used_percent` 展示；[QuotaPopover](C:/Code/system-handle/apps/web/src/components/QuotaPopover.tsx:18)只格式化时间，没有采用账号页的周重置计算。上次修复的文件列表没有覆盖这两个入口。
- 因此账号管理页修复上线后，运行模型额度弹层仍可能出现不同结果。该路径是已确认的代码遗漏，但尚未确认它就是用户当前打开页面的入口。
- 读取默认 scope 的 `/api/model-tools/agy/models` 返回 `status: missing`、空 entries。该接口不是账号额度接口，不能据此判断账号周额度是否恢复；验收需明确页面、账号、模型池、scope 和数据来源。
- 若源码更新上线后仍异常，继续核对窗口完整性、`capability_verified`、账号身份与模型池匹配、CLI 输出解析、快照新旧顺序，而不是再次局部改百分比组件。

## 3. 实施路线

### A. 固定运行版本，先消除发布断点

涉及 [构建入口](C:/Code/system-handle/package.json)、[API 入口](C:/Code/system-handle/apps/api/src/main.ts)、[健康接口](C:/Code/system-handle/apps/api/src/base-server.ts)、[静态资源入口](C:/Code/system-handle/apps/api/src/server.ts)、[发布构建](C:/Code/system-handle/scripts/release/build-release.mjs)、[服务启动](C:/Code/system-handle/packages/service/src/launcher.ts)。

1. 清点当前 checkout 未提交修改和在途 Run，记录运行目录、控制器身份、构建文件和前端入口。现有 checkout 有大量其他任务改动，不能直接全目录构建后覆盖当前运行目录。
2. 在独立候选输出目录从明确审查过的源码快照构建后端、前端和 Skill 资源。候选必须包含既有周额度修复和取消执行/复核槽逻辑，并纳入当前需保留的修复；不通过覆盖源目录混入无关改动。
3. 使用一份构建标识记录源码快照/提交、构建时间、后端及前端内容哈希。源码含未提交修改时必须用内容摘要识别，不能仅报 HEAD。
4. 服务健康接口返回实际载入版本；前端嵌入相同构建标识。新构建启动前核对前后端属于同一次构建，不能再以 `source/0.2.0` 判定发布成功。
5. 使用已有维护/交接机制等待在途调用结束或明确暂停后更新；保护现有批准计划、会话、冻结参数、worktree、账号及数据库。重启旧 dist 不能视为更新。
6. 发布后核对进程入口、健康接口构建标识、首页所引用资源内容，以及真实接口行为；此后再验收各项改动。

该阶段优先使已完成的源码修复进入运行版本，避免重写已经修复的分支。构建标识属于小范围发布信息，不引入新调度框架或证据平台。

### B. 彻底删除全局名额

涉及 [配置合同](C:/Code/system-handle/packages/contracts/src/config.ts:109)、[Schema](C:/Code/system-handle/examples/schemas/config.schema.json)、[配置](C:/Code/system-handle/devflow.yaml:15)、[调度器](C:/Code/system-handle/packages/scheduler/src/scheduler.ts:14)、[Engine](C:/Code/system-handle/packages/core/src/engine.ts:3279)、[默认模板](C:/Code/system-handle/packages/core/src/templates/default-template.ts:42)、[环境](C:/Code/system-handle/packages/runtime/src/environment.ts:87)、[测试运行时](C:/Code/system-handle/packages/runtime/src/runtime.ts:1101)、[提问服务](C:/Code/system-handle/packages/asides/src/service.ts:12)。

1. 执行、复核、测试、环境的旧容量配置统一成为兼容输入，不校验人为上限、不参与派发。新示例及当前配置移除四类数量字段；不替换成更大的数、Infinity 或另一处 hidden limit。
2. 删除 task/test/environment 名额获取和释放路径；Scheduler 保留 acquire/release/heartbeat/fence 等真实资源租约能力。没有调用者后删除 capacity/waitForCapacity，避免后续复用恢复限制。
3. 删除 aside 全局 active 和 queued 数量判断；一次提交建立一个独立 aside，会话、outbox、Run、取消和账号等待按 aside_id 区分，不能因同 workflow 拦截其他提问。
4. 旧 queued aside 在恢复时逐条幂等派发，不依赖“全局空闲才提升第一条”。waiting_account 不阻塞其他可运行会话。
5. 环境缺少服务清单时仍按已有合同处理；有服务清单时独立启动，不再占用 environment:N，实际 external_lock 仅关联指定数据资源。
6. 文案只报告实际资源冲突、用户暂停、模型账号等待、准备状态；不再生成“等待独立复核名额/执行名额/测试名额/环境名额”。

### C. 缩小真实资源锁，支持独立检查

涉及 [浏览器运行时](C:/Code/system-handle/packages/runtime/src/browser.ts:228)、[CLI 调用占用](C:/Code/system-handle/packages/runtime/src/cli-dispatch.ts:445)、[测试运行时](C:/Code/system-handle/packages/runtime/src/runtime.ts:1101)、[环境端口分配](C:/Code/system-handle/packages/runtime/src/environment.ts:418)、[角色职责](C:/Code/system-handle/packages/core/src/role-boundaries.ts)。

1. 为检查建立 invocation ID；检查状态、进程、结果及报告路径分别按该 ID 记录，task/run 作为归属。调整 `checking`、`check_lock`、`check_process`、取消和空闲检测，不仅删除拒绝条件。
2. 每个检查仍明确一个文件、用例、类或方法。隔离临时输出/报告；同一构建目录、会改变相同数据库的检查按具体资源排队，其余立即执行。冻结阶段推进等待属于本阶段的必要检查完成，不受其他任务或检查影响。
3. 浏览器独立标签页场景按 session/tab 获取资源。启动、导航、截图、失败、清理仅操作本次创建的标签页；对确实共享的焦点/登录操作保留短期、具体资源锁。
4. 核实桥接工具的真实并行能力。若该工具当前只能共享焦点，先分离可隔离操作及浏览器会话，再移除全局锁，不能直接去锁导致串页。
5. 纯代码复核使用冻结材料或可稳定读取的代码版本，并行复核无需独占写锁。复核需要修复时走已有修复 Run 并获取写资源，不能把只读任务悄悄变成写任务。
6. 两个实际写入同目录的任务继续互斥；不同 worktree 不受同项目名称影响。向同一主分支集成仅集成动作互斥，其他开发/复核继续。
7. 动态端口分配必须处理探测与服务绑定之间的竞争、有限重试、所有权及退出释放；portAvailable 只能作候选提示，服务成功绑定才确认端口生效。

7. 公开有效余额用于显示/候选排序，不将本地投影当成已重新核验的真实许可；继续使用已有获取 permit 前的账号/额度核验。
8. 刷新运行账号时遵守既有凭据域操作边界，不为了展示问题停掉所有任务或轮流切换全部账号。真实上游探测失败如实保留旧观测时间及异常。

## 4. 迁移与故障处理

- 旧 executors/reviewers/heavy_tests/live_environments 配置及旧模板能读取，但不再有行为效力；Schema/CLI/示例同步更新。
- 历史 executor:N、reviewer:N、test:N、environment:N 租约不应恢复限制。停止使用后仅在确认所属旧进程退出时清理；不删除 write/data/port/browser 资源租约，不抢走仍在运行进程的资源。
- 旧 capacity queue_wait/resource_wait 在新派发或启动恢复中按实际资源重算；不清空历史事件或冻结 Run。升级中已暂停的任务保留原状态，按已有恢复规则续接。
- 检查运行状态若改变键结构，恢复时识别旧记录并核对进程身份；保留原结果、快照、Run 归属及取消状态。
- aside queued/active/waiting_account 历史状态分别恢复，outbox 保持幂等，避免升级使一个问题启动两次。
- 构建/启动失败保留旧运行目录；前后端标识不一致不发布候选。切换后失败，使用同一发布事务回退整套前后端资源，不用旧数据库覆盖更新后的业务记录。
- 若增加最小快照字段，使用向后兼容可选字段，旧产物可读；恢复旧版本只回退代码，不破坏新历史。
- 对真实资源退出状态不确定的情形报告具体资源与占用者；该任务等待或需要处理，不使所有独立任务停摆。

### 明确停止条件

- 源码、候选产物、实际运行入口或 HTTP 资源无法对应：停止发布，先修正构建来源。
- 不能确认旧进程退出或资源所有权：保留相关租约，处理具体进程，不直接清库解锁。
- 浏览器桥接只能共享操作而未提供可隔离资源：先完成隔离实现及双场景验证，再去除全局互斥。
- 实际页面无法读取：额度修复不能报页面验收完成，保留接口/产物已验证与 DOM 未验证的边界。
- 若实际刷新证明 CLI 字段发生变化：保留原始脱敏输出和版本指纹，先修解析，不通过硬写百分比掩盖。

## 6. 优先顺序

先完成 A，让现有取消执行/复核名额与周额度修复进入实际运行版本；随后实施 B/C，清除剩余固定名额并隔离真实共享资源；D 同步补齐遗漏展示入口。最后在实际运行版本完成组合并行与真实额度页面验收。
