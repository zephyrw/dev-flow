按主方案 N00 至 N14 顺序完成：基线与残项核查 → 原生交付可靠性 → 精简合同 → 轻量运行 → 跨平台 Host → 八工具配置 → 新任务与 @ 引用 → 规划反馈和文档 → 双质量回路 → 功能反馈与 /btw → Git 整合清理 → 现有 UI 融合 → 安装与七 Skill → 模板迁移 → 联合认证和开源候选。

这些工作包用于组织设计与交付，不要求执行过程中逐包向 DevFlow 调用 start/claim。

## 完成规则

两道质量审查分别计算执行模型的连续正式整改失败：首次发现问题只生成完整整改方案，不计失败；执行模型完成方案要求的实现、测试、有效交付和程序自查后，再次独立复核仍不合格才计一次，连续三次才由规划模型接管。执行、测试、超时、交付核验、自查或基础设施失败均不能计入该次数或触发换模型。复核通过清零连续次数并保留历史记录。规划模型接管后以新只读上下文自审。人工问题由执行模型逐项修复，用户复验确认；第二阶段修复改变功能时重验受影响部分。

工作树交付先吸收目标分支最新已提交代码、解决冲突并复审整合结果，再合回，确认成功后清理。主工作区执行只提交任务增量，不合并、不清理当前分支。

交付必须包括真实报告、资源测量、保留布局的回归、八工具和跨平台认证状态。未执行、失败、缺资源和未发布必须分别记录，不能把文档、代码文件或模拟结果当成真实成功。
