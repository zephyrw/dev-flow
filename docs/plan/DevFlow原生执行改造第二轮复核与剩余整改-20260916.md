## 3. 必须修复的问题

### B01 / P1：宿主事实仍会误判成功，异步测试完成又可能无法识别

**位置**

- `packages/evidence/src/native-run-records.ts:50`：从普通输出中搜索 code；
- 同文件第 88、104 行附近：step 标识与退出码提取；
- 同文件第 213 行：readRecords 忽略 runId；
- 同文件第 236 行：使用 includes 判断命令一致。

**实测**

- S01：run_command 返回运行中的进程，后续 command_status 明确输出完成且退出码 0，读取器仍认为原调用没有退出码。它没有建立进程 ID 到后续查询结果的关联。
- S01：宿主命令是 `echo pnpm test`，交付声称 `pnpm test`，校验结果为 valid=true。字符串包含关系不能证明执行了测试。
- S14：输出为“application response code: 0 / Process still running”，没有进程退出事实，却被解析为 exit_code=0、valid=true。工具步骤 DONE 可能只表示异步启动工具返回，不能代表子进程结束。
- 补充边界：S01 中带双引号的 JSON `{"code":0}` 没有触发这个正则；触发 S14 的是普通文本 code: 0。整改必须测试真实输出结构，避免根据一个样例推断所有形状。

**整改**

按真实 AGY 协议建立 run/conversation/tool-call/process 关联，区别工具返回与进程退出。由宿主结构化结果或有明确边界的宿主完成元数据提取退出码，不扫描业务 stdout 的任意 code 字样。未知、运行中、失败或取消都不能成功。

命令校验使用实际调用及参数结构，不能用子串匹配；cwd、轮次和会话必须一致。新增支持同步、异步、重复更新、旧历史重放的脱敏真实协议夹具。DevFlow 读取已有执行事实，不重新执行测试。

**验收**

S01 的已结束异步命令能通过；echo 命令和 S14 必须拒绝。缺原始退出事实保持 unknown，不能从模型声明补齐。
