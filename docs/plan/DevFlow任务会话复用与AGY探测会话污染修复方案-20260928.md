# DevFlow 任务会话复用与 AGY 探测会话污染修复方案

日期：2026-09-28。状态：缓存/并发、最新 Run 追踪及账号额度身份校验已修复；真实规划→执行→复核、原生取消后续接已通过。正式服务更新和历史错配账号恢复待用户确认。详见 [实施与验收记录](../test/AGY账号额度与会话复用修复验收-20260928.md)。

**实施范围补充（用户已确认）：** 当前未找到 AGY 1.2.12 可用的无历史探测入口。用户选择“先保留原探测方式，完成缓存/去重与真实流程修复；无痕能力暂列未完成”。因此下文涉及无可见历史的目标均列为未完成，不作为本次已实现能力；保留必要探测、原提示词、访问门槛与现有超时策略。重启后缓存仍会失效，首次必要探测仍可能生成可见短会话。不删除旧历史，也不编造 CLI 参数。

## 1. 结论与排查边界

用户看到的短会话确实包含 DevFlow 自动创建的真实 AGY CLI 会话。它们主要是“模型访问验证”和“每次执行许可申请前的模型探测”，用于验证模型调用能力，但被保存进用户日常使用的 CLI 历史。探测本身不因此被认定为多余，问题是重复调用和可见持久会话副作用。临时工作目录和 `--sandbox` 都不能阻止保存原生会话。

但今天两个正式任务的 AGY 主会话，在首次运行和恢复运行之间均保持同一个原生 ID。不能把“探测会话污染”直接等同于“这两个任务每次恢复都新建主会话”。现有统一绑定已生效于这两条执行链；规划到执行及后续正式角色的完整链路仍需真实验收，不能由这两次恢复推断全部通过。aside（类似 /btw）按原设计独立，属于正常功能，不纳入正式主会话复用。

初次排查只读检查源代码、已构建代码、运行描述文件、生产 DevFlow SQLite 和原生 stdout；AGY CLI 摘要库复制到临时目录后读取，属于时点副本，不宣称是全局原子快照。此后用户授权实施，已执行隔离回归和真实模型验收，新增测试会话详见验收记录；没有删除历史或修改生产业务任务。

排查开始时存在多处未提交修改；排查结束时它们已由外部工作提交，当时 HEAD 为 `8f9d304`。本方案不能替代实施前重新核对代码和活动任务。运行描述指向 `dist/apps/api/src/main.js`，AGY 探测缺陷在当前源码和 dist 中均可见。

### 2.3 为什么只回答 OK

`packages/core/src/model-access-service.ts` 的 `ACCESS_PROBE_PROMPT` 为“仅回复 OK，不读取文件，不调用工具”，`buildAgyProbe` 用 `--mode plan --sandbox -p` 调用 CLI。`executeProbe` 每次使用新的 `verif-*` 目录，不传 `--conversation`，也不登记任务会话绑定。

`packages/adapters/agy/src/account-probe.ts::probeModelAccess` 用 `-p "Reply only OK."` 做真实推理。`packages/agy-accounts/src/service.ts` 在发放执行许可前，对 `required_model_ids` 逐个调用它，不只在账号切换时调用。`packages/process/src/agy-account-job-runner.ts` 每次生成新的 `devflow-agy-aux-*` 目录，结束时删临时目录，却不会删除 CLI 全局历史。

因此 OK 是代码人为设置的最小推理探测，不是任务模型自行决定只做这件事。它的目的在于检测模型能否调用；当前实现把检测副作用泄漏进用户会话列表。

## 3. 用户确认的范围与纠正

以下约束替代上一版扩大范围的要求，实施时不得自行变更正常功能：

- **aside 保持原行为。** 它类似 /btw，排除在正式统一绑定之外是正常设计。保留独立会话、权限、调度、生命周期和现有测试，不强制归入主根，不改成等待主会话空闲。
- **必要探测保留。** 不删除模型验证入口，不放宽模型访问门槛，不以第一次正式任务代替必要的前置验证。修复目标是探测不进入主会话，也不在用户日常 CLI 历史中留下可见持久会话。
- **工作目录按正常流程固定。** new_worktree 模式应在规划启动前就准备实际 worktree，执行沿用它。不设计目录变更兼容，不改变绑定键算法，不引入新工作区映射机制。existing_workspace 模式沿用其原行为。
- **真实 CLI 测试保留且必须做。** 不增加“普通测试禁止真实 CLI”的全局禁令。模拟测试只能验证可控分支，不能代替实际规划、执行和恢复验收。
- **只修有证据的缺陷。** 不借本次问题重构展示树、模型可用性状态机、账号切换、会话契约或发布框架。凡需改变现有正常功能或跨越上述边界，先说明具体影响并向用户确认，再纳入执行方案或实施。

### 3.1 已确认要修的问题

1. 两条模型探测路径使用真实生成请求，却没有不保存可见历史的措施。verif-* 和 devflow-agy-aux-* 已与现场会话对应。独立于主绑定本身不是错，错误是让临时探测成为可见持久会话。
2. AgyAccountProbe.modelAccessCache 只有读取没有成功写入，现有 24 小时缓存逻辑没有生效；同键探测也没有登记自己的运行 Promise，无法合并重复请求。修复沿用现有成功判定和缓存键，不扩大有效期或跨账号共享结果。

### 3.2 关联问题：先验证具体影响，再做最小修补

这些发现不能全部解释成今天重复会话的原因，也不是全面重构授权：

- resolveClientScope 的 AGY 默认目录是 .gemini/antigravity，本机 CLI 历史与原生记录读取器使用 .gemini/antigravity-cli。先区分客户端会话配置域与账号凭据域，只有确认影响实际复用/定位时才修相应解析；不能全局替换目录或直接重写生产绑定。
- onRootSession 向 Run 写原生 ID，engineRecoveryRunPort.observeAttempt 又把内部 cnv-* 写进 Run.conversation_id。现场 root_session_id 与 binding 仍保存真实 ID，当前恢复成功。先核对消费者字段语义；若真实续接/打开入口误用内部 ID，优先让该入口读取已有正确字段，不预设新增契约或全库迁移。
- bindConversationId 的同 ID 分支未更新 latest_run_id，现场该字段停在旧 Run。核实约定后仅补最新 Run 追踪，保持根、owner、generation 与原有 revision 语义。
- 按 purpose 组织展示节点不等于 CLI 创建新根。本次不调整展示树分组，也不以界面聚合掩盖原生会话问题。

### 3.3 工作区流程重新核对结论

packages/core/src/create-workflow.ts 的标准 new_worktree 入口，已在记录创建意图后执行 git worktree add，再持久化 workspace 并排入 planning。profile-runtime.ts::planningWorkspaces 优先使用已有 workspace。用户要求的“规划前准备好 worktree”与这条正常路径一致，不需要另造兼容机制。

planningWorkspaces 缺少 workspace 时仍有读取源仓库的兜底，注释说明服务于外部提交计划的场景。上一版把它扩大为正常规划到执行的目录切换问题，判断不准确。后续通过真实任务检查各入口，特别是多仓库是否完整准备；只有正常入口确实漏建工作区，才在进入规划前补齐。若修补会影响外部提交计划的现有行为，先问用户，不直接删除兜底。

## 4. 收窄后的实施顺序

### 4.1 先确认探测不留可见历史的真实能力

检查 AGY 适配器、model-access-service.ts 与 account-probe.ts 的探测准备逻辑。

1. 核实当前 CLI 版本的官方参数、接口或已支持的临时会话机制，确认能沿用目标真实账号、模型及必要环境完成访问验证，同时不在用户日常 CLI 历史中留下条目。先查本地能力与官方说明，再做明确范围的真实验证。
2. 目前只确认 agy --help 没展示明确无历史参数，不能据此断言绝对不支持，也不能编造 --ephemeral、假设 AGY_HOME 可以隔离，或把临时 cwd/--sandbox 当作无历史能力。
3. 若证实存在受支持能力，只在两条探测路径启用；正式任务依然持久化并按原绑定续接，aside 保持原行为。保留账号归属、模型匹配、成功终态、超时、取消、权限和错误分类。
4. 验证成功、失败、超时、取消四种结果都不留下可见探测会话，也不向主会话写入 OK；不能只测成功路径。
5. **若未找到可用能力，或必须更换账号、改变验证流程、创建额外持久会话、删除原生历史才能实现，本项停止并先问用户。** 报告已核实限制与具体可行选择，不擅自删除探测、放宽访问检查、切账号或使用私有数据库删记录。

这是待验证的技术前提，不是已确认可行的实现。能力未落实前不能声称会话污染已彻底修好。

### 4.2 修复已有缓存与并发缺陷

主要文件：packages/adapters/agy/src/account-probe.ts；按需核对 packages/agy-accounts/src/service.ts 的调用方。

- 同一账号、凭据版本、模型、CLI 指纹验证成功后写入现有缓存；失败、解析不完整、取消、超时不能缓存成功。
- 同键并发合并为一次探测；结束后清理进行中状态。不同身份不共享结果，沿用账号服务互斥规则，避免与身份/额度探测并发改变上下文。
- 保留现有 24 小时期限与失效边界，不新增持久化缓存体系，不改账号恢复策略。重启后首次必要探测依靠 4.1 的无可见历史能力解决。
- 一个等待者取消不能误杀其他等待者；账号操作整体终止时按原语义取消，优先复用现有机制。
- 检查两条探测入口的重复调用，但不为去重重建模型验证服务。补缓存只是减少重复，不能替代“不留可见历史”的验收。

### 4.3 真实验证规划→执行→续接，缺哪里补哪里

核对范围是 create-workflow.ts、profile-runtime.ts、execution-session-store.ts、AGY 参数构造与现有恢复入口，不是要求全部改动。

- new_worktree 任务在规划前已准备每个所需仓库的真实 worktree；规划、审批后的执行沿用同一组目录。保留审批后才实施业务代码的流程。
- 规划与执行为同工具同模型时，正式流程按现有统一绑定继续同一主根；为不同工具/模型时，各自真实创建并复用自己的主根。后续正式角色按相应工具模型核对。
- 首次 init、暂停恢复、失败重试逐项对照 binding、实际 CLI 参数及原生 init；继续使用既有绑定，不以“最近会话”替代。
- aside 单独验证原有独立行为，不纳入正式主根计数。原生子 Agent、账号切换与既有恢复策略不顺带改造。
- 对 cnv ID 误传 CLI、最新 Run 追踪错误等已复现问题，仅修相应读写入口并增加回归。若涉及正常功能或兼容性变化，先说明并问用户。

### 4.4 真实链路为最终标准，模拟测试补充分支

保留真实 CLI 测试方式，使用明确测试任务/worktree与可追踪会话。实际用于工作流验收的持久测试会话是合理产物，不应被误判为 OK 探测垃圾。

- 缓存、并发、取消、身份失效、异常输出等分支用受控 runner/fixture 精确回归，减少重复且无意义的模型请求。
- CLI 适配、认证、模型、worktree、原生会话持久化和恢复必须真实测试。模拟通过不能证明真实链路通了。
- 在同一测试任务中连续跑多轮并复用会话，不为每个断言新建任务；记录任务名与原生 ID，便于辨认。
- 不改全局测试配置禁止真实 CLI，不切用户账号或接管正在运行的生产任务；结果中说明新增的真实测试会话。
- devflow-test-KN2Adm 只证实是真实测试目录会话，尚未确定具体调用者。不能仅因它存在就认定测试方式有缺陷。

## 5. 验收要求

| 场景 | 通过条件 |
| --- | --- |
| 必要探测成功/失败/超时/取消 | 真实验证结果可信；主会话没有 OK；用户日常 CLI 历史无新增探测会话 |
| 重复许可、同键并发 | 缓存有效写入；有效期内不重复推理；并发只执行一次必要探测 |
| 账号/凭据版本/模型/CLI 指纹变化 | 旧结果不错误共享；原有访问控制与账号行为保持 |
| 服务重启 | 必要重验真实执行，仍不留下可见探测会话 |
| new_worktree 规划→审批→执行 | 规划前实际创建 worktree；多仓库完整；后续目录一致，不靠目录兼容 |
| 同任务同工具模型的正式多轮 | 主根 ID 不变，CLI 可查看连续历史 |
| 规划与执行为不同工具/模型 | 各自真实创建并分别复用，不串会话 |
| aside / btw | 保持独立、不占正式绑定、不污染主上下文；原有功能回归通过 |
| 暂停恢复、重试 | 参数与 init 匹配已有根；原有恢复语义不被扩大修改 |
| 内部节点/原生 ID、latest Run | 使用入口语义正确，不把 cnv ID 用作原生续接目标 |
| 真实测试任务 | 实际规划→执行及后续多轮跑通；新增会话有明确任务归属，不能以 mock 代替 |

优先扩展既有 w02-agy-resolution-and-probe、agy-model-verification、cli-session-lifecycle 与真实工作流用例，不新增测试框架。保留 aside 的既有隔离断言。

真实验收前后记录 CLI 历史基线，区分正式测试主根、正常 aside/子 Agent 与探测会话。必须打开原生 CLI 核对；仅数据库一条 binding、页面状态正常不足以证明通过。

## 6. 现有记录、发布与确认边界

- 排查阶段只修改方案；后续用户已授权实施。实施只修改本方案范围内源码、测试和记录，保留现有两个正式主根、生产数据与服务，不重建生产任务/worktree，不清空历史。
- 不预设全库迁移。若最小修复仍需更新持久化身份/字段，先给出具体记录、兼容办法和风险并问用户；不暗含重建 owner 索引或改变绑定键。
- 老探测会话清理不是默认动作。不得按 OK 标题/两步记录批量删除，不直接写 AGY 私有历史库。需要清理时另列可核实 ID与具体操作再确认。
- 发布前核对活动任务；需要停服务、暂停任务或改变正常会话行为时，先说明影响并按用户要求询问。沿用项目现有发布/备份方法，不新增发布框架。
- 回滚优先恢复本次代码/配置；不以旧数据库覆盖新进度，不回滚整个 AGY 历史目录。
- 尚未落实的关键前提是“AGY 真实探测不留 CLI 可见持久历史”。若能力验证不成立，先报告并问用户，不擅自换成取消探测、放宽验证或事后删除会话。
