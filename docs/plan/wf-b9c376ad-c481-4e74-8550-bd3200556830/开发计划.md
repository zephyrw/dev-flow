# AGY 5.5 模型、双类别额度与并发一致性开发计划

日期：2026-10-04（Asia/Shanghai）

## 背景与目标

用户要求增加 AGY 的 Opus 5.5、Sonnet 5.5 选项，展示并管理 Gemini 与其他模型各自的周额度、5 小时额度。其他模型额度放在原 Gemini 额度和重置时间下方，两类均有清晰标识，区域适当扩大。账号自动选择、额度耗尽切换和恢复必须使用执行模型所属类别的额度。

所有同时使用 AGY 的任务只能属于一个模型类别：Gemini 类，或其他模型类。Opus 5.5 与 Sonnet 5.5 同属其他模型类，可以同时运行；它们与 Gemini 不能混用。限制针对共享 AGY 凭据域中的全部占用任务，包括跨项目任务、规划、执行、测试、复核、旁路问题及原生子任务；不增加任务数量限制，也不限制非 AGY 工具。

当前源码已经解析 Gemini Models 和 Claude and GPT models 两池，并各自保存额度窗口，但账号卡片只选一个快照显示。resolveModelPools 当前忽略模型返回 global；requiredQuotaPools 在无真实 global 时默认取 Gemini 或首池，再补模型匹配池，会让其他模型请求被无关 Gemini 余额约束。现有 permit 保存池要求但未保存模型类别，不能据此可靠实施分类并发。

本次只完成调查与正式计划，尚未进行产品开发或功能测试。主目录存在大量已有改动；批准后使用主仓库 .worktrees 内独立工作树，执行前核对基线、已有相关修复及其提交/发布状态，保留用户未提交内容，不擅自提交或搬运全部主目录改动。

## 当前证据及模型能力边界

2026-10-04 本机 agy models 查询成功退出，返回 Gemini 3.8/3.7/3.6 Flash、Gemini 3.1 Pro，以及 claude-sonnet-4-6、claude-opus-4-6-thinking、gpt-oss-120b-medium；本次输出未列出 5.5。查询出现日志写权限提示，随后成功读取已有登录并取得目录。此结果只说明当前账号/CLI 目录的观测，不否定用户说明的新增支持，也不能把猜测的模型 ID 当成已验证事实。

新增两个选项仍是必须完成的需求。执行时核对 AGY 原生目录或正式 CLI 契约，确认两个 5.5 模型的实际调用 token、展示名、是否存在 thinking 后缀及真实能力。若当前目录暂未返回，可用明确标记为待核验的候补选项保留用户选择；在调用前完成现有模型访问核验，失败时显示模型不可用的实际原因。不能借用 4.6 token 冒充 5.5，不能自动回落到另一模型，不能给新条目臆造思考强度。真实 5.5 调用未通过时该验收项保持未完成，其他开发继续进行。

## 功能与数据设计

### 1. 统一模型类别与目录

模型目录、模型选择、任务冻结配置、额度映射、permit 和恢复统一使用 Gemini / 其他模型类别。类别由实际 AGY 原生模型 ID 与已核验池映射确定，Opus/Sonnet 和已有 GPT 类模型进入其他模型类。目录能力与实际可访问性分开记录。未知模型或池映射不明时给出可理解的待核验原因，不默认归为 Gemini，也不凭展示名模糊匹配。

Opus 5.5、Sonnet 5.5 可在全局执行配置、任务执行模型配置等已有 AGY 选择入口看到并持久化；刷新目录、重开页面、账号切换后选项和状态正确，不重复条目。已冻结 Run 保持原模型；新全局默认只影响后续派发。

### 2. 两组额度完整显示

每个账号固定展示两组：上方“Gemini 额度”，下方“其他模型额度（Claude / GPT）”。每组都有周额度、5 小时额度和各自重置时间，使用同一套现有格式化、剩余/已用转换、未知状态、倒计时、有效周额度投影及刷新规则。适当增加卡片高度和内容空间，不能通过切换当前模型隐藏另一组；缺失时在所属组显示待实测/不可用，不借另一组或列表首项补位。

当前运行模型和额度弹层按其冻结模型显示正确类别和两个窗口，并标识所属类别；所有本来展示账号双类别总览的区域按 Gemini 上、其他模型下排列。用于展示的投影不改写原始快照，不能替代启动前的真实额度及访问核验。已有周额度无周期/到期语义复用当前已核实修复，缺失来源、非法时间或未核验窗口不能借投影成为有效观测，五小时规则保留。

快照继续按账号、凭据上下文、模型池存储，一组缺失或异常不污染另一组。乱序刷新不能覆盖较新数据；较新真实消费观测必须替换旧满额投影。倒计时边界自动更新。刷新沿用已有安全范围，不为了双组显示轮流切换所有账号或中断任务。

### 3. 按模型类别选择与切换账号

有模型需求时只选择该类别实际匹配的池；若官方确有全局共同约束则同时检查真实 global，不能用 Gemini 池充当 global。没有任务模型需求的独立账号管理操作保留明确的选择上下文，以当前管理设置模型/活跃类别为依据；页面清楚显示自动选择依据，执行任务始终以自身冻结模型为准。

候选排序、周及五小时耗尽判断、重置等待、切换前刷新、候选账号模型访问核验、夜间策略、自动恢复和失败解释均使用相同类别。例如账号 A 的 Gemini 0%、其他模型 80%，账号 B 的 Gemini 90%、其他模型 20%：Sonnet/Opus 按其他模型余额评估 A，Gemini 按 Gemini 余额评估 B，不能取两池最小值误判。任一所属窗口真实耗尽且未恢复时遵循已有不可用/等待规则。

账号切换仍是凭据域整体操作，恢复该域所有受影响消费者；恢复批次可以包含 Opus 与 Sonnet，但目标账号必须满足批次中每个实际模型的访问能力、账号允许列表及同类别额度。保持原工作流、Run 用途、会话、计划绑定和模型 token，不以切换为理由换模型。普通网络故障、泛化 429 或模型输出文本不作为额度切换信号。

### 4. 分类并发占用与选择限制

共享 AGY 凭据域保存可恢复的类别占用信息，将模型 ID、类别、消费者/Run 归属关联到有效 permit 或等效持久占用记录。issued 即占用，started 继续占用；释放必须跟进真实启动失败、停止、完成与进程退出结果。原生子任务继承父类别，不能绕过限制跨类启动。

模型选择页面在其他 AGY 任务占用期间只允许同类别 AGY 模型，显示“当前 AGY 任务使用 Gemini 类/其他模型类”及阻塞原因；Opus 与 Sonnet 不互相禁用。涉及保存、切换、继续任务、启动/取得 permit 的后台入口均校验，直接 API 请求不能绕过。两个不同类别同时启动时通过事务或已有协调器原子裁决，只放行一个类别；同类任务数量不受此规则限制。

类别约束按当前实际占用执行，不把历史完成任务、未执行草稿、全局未来默认永久当作占用。停止一个任务但同类别另一个任务仍存活时不能释放整个类别；最后一个真实占用解除后可选另一类别。暂停、额度等待和恢复中如果还有已发许可或未确认退出进程，保留占用；已确认全域无 AGY 进程/有效许可后允许换类，原暂停任务恢复时重新检查类别，不能自动抢占正在运行的另一类。

主动跨类切换被拒绝时不先停掉其他任务，不启动账号切换、不污染现有额度状态；提示用户等待当前类别任务结束或主动停止它们。保存未来默认不改当前 Run，实际任务生效前仍必须核对当前占用。

### 5. 兼容、恢复与故障处理

新增类别字段采用可兼容的契约/存储迁移，不批量猜测历史记录类别。旧 permit 能从其原冻结模型及可靠池证据恢复时补齐；证据不足且进程可能存活时阻止新增跨类请求，并提示需恢复核对。不能把旧 global 直接当 Gemini，不因控制器重启清掉所有占用。

恢复核对持久状态、真实进程和凭据域锁；未知进程状态保持阻塞，确认退出后释放。切换中断、候选不可用、无可用账号、登录失效等错误遵循现有回滚/等待机制，保留原账号和任务恢复信息。外部 AGY 进程与管理服务模式遵循现有凭据域保护，不能关闭管理后绕开类别检查。

不增加全局串行调度或容量名额；保留真正共享工作目录写排他、数据锁、凭据域切换锁、浏览器和端口隔离。相关逻辑定位于 AGY 模型适配、agy-accounts、运行桥接、模型配置和前端展示链路；这些路径用于定位，不是修改白名单。

### 集成

- I03：重启恢复、旧 schema/permit/快照兼容、进程存活或未知、最后消费者退出、等待任务重验；无混类窗口、重复启动或永久残留占用。
- I04：额度 API 返回两组完整数据、身份/凭据/能力核验与乱序更新、运行模型额度弹层；新记录替换投影，原始快照不改写。回归导入/移除/重新登录、手动设活动账号及独立管理模式。

### E2E

- E01：隔离真实前后端和真实浏览器，从模型配置选择并保存两个 5.5 选项，重开/刷新核对；打开账号管理、展开运行模型额度，核对两组数据、重置时间与分类标识。
- E02：从真实页面启动同域 Opus 与 Sonnet 任务均成功；尝试 Gemini 被拒绝且既有任务继续。反向 Gemini 占用下拒绝其他模型；单个任务停止仍受剩余占用约束，全部真实停止后换类成功。跨项目和直接 API 竞争补充覆盖。
- E03：用隔离可控额度与真实后端完成账号选择/耗尽/等待/切换/恢复闭环，验证实际类别及账号归属；真实 AGY 账号另行核对 5.5 调用与所属额度、A→B→A 切换。受控数据验证不冒充上游真实模型/账号验收。没有相应真实能力时明确保留该未完成项，不宣称全功能完成。
