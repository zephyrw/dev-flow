## 1. 必须遵守的产品边界

1. 页面只显示用户当前需要看的内容；模型信息只有一个主要展示位置：右上角。
2. 右上角正常形态为 `Codex GPT-6 Astra(xhigh)` 加一个额度图标按钮。不加“模型”“工具”“思考强度”前缀，不摆设置、修改按钮、账号信息、会话说明、配置来源或历史记录。
3. 设置位于左下角；AGY 账号、使用指南、设置三个入口图标和文字左对齐。
4. 配置、账号管理等表单全部采用白色居中弹窗。额度小浮层、下拉列表、附件菜单是与触发点相连的轻交互，不改成大弹窗；执行过程仍是既有侧栏。
5. 工具模型配置按步骤 Tab 复用一套“工具、模型、思考强度”表单，不在页面竖排多套相同表单。
6. AGY 账号窗口默认只包含：自动切换开关、添加管理账号、账号列表及必要的账号操作。没有模型输入、时区、夜间起止、日间维护、启动管理或“自动选择并切换”按钮。
7. 删除用户点名的说明和模块，不通过“默认折叠”“移到下面”“换个名字”继续占位。不增加新仪表盘、模型历史、诊断中心、账号策略编辑器、配置向导或说明书式空状态。
8. 简化界面不能损坏真正的能力：模型和对应强度必须可选、保存和生效；账号添加和切换必须按真实能力运行；内部冻结配置、并发控制、账号隔离和恢复保护继续有效。
9. 本次不修改工作流质量复核顺序，不增设业务阶段，不改变用户已有模型配置和任务状态。与同日 MiMo 接入、轻量工作流改造兼容。
10. 验收材料属于开发工作，不能变成 DevFlow 的新业务门槛或新界面模块。

## 4. 确定的界面与交互

### 4.1 工作台布局

```text
┌──────────────┬────────────────────────────────────────────────────┐
│ DevFlow      │ 任务名称          Codex GPT-6 Astra(xhigh)    [额度图标] │
│ 工作流总览   ├──────────────────────────────────┬─────────────────┤
│ 项目/任务…   │                                  │ 执行过程        │
│              │ 现有任务内容                     │ 原生会话内容    │
│              │                                  │                 │
│              │                                  │ 输入内容…       │
│ AGY 账号     │                                  │ [+]        [↑] │
│ 使用指南     │                                  │                 │
│ 设置         │                                  │                 │
│ 连接状态     │                                  │                 │
└──────────────┴──────────────────────────────────┴─────────────────┘
```

- 左下角顺序固定为 AGY 账号、使用指南、设置、既有连接状态。按钮整行可点，`justify-content:flex-start`、`text-align:left`，图标宽 18px、间隔 8px、统一 padding。
- 沿用现有导航宽度、主内容和执行侧栏结构，不借机重做全站。
- 顶部名称 13～14px，工具使用 `Codex`、`AGY`、`MiMo Code` 等简短名称。明确映射已知显示名，例如 `gpt-6-astra → GPT-6 Astra`；未知模型使用原 ID 一次，不用字符串规则编造产品名称。
- 运行名整体 hover/focus 变主题蓝；按钮背景透明、没有常驻边框；键盘 Enter/Space 可打开配置。
- header 主标题 `min-width:0`、允许截断；运行区域保留内容宽度，禁止把工具、模型、强度各自裁成 `C... · g...`。较窄屏幕先把运行区放到标题下一行、仍右对齐；只有真正超长名称才整体截断并提供完整 title。
- 移除顶部“会话与续接说明”和 AGY 账号行，移除任务工具条中重复的“工具与模型”按钮。没有已选模型的可编辑任务，原位置提供 `选择模型` 入口；总览、指南不展示虚构的任务模型。

### 4.2 当前模型显示的确定规则

| 任务情况 | 顶部取值 | 额度 |
| --- | --- | --- |
| 正在执行/启动/等待原生响应 | 严格匹配 workflow 当前 run 的冻结调用；同 run 的可靠原生实际观察可覆盖模型和强度 | 只读该运行绑定账号与模型作用域的数据 |
| 当前模型已有保存草稿但尚未应用 | 继续显示仍在运行的模型 | 不提前换成草稿额度 |
| 已暂停、等待批准、尚未启动 | 显示服务端给出的该任务继续执行/下一步生效配置，任务原有状态仍显示“已暂停”等 | 点击显示“暂无运行中的模型”，不复用历史百分比 |
| 已结束/无法确定下一执行上下文 | 不拿最后一轮冒充当前；已结束任务隐藏模型控件，仍可从既有任务记录看历史事实 | 不展示历史额度 |
| 工具已知，模型或强度未报告且配置也无法确定 | 只展示已知部分，不附“工具默认”“未选择强度”“实际未报告” | 缺失部分不造数 |

显示字符串统一由 presentation 层生成；运行中的实际模型、请求模型仍在内部区分。不要使用其他 run 的观察补字段；原生路由器尚未报告具体模型时保留已知路由名称，不能假定某个实际模型。点击顶部默认打开当前角色对应的 Tab；不因为用户在其他 Tab 浏览就改变实际执行角色。

### 4.3 额度按钮与小浮层

- 使用用户第二张图所表达的简洁仪表盘式线性图标，尺寸 16px、点击区域至少 28px，`aria-label="查看额度"`，无常驻额度文字。
- hover/focus 可预览；点击可固定/关闭；鼠标从按钮移动到浮层不会立即消失，移出两者后关闭未固定浮层；点击外部或 Esc 关闭，触屏用点击。
- 白色浮层宽约 260px，锚定按钮下方，距按钮 8px，遇边界翻转；不是右侧抽屉。
- 内容只保留两行：`5 小时  剩余 68%`、`每周  剩余 42%`，可配极细进度条；有可信 reset 时间时各加一行简短恢复时间。示例数字只是布局示例，不能成为默认数据。
- 缺窗口显示 `暂不可用`；有上次值但已过期显示 `待更新`，旧百分比不冒充当前额度。不能因为重置时间已到直接推算为 100%。
- 只显示 300 分钟和 10080 分钟的实际窗口；供应方不是这两个窗口时显示对应行不可用，不能硬改其周期名称。
- 对确认为账号共享且适用于当前模型的额度，可展示并在浮层内用一句 `当前模型使用账号共享额度` 说明。不存在映射证据时不可拿全局或其他模型数据顶替；不显示其他模型列表。
- 打开/hover 只读取或订阅当前账号已有额度服务，不轮询备用账号，不切换登录身份，不触发模型推理。继续复用已有采集和节流机制。

### 4.4 输入区减法

输入区保留输入框、已有附件、加号、发送/停止按钮，以及已有临时提问的必要操作。placeholder 收敛为 `输入内容…`；`/btw`、`/side`、`@` 保留真实行为及输入后候选，去掉常驻长说明。

删除：空输入橙色行、规划模型行、上次模型行、输入区模型配置按钮、发送交接提示、运行模型记录及其卡片。空输入只禁用发送按钮；附件上传失败、网络提交失败等实际错误仍在发生时显示一条具体错误，不把所有状态提示一起删掉。

`ConversationStatusBar` 中必要的会话状态若已有执行区状态显示则合并，模型展示分支取消；不能因为移除组件顺手破坏其用于发送路由的 hook。`WorkflowActivity` 只保留用户真实功能问题与复测操作，无问题无错误时不渲染空容器。

### 4.5 统一居中弹窗

- 新增一个轻量共用 `AppDialog`，用现有 React/CSS 实现，不引入整套 UI 框架。
- 工具模型弹窗宽 720px，AGY 账号 760px，简单确认/添加视图 480px；统一 `max-width:calc(100vw - 32px)`、`max-height:calc(100dvh - 48px)`，在视口中心。
- 白色表面、主题正文/边框/蓝色主按钮，圆角 12px；header 和 footer 不随正文滚走，仅 body 滚动。大列表不能让保存按钮掉出视口。
- portal 到根部，单一遮罩、焦点约束、打开时聚焦标题或首控件、Esc 关闭、关闭后焦点回到入口、背景不可操作。
- 无草稿可点遮罩关闭；有未保存编辑，遮罩不丢稿，Esc/关闭/取消触发同一条简短放弃确认；确认使用同一对话框视图，不叠第二个侧栏或多层遮罩。
- 账号列表进入添加/重新登录视图采用同一弹窗内切换并有返回按钮；登录操作进行中可关闭 UI，后台操作由既有操作 ID 追踪，再打开恢复进度，不重复启动登录。
- 逐项核对工具配置、设置、创建任务、账号、计划问答/修改、来源变更、反馈、历史、文件 diff、图表预览等现有真正弹窗。已经居中的维持业务内容，仅统一必要容器行为。锚定的额度/附件/@候选/临时提问浮层不强行居中。

- 新流程 `quality_policy_version=2` 按同日工作流计划只有规划、执行两组职责，因此也只有两个 Tab。审查、规划修复、提交映射规划，开发、执行测试、功能修复映射执行；以服务端实际职责映射为准，不在前端重新推断业务阶段。
- 老流程仍允许的 reviewer/review_fixer/functional_fixer 用 `代码审查 / 质量修复 / 功能修复` 三个附加 Tab 表示；不得把旧任务的独立选择静默丢掉。只有该任务实际允许配置的 Tab 才出现，不创建无法生效的步骤。
- 老流程附加 Tab 顶部只有一个复用选择：`同规划 / 同执行 / 单独选择`，按已有合同限定合法来源（审查默认同规划，修复默认同执行）。跟随时不再堆第二份表单或长串模型摘要；单独选择时复用同一编辑器。
- 从任务顶部点击时定位当前执行职责的 Tab；从设置进入默认规划 Tab。切换 Tab 保留每项草稿，保存一次提交完整快照，仅修改已编辑字段。
- 角色/Tab 关系通过扩展 `execution-spec-view.ts` 的只读展示字段返回；v2 不开放角色覆盖，与正在开发的 MiMo 工作流约束一致。不会为了本次 UI 重新改变流程。

**三项选择：**

- 工具列表只使用简短显示名，不重复 `Codex（codex）`。已安装工具优先，未安装工具灰显并仅标注 `未安装`；安装修复仍复用既有配置/指南路径，不新增管理大表。
- 模型是可搜索 combobox，点击展开完整目录；显示一个名称、一个选中标记。需要搜索时直接输入；不使用浏览器 datalist 和自定义 listbox 叠在一起。
- 模型 listbox 最大约 240px、独立滚动、支持上下方向键/Enter/Esc/Tab、读屏选中状态；禁用浏览器 autofill 干扰，不用固定 120ms blur 延时决定能否选中。
- 思考强度独立 select，以 `low / medium / high / xhigh` 等原生实际值显示一次，不再显示“高 · high”等重复文案。只列当前模型确实支持的值。
- 原生不支持独立强度时隐藏该控件；仅有一个确定档位时显示该确定值；目录加载失败/元数据缺失不能伪装成“不支持”，显示一条 `暂未读到思考强度` 和 `重试`，不能静默清掉历史强度后保存。
- 支持原生默认时，在强度下拉提供 `默认`，表达明确的配置选择；顶部不会输出“工具默认/实际未报告”。切换模型时优先保留仍合法的强度，否则选新模型的原生默认；没有已知默认就保持待选，阻止提交不完整的新选择。
- 只在加载失败、登录失效、授权失败等情况下出现一条短错误和对应动作；正常状态不显示“访问状态、重新验证、元数据、r0、来源、实际观察”。目录刷新是模型下拉中的一个小刷新按钮，校验在保存/应用时统一执行。
- 原始模型 ID、实际 CLI、原生命名配置从这套普通表单移除，既有存储值在载入/提交时完整保留；配置诊断继续用已有运维入口和日志，不新做高级配置页面。未知但已保存的模型保留一次，标记 `当前配置`，不混入搜索无关结果。
- 创建任务、任务配置、默认设置和已有问题修复选择共用编辑器与格式化函数，避免修好一个入口、另一个入口仍重复显示。

**保存与当前执行：**

| 情况 | 页脚行为 | 生效与保护 |
| --- | --- | --- |
| 全局默认 | 取消、保存 | 只影响之后创建的任务；不改已有任务 |
| 新建任务 | 嵌入原创建流程，不再额外套弹窗 | 使用同一份选项与草稿，不另造默认值 |
| 暂停/未运行任务 | 取消、保存 | 更新该任务配置，保持暂停或等待状态；用户从原入口继续 |
| 运行任务，仅改未来职责 | 取消、保存 | 当前 run 不变，后续相应职责使用新配置 |
| 运行任务，改当前职责 | 取消、保存供后续使用、切换并继续 | 后者执行校验→停止当前执行→保存→原阶段续行；按钮文字直接交代操作 |
| 任务终态 | 不提供写操作 | 不能从顶部误开可编辑表单 |

成功后关闭弹窗，短暂显示 `已保存` 或 `已切换`；不留下大块成功说明。保存失败保留草稿，聚焦第一处真实错误。409 不自动覆盖服务端配置，显示 `配置已更新，请重新载入`，提供保留草稿的重载合并，不自动重放写请求。

### 4.7 AGY 账号窗口

```text
┌─────────────────────────────────────────────────┐
│ AGY 账号                                    [×] │
│ 自动切换                              [ 开关 ]  │
│                              [+ 添加管理账号]   │
│                                                 │
│ 工作账号                  当前账号        [⋯]  │
│ 备用账号                  可用      [切换] [⋯] │
│ 备用账号二                需登录    [登录] [⋯] │
└─────────────────────────────────────────────────┘
```

- 账号列表只展示用户识别账号所需的别名/账号标识、简短状态、切换或登录动作。别名已足够识别时不另占一整列展示内部 ID。
- 更多菜单仅容纳已有改名、停用/启用、移除管理等必要账号动作，不添加模型策略、诊断与历史入口。当前账号不可被直接移除；按钮出现时才解释具体限制。
- 没有账号只显示 `还没有管理账号` 和添加按钮，不写工作流、额度探测、凭据域说明。
- 开关标签固定 `自动切换`；开启后服务自动处理受管 AGY 任务的可信额度耗尽/身份失效，不需要用户再点自动选择。关闭不退出当前账号、不删除账号、不停止正常工作流，只停止后续自动切换和后台候选调度。
- 初次开启无账号时进入添加视图；开关在尚未真正启用前保持关闭。取消登录不把开关假设为已开启；添加完成且能力满足后，继续最初开启动作。
- `添加管理账号` 在自动切换关闭时照常可用，不要求填写模型或先点启动管理。进入添加视图可用 `登录新账号`、`添加当前登录账号` 两个明确动作，以及可选账号名称；不把账号密码/token 做成应用表单。
- 有能力问题时，一行准确错误替代整页灰按钮，例如 `未找到 AGY CLI` 加 `重新检测`。自动切换可以受能力限制，但不能把缺额度能力等同于完全不允许登录/添加；分别判断各动作需要的能力。
- 正常操作只显示 `正在登录…`、`正在切换…`、`需重新登录` 等结果或进度，最多一条当前异常。原始错误码、AuthHost、DPAPI、epoch、恢复协议留在已有脱敏日志中。
- 账号行 `切换` 是用户主动指定某个账号，和开启自动切换职责不同；不再提供另一个“自动选择并切换”主按钮。
- 切换若确实会暂停其他正在运行的受管 AGY 任务，执行前只显示一个简短确认：`切换账号会短暂暂停 N 个任务`，按钮为 `取消 / 切换`。没有受影响任务不增加确认。
- 日间报告、刷新验证间隔、夜间池、时区等退出普通 UI。已有定时维护保留后台规则与旧值；新安装沿用当前后台默认值，本次不修改维护频率或增加全时区产品能力。时间显示使用浏览器本地时间。
- 账号列表不展示跨模型额度大表、候选排除说明、历史额度、原始能力表和任务恢复配置。当前运行模型的额度统一从顶部按钮查看。

## 5. 模型目录、强度与生效链路的修复

### 5.1 修复“手工单条目录被当成正常目录”

执行路线固定为：**补全目录质量状态 → 从原生工具发现完整目录 → 正确保留最后成功目录 → 形成模型/强度选择 → 校验并派发**。

1. 在 `ModelCatalog` 增加向后兼容的 `discoveryStatus: complete | partial | missing` 和 `parserRevision` 可选字段；旧数据无字段时按来源、CLI 信息和解析版本保守推导。只有手工候选的目录为 missing；原生已完成发现即便只有一个真实模型也可 complete，不能凭数量认定失败。
2. `ensureManualCandidate()` 只补历史候选，不赋予原生目录成功含义，不延长真实目录发现时间/TTL，不替换已有原生完整元数据。全手工目录不能以 fresh+complete 让前端跳过发现。
3. 编辑器首次打开遇 missing/partial、过期或 parserRevision 不匹配时，调已有 refresh 接口并等待 operation 完成；同 scope 去重，失败后保留可读旧项和一个重试入口，不无限循环刷新。GET 保持只读。partial 仅用于发现尚未完整完成或数据被截断的情况，不能把它升级为 complete。
4. Codex 继续用现有 app-server `model/list` 发现路径，保留初始化握手和游标分页；核对真实版本返回的名称、隐藏字段、`supportedReasoningEfforts`、默认强度。不要重造一条猜测的 CLI 命令，也不能从本次助手的可用模型列表当作 DevFlow 目录。
5. 本地 Codex cache 只在既有受支持作用域下作为后备；标明缓存时间，不能从其他 profile/provider 取同名目录。失败时保留最后一次成功原生目录，错误状态和旧数据分别表达。
6. AGY 继续使用已核实的原生目录命令；正确解析多模型、多变体及失败输出。安装/命令/版本不匹配时返回短错误，不能用当前 profile 的单模型造出“正常目录”。
7. 模型目录与授权缓存分开：出现在目录不等于当前账号已授权；验证一个模型也不代表目录完整。原生发现覆盖同 nativeId 的手工项时保留完整强度和来源，不被旧 unknown 覆盖。
8. 同步配置目录请求作用域与验证/派发作用域：adapter、实际可执行路径、原生 profile、provider/account 身份边界一致。使用后端返回的非敏感 `scope_id`；前端不读取凭据、不拼宿主路径。
9. 已知其他工具及同日新增 `mimo-code` 继续走注册表；本次不硬编码只有 Codex/AGY 两个选项，也不承诺未安装的工具已经实测。

### 5.2 模型与强度分离，底层调用保持精确

- 新增展示层 `ModelChoice`（不是持久化的运行模型）：`choiceId`、`label`、`entryIds`、`effortValues`、`defaultEffort`、`variantByEffort`。由可信 `familyId`、`variants` 和 provider 构建，不按 `-high` 后缀随意截字符串归组。
- Codex：选择模型 A 后，强度下拉来自 A 的原生 metadata；选择模型 B 后按 B 重算，不将 A 的强度带入不支持的 B。
- AGY：已确认同家族 medium/high 变体展示一个模型名称；强度选择 medium 时将 profile.modelId 设为实际 medium 变体，reasoning 为 medium；派发使用现有 resolver 生成正确 token。已确认只有 high 的家族只展示 high，不伪造 medium。
- 家族映射必须基于该 CLI 版本的真实目录/已核实合同。当前源码 `AGY_VARIANTS` 的注释不是本机 capability 的证据；实施时要用真实输出复核。
- 未知模型完整 ID 只显示一次，不从名字推断强度；明确不支持和暂时未发现是不同状态。
- 持久化仍使用原 `ToolProfile` 的 `adapterId/modelId/reasoning`，不把前端 family choiceId 直接当可执行模型 ID 保存。保持旧 Run、native ID、fingerprint、冻结调用可恢复。

### 5.3 请求、草稿与校验

- 三控件编辑共享唯一 selection key：工具、scope、模型、强度及相关原生配置；任何一项变化清除旧验证状态。
- 搜索文字不改变选中 profile；只有选中结果才提交草稿更新。输入法组合输入不能触发发送/选中。
- 快速切工具、Tab、任务时 AbortController 与请求 generation 双重校验；迟到的目录/验证结果不能覆盖新选择。关闭弹窗取消非必要读取。
- 普通浏览模型和 Tab 不发送模型推理探针。保存/应用时，复用 `ModelAccessService` 对最终唯一配置去重校验；可信缓存仍按账户、scope、模型、能力修订隔离。
- 保存只对本次改动涉及的有效 profile 做严格校验，不因为一个完全未改的历史工具暂不可用就挡住其他 Tab 的修改；服务端在实际派发前仍校验本轮精确配置。前后端必须采用相同的差异/继承展开规则，不能仅由前端少验。
- 强度从 high 改到 xhigh 必须重新判断支持能力与调用参数，不能沿用上一状态显示已验证；是否复用模型授权成功缓存由已有服务按完整身份判定。
- 不支持/未知组合不能在保存时被删除强度、回落模型或改成默认来“让它通过”。保持草稿并给一条操作级错误。

### 5.4 正常保存与运行中切换

- 沿用 spec revision、workflow version、expected run ID、request ID 幂等保护；不创建新配置版本体系。
- `保存供后续使用` 仅写 task spec，旧 run/frozen invocation 不变；顶部直至新 run 启动仍显示旧模型。
- 给既有 model-switch 请求增加可选 `resume_after_switch`，旧客户端省略时继续保持“暂停并保存”的旧行为；新 UI 的 `切换并继续` 使用 true。
- 新行为顺序：校验最终配置 → 用 expected run/version 锁定需停止的执行 → 确认进程树退出且持久化当前阶段/恢复上下文 → 写新 spec → 由原恢复入口继续同一步。
- 停止失败/超时不得启动新模型；版本或 run 已变化不得误停新 run；保存失败保持明确暂停与可重试状态；保存成功但续行失败保留已保存配置和原恢复点，显示 `已保存，继续执行失败`，复用任务原有继续入口。
- 幂等操作记录复用既有切换/变更收据，在“停止、已保存、已续行”阶段可恢复；重试不能重复开新 run 或重复保存 revision。
- 同工具、同模型、同强度且原会话可恢复时继续现有会话；用户明确改变工具/模型/强度，按现有兼容边界建立新会话并保留工作区与任务进度；自动账号恢复维持原 frozen invocation，不把换号变成换模型。

## 6. 额度与账号服务的最小必要调整

### 6.1 额度归属

现有 `CurrentRuntime` 对 Codex 先匹配 model，再回退名为 codex 的 bucket；其他工具直接使用全部 buckets。这不足以满足“只显示当前运行模型”。

在既有 `RunObservation.quota` / `QuotaBucket` 上增量补充可选的归属信息：不含凭据的账号 scope 标识、账号 epoch、模型 ID 集合、额度池 ID、作用域类别 `model / pool / account / unknown`。无需新建额度管理系统或持久化历史表。

统一选择顺序：

1. 先匹配当前 workflow/run 与该 run 的工具、账号 scope/epoch；不匹配直接丢弃，即使 observed_at 更新也不能显示。
2. 选择明确匹配当前原生模型 ID 的 bucket。
3. 没有精确 bucket 时，只允许选择已确认包含该模型的 pool；模型别名/AGY 变体必须用已核实映射。
4. 没有模型/pool bucket 时，只有提供方明确表示当前账号全模型共享，才选择 account bucket。
5. 无可信归属返回 unavailable，不用“第一个 bucket”、其他工具、其他账号、历史 run 或全局配置替代。
6. 从选定作用域读取 300/10080 分钟窗口，百分比有限值限定 0～100；null/缺失不是 0。过期判断继续采用现有 120 秒或源明确给出的有效期，断连和已退出执行强制标记不可作为当前值。
7. 模型/账号切换立即清掉旧浮层数据；旧请求即使稍后返回也不能重新填上。额度读取失败不阻断模型运行。

`codex-account-quota.ts` 的缓存键目前主要依赖 executable/profile/home，需要纳入已有可确认的账号身份/版本失效信号；不能在同一路径换账号后复用上一账号额度。与模型授权隔离复用同一身份来源，不读取或暴露 token。AGY 从既有 quota parser、账号快照和运行桥接获得当前模型适用范围。

关于“AGY 不同模型是否有不同额度”：**本次没有获得真实服务端的模型额度映射，不能宣称所有模型各自独立，也不能宣称永远共享。** 无论供应方实际采用哪种方式，账号窗口都不要求用户填写模型；后台从运行模型与可信额度返回中解析。当前源码部分路径硬编码 global，需要随真实协议一起核对，不能为了删模型输入而盲目扩大这个假设。

### 6.2 一个开关，后台生命周期自行处理

复用现有账号 coordinator、AuthHost、operation receipt 和 realm，不引入第二套账号服务。

- 产品开关的意图由既有 `settings.workflow_auto_switch` 表达；`realm.desired_enabled/service_state` 仍是内部生命周期。UI 显示服务端汇总后的 `automation.enabled/status`，不把 running 直接等同于用户已开启。
- 新增 `PUT /api/agy-accounts/automation`，输入为 `request_id`、`enabled`、`expected_settings_revision`、`expected_control_generation`。服务端在同一 coordinator 控制流程中执行策略与服务状态变更，返回操作收据。不能由前端分别 PUT 设置、POST start 后假设两步都成功。
- 开启：校验自动切换所需能力、获取原有域锁、启动现有管理循环、登记成功意图；失败回滚到原意图并返回具体原因。重复点击复用同一 request ID，不能重复启动。
- 关闭：立即禁止新自动切换；已进入凭据写入的操作安全完成或回滚后再释放资源；不杀现有正常模型任务、不登出。UI 期间显示 `正在关闭…`，只在服务端完成后显示关闭。
- 全局开关是总开关：关闭时旧任务中 `auto_switch=true` 不能绕过；开启时保留旧任务显式关闭的约束，不抹掉历史策略。新任务默认继承全局。普通 UI 移除 `AgyWorkflowPolicy` 面板，存量策略保留，出现明确排除时只在对应失败操作中说明。
- 浏览账号窗口和普通刷新只 GET，不能暗中 start 管理、改开关或自动换号。

### 6.3 自动切换关闭时仍可添加/手动切换

这项需要后端支持，不能只删掉前端 disabled。

1. 既有 enroll/switch 操作入口增加内部“单次管理操作租约”：自动切换关闭时，按实际能力临时获取原有 AuthHost 域锁、完成手工操作，再释放租约；不修改用户开关意图，不运行自动候选循环。
2. 持久自动管理和单次操作共用同一个 coordinator 与 realm fencing。租约关联 operation ID，进程中断后用现有操作记录恢复/回滚；有未决凭据操作不得抢占、并行写或提前释放锁。
3. `添加管理账号` 的可用条件是身份读取、登录/捕获、凭据安全存储等该动作所需能力，不依赖自动切换已开启；缺 quota 能力不能直接禁止保存一个已验证身份的账号，但该账号不得进入自动候选。
4. 添加流程默认不要求 `standalone_model_id`，保存账号身份和可获得的可信额度；缺失项保留 unknown。手动指定账号、当前无受管任务时只验证身份与安全切换，不以填写模型或双额度为前提。
5. 手动切换影响受管任务时，由后台收集受影响 run 的冻结模型需求，沿原暂停/回读/恢复协议处理。模型访问不能确认时不把受影响任务冒险恢复；给出具体任务错误，保留原恢复上下文。
6. 开启自动切换后，额度失败事件携带的 workflow/run/frozen model 是唯一需求来源；多任务共享身份时使用全部受影响模型需求，不能使用当前浏览器选中的任务替代。
7. `standalone_model_id` 旧字段保留读取兼容与回滚，但新 UI 不提交、不依赖；新自动路径不得被旧值覆盖。
8. 自动登录或凭据写入使用原生正规路径；失败保留/恢复原身份，用户取消不留半个账号。添加新账号后恢复进入添加前的活动账号，除非这是首次没有活动账号或用户随后明确点击切换。
9. 当前账号高亮只依据成功后的身份回读，不能看到 HTTP 202 就标记切换成功。刷新页面能恢复正在进行的操作，不重复弹原生登录。

### 6.4 能力发现与失败表达

- `account-service-bootstrap.ts` 目前优先配置路径和固定 Windows 安装位置；实施时核对实际安装、PATH、工具目录发现和 AuthHost 使用的路径是否一致，区分“已安装但没发现”和“真实缺能力”。
- 复用工具发现结果和明确 CLI 配置，验证指纹/版本后供账号服务使用；不直接写死某台机器的绝对安装路径。
- 将当前总 `supported` 补充为动作级可用性：`addAccount`、`captureCurrent`、`manualSwitch`、`automaticSwitch`，每项包含 enabled 与一个面向用户的简短 reason；旧字段留给旧消费者。
- 自动切换仍要求真实身份、有效额度/重置时间、适用模型范围及安全切换能力。不能把 registry 的未验证项改成 true、伪造 quota 或删除保护来让 switch 变亮。
- 普通 429、网络超时、输出文本提到 quota 都不是可靠换号事件；沿用既有结构化失败事实。
- 没有可用账号时使用已有等待/暂停恢复机制；UI 在实际发生时显示 `暂无可用账号`，不常驻一页选择算法说明。
- 真实 CLI 不支持所需能力时，该能力仍属未完成/外部阻塞，必须如实交付。可用的手动能力照常验收，不能反向宣称自动功能完成。

## 9. 兼容、迁移与回滚

### 9.1 数据与配置

1. 本次不清库、不删除 Run、模型绑定、会话、账号、凭据、工作树或任务计划；不因删历史 UI 去删历史事实。

### 9.2 上线与回滚步骤

1. 记录本次修改白名单、构建版本及当前服务加载入口；必要的持久化备份采用已有服务一致性方案，不复制正在写入的 SQLite 主文件冒充完整备份，不将凭据备份放进仓库或验收目录。
