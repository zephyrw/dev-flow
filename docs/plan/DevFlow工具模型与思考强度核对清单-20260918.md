# DevFlow 工具、模型与思考强度核对清单

核对日期：2026-09-18。配套主计划：[模型配置与运行中切换详细实施计划](./DevFlow模型配置与运行中切换详细实施计划-20260918.md)。本清单是开发参考和解析器测试输入，不是永久产品目录，也不是八个工具都已完成账号授权的证明。

## 1. 先明确目录的含义

模型选择器必须同时展示以下三个彼此独立的信息：

1. 工具能力：是否安装、版本、能否传模型和思考参数。
2. 模型目录：原生客户端当前返回、原生缓存、原生配置、官方候选或用户手工输入。
3. 当前账号访问：未验证、验证中、已验证或具体失败原因。

“帮助里有 --model”“目录列出了模型”“账号已登录”均不能单独推出“这个模型已授权”。首次使用时按主计划第 8 节验证；验证成功以后复用。本文所列版本只是本次核对版本，实现根据实际检测版本和能力运行，不要求用户必须安装完全相同的版本。

本文用原生模型 ID，展示名另列。不要把 GPT-6、Gemini 3.7、Grok 4.6 等自然语言名称直接拼成调用 ID。不同工具代理同一厂商模型时，ID、档位和账号访问范围可以不同。

这里的 max/ultra 来自本机缓存，发布时必须与原生 model/list 和 CLI 实际能力取交集。通用配置说明页中的枚举可能落后于具体客户端，不能用一个旧的 low/medium/high/xhigh 枚举永久裁掉新模型能力。[模型文档](https://learn.chatgpt.com/docs/models)、[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

### 2.2 目录读取合同

使用现有 nativeLaunch 启动短命 `codex app-server`，标准输入输出 JSON-RPC：先 initialize，收到响应后发送 initialized，再分页 model/list。请求参数为 `includeHidden:false`、`limit:20`，有 nextCursor 则追加 cursor。只抽取 data 中的 id/model/displayName/hidden/defaultReasoningEffort/supportedReasoningEfforts。收到完整结果后关闭 stdin，正常退出优先，超时只结束本次子进程。[app-server 文档](https://learn.chatgpt.com/docs/app-server)。

实现注意：

- initialize 的 clientInfo 使用固定 name `devflow-model-catalog`、title `DevFlow model catalog` 和当前平台版本，不能带业务任务信息。
- 通知与响应按 JSON-RPC id 匹配；stderr 不是 JSON 消息流；收到其他通知不能错配成 model/list。
- model/list 的 `model` 是调用模型 token，`id` 用于目录识别。两者不同时不能自行选择 displayName 当 modelId。
- supportedReasoningEfforts 每项取 reasoningEffort；description 只供说明。保留未来未知原生枚举，不做盲目过滤，也不能自行增加枚举。
- model/list 不可用时允许读取本机原生模型缓存，source=native-cache，保留缓存时间并显示来源；缓存缺失时用官方候选，均不标已授权。
- 本机缓存测试夹具只保留上述白名单字段，不复制整个用户目录。

### 2.3 参数与会话

模型参数：`["--model", "gpt-6-astra"]`。effort 参数：`["-c", "model_reasoning_effort=\"xhigh\""]`。这是 spawn args 的单个值，不是拼接给 shell 的命令。

首次 exec 和兼容的 exec resume 均传入同一组冻结选择。effort 从 high 改成 xhigh 后按主计划新开会话；不要拿只改变展示标签的方式假装切换。模型/effort 未变化的普通暂停恢复才允许续最近兼容会话。

### 3.2 编码规则

1. 读取 `agy models` 的 stdout 模型条目，保留原生 ID。清除 ANSI 和展示边框，stderr 只做脱敏诊断。
2. 已明确固定强度的 slug，Profile 同时保存 exact ID 和对应 explicit effort；调用只传 `--model exact-id`，不重复传相冲突的 --effort。
3. 用户在 Gemini 3.7 家族由 high 切 medium，必须找到目录中的 gemini-3.7-flash-medium。找不到则禁用 medium，不拼接后试运行。
4. 没有强度 slug、但元数据明确支持独立 --effort 的模型，才传该参数。无可靠逐模型元数据则只允许原生默认。
5. 原生目录只给显示名而不给可调用 ID 时，仅放在目录的帮助说明中，不产出可选 ModelEntry，不把显示名当 CLI 参数。精确 ID 确认后再生成 availability=candidate/listed 的条目。

本机存在 `--mode plan`、`--sandbox`、`--disable-slash-commands`、`--print-timeout`；首次访问探测只在空目录使用这些已支持能力，不能使用 `--dangerously-skip-permissions`。目录和探测过程可能启动客户端自己需要的辅助进程，清理只限本次拥有的子进程，不停止用户已有 agy 会话。

### 5.5 家族分组与首次验证键

不要为分组写一条通用“删除所有 -high/-thinking/-fast”正则。实现受版本控制的映射规则，每条至少包含：精确家族标识、允许后缀集合、实际 nativeId、effort、Thinking/Fast 等不变维度、映射证据来源。

只在目录中的具体组合存在时建立变体映射。以 Grok4.6 为例，当前常规家族的 low/medium/high/xhigh 对应四个已列出的 cursor-grok-4.6-*，UI 可以在相同家族切强度；Fast 家族单独保留。新未知 ID 默认独立显示且 effort=unknown，不猜测归属。

本清单已经核实为同一底层模型的纯 effort 变体，在映射表内声明共享 accessModelKey。例如常规 cursor-grok-4.6-{low,medium,high,xhigh} 都用 `cursor-grok-4.6:standard`，首次成功后只换强度不再次调用授权探测。Fast/Thinking 等非 effort 维度先保留在访问范围内，除非原生能力明确表明权限范围相同。

对于未来未知 ID，没有可靠 family 信息时先独立显示和按 exact ID 验证，不能靠猜测删除后缀合并。后续元数据明确它是现有模型的纯 effort 变体后，归入已有访问键即可，不要求重新登录。已验证具体 ID 永不因重新打开选择器而重复验证。

## 7. Kimi Code

### 7.1 识别正确产品

本机是 TypeScript 包 `@moonshot-ai/kimi-code` 的 0.37.2，不是旧 Python kimi-cli。两个产品名字相似、配置路径和参数不同，不能混用旧文档，也不能添加本机不存在的 `--thinking`、`--effort` 参数。

读取 `KIMI_CODE_HOME` 指向的目录；未设置时按此产品的原生默认配置目录读取 `.kimi-code/config.toml`。只取 models 中用于展示和参数能力的字段，provider 配置只返回名称/类型/端点指纹等非敏感摘要。不要把 provider 的 API key 返回浏览器。[配置文件](https://moonshotai.github.io/kimi-code/en/configuration/config-files)、[环境变量](https://moonshotai.github.io/kimi-code/en/configuration/env-vars.html)。

### 7.2 本机配置的具体模型

| CLI alias（保存和传给 --model） | 底层 model/展示名 | effort |
|---|---|---|
| kimi-code/kimi-for-coding | K2.7 Coding | 配置为 always_thinking，此次没有 support_efforts，不开放任意档位 |
| kimi-code/kimi-for-coding-highspeed | K2.7 Coding Highspeed | 同上；Highspeed 不是 high effort |
| kimi-code/k3 | k3，provider=managed:kimi-code | low、high、max；默认 high |
| kimi-code/k3-256k | k3-256k，provider=managed:kimi-code | low、high、max；默认 high |

`support_efforts` 是允许集合，`default_effort` 是默认值，二者不能混淆。没有 support_efforts 并不意味着支持所有档位。

### 7.3 每次调用传参

在本机版本的 kimi provider 通道，`KIMI_MODEL_THINKING_EFFORT` 是进程环境覆盖，可以独立于 KIMI_MODEL_NAME 使用。DevFlow 先验证 alias.support_efforts，然后给本次 spawn 的 env 增加该值，进程退出即结束，不调用系统 setx、不修改用户 TOML、不写全局环境。[环境变量说明](https://moonshotai.github.io/kimi-code/en/configuration/env-vars.html)。

示例：profile modelId=`kimi-code/k3`、effort=`max`，args 保留 `--model kimi-code/k3`，本次 env 为 `KIMI_MODEL_THINKING_EFFORT=max`。不能把 modelId 改成不存在的 kimi-code/k3-max。

如果用户配置的 alias 经过其他 provider，且本版本没有经过验证的单次 effort 通道，显示“当前客户端暂不能按次覆盖此 provider 的思考强度”，只允许原生默认。不得临时改全局配置再恢复，不复制其密钥到另一 provider。[provider 说明](https://moonshotai.github.io/kimi-code/en/configuration/providers)。

已有本地 Kimi server 时可使用它的 `/api/v1/models` 读取模型元数据；本期不为目录新启常驻 server。禁止调用会返回 key 的 provider 详情接口作为前端数据来源。[server API](https://moonshotai.github.io/kimi-code/en/reference/server-api.html)。

### 8.2 参数和现有缺陷

本机命令是 `qodercli`，帮助支持 `--list-models`、`--model`、`--reasoning-effort`、`--thinking`。thinking 接受 auto/adaptive/enabled/disabled；它与 reasoning-effort 分开，本期不另加 Thinking 开关编辑器。

本机 permission-mode 的集合为 default、accept_edits、bypass_permissions、dont_ask、auto，没有 plan。现有适配器不能继续给 Qoder 传 `--permission-mode plan`；普通只读用途使用当前有效权限模式与只读工具白名单，访问探测则禁用工具并使用空 MCP 配置。不存在的参数导致启动失败应报 CLI_PARAMETER_UNSUPPORTED，不报账号未授权。

若原生 list 要求登录，UI 给出 `qodercli login` 的提示和重新验证入口；平台不代替用户执行 login。文档候选先展示，精确 ID 未确认前不得发布为活动配置。

## 9. OpenCode

### 9.1 为什么不提供一个固定模型全集

OpenCode 的模型由用户配置的 provider 决定。相同模型名称可来自不同厂商、代理或本地端点，能力和权限均可能不同。选择器完整读取本机 `opencode models --verbose` 和其可读模型元数据，模型键保留 `provider/model`。本次受宿主日志目录权限限制，未取得可靠本机目录，因此本清单不编造“本机全部可用模型”。[CLI](https://opencode.ai/docs/cli)、[模型配置](https://opencode.ai/v2/docs/models)、[provider](https://opencode.ai/v2/docs/providers)。

| 原生条目类型 | 模型字段 | effort 下拉来源 |
|---|---|---|
| 配置的 OpenAI/provider 模型 | 原生返回的 provider/model | 此 provider 的 variants；不能复制 Codex 的集合 |
| 配置的 Anthropic/provider 模型 | 同上 | 此 provider 的 variants；不能复制 Claude Code 的集合 |
| Gemini、DeepSeek、其他远端模型 | 同上 | 原生返回集合 |
| 本地/provider 自定义模型 | 同上 | 缺 variants 时原生默认，不能猜 |

### 9.2 版本分支

- 本机 1.18.30：`run --model provider/model --variant value`，只有目录存在的 variant 才允许。`--thinking` 只是展示思考内容，不能替代 --variant。
- v2：只有实际版本/帮助确认该语法时使用 `provider/model#variant`。不能同时传 #variant 和 --variant。[v2 模型语法](https://opencode.ai/v2/docs/models)。
- `run --pure` 可用于禁用外部插件，但不等于禁用所有工具权限。访问探测必须使用独立的禁止工具/权限配置；不能选择 auto 批准来绕过。
- 模型目录离线失败时保留旧缓存并显示错误，不删除正在使用的 provider/model。

## 10. 规范化示例与不可猜测规则

### 10.1 四种参数运输形式

以下是核心解析器的输入输出期望，省略业务提示词和与模型无关的现有参数。

| 工具/profile 输入 | 解析结果 | 必须拒绝的错误做法 |
|---|---|---|
| codex / gpt-6-astra / xhigh | model gpt-6-astra；config model_reasoning_effort="xhigh" | 给 --model 传自然语言 GPT-6 xhigh |
| agy / gemini-3.7-flash-high / high | model gemini-3.7-flash-high；无额外 effort flag | 同时附 --effort medium |
| claude-code / claude-opus-5 / max | model claude-opus-5；--effort max | 保存 opus 别名却展示固定 Opus5 |
| cursor-agent / cursor-grok-4.6-high / high | model cursor-grok-4.6-high；无通用 effort flag | 传 grok-4.6 再附不存在的 --effort |
| grok-build / grok-4.6 / xhigh | model grok-4.6；--reasoning-effort xhigh | 把 Grok4.5 的 xhigh 降档当成功 |
| kimi-code / kimi-code/k3 / max | alias 不变；本次 env effort=max | 修改用户 config.toml 或添加假的 --effort |
| qoder / 原生已列出 ID / 支持值 | exact nativeId；--reasoning-effort 支持值 | 将官方显示名自行 kebab-case 当 ID |
| opencode 1.x / 已配置 provider/model / high | model 不变；--variant high | 没有 variants 元数据也显示全档位 |

### 10.2 capability status 与 UI

| 状态 | effort 控件 | 可以保存什么 |
|---|---|---|
| supported，values 非空 | 只显示 values；默认另附 native-default 说明 | explicit 的已支持值，或明确原生默认 |
| 已存在 exact variant 且 fixedValue 已知 | 显示固定值；同家族下拉只映射已存在组合 | 当前 variant 与匹配 effort |
| unsupported | 显示“不适用” | not-applicable，不能提交 explicit |
| unknown | 显示“当前客户端未提供档位信息” | native-default；有新元数据后可编辑 |

模型 ID 和 effort 冲突直接返回 422 EFFORT_UNSUPPORTED，并说明实际可选集合。不能自动选最接近的档位。凡“未列出”均保留 unknown 语义，不轻率改为 unsupported。

### 10.3 模型目录优先级

同一 scope 同一 ID：本次原生返回优先，其次最近原生缓存，再次配置元数据，最后官方种子。能力字段逐项带来源，不能拿文档种子的全部字段覆盖原生已报告的组织限制。已知组织禁止的档位必须从可选集合去掉。

新模型出现在原生目录但内置表不认识时：照常展示 exact ID；原生提供 effort 就使用，没有则 unknown；允许按原生默认首次验证。不能等待平台发版才能看到每个新模型。

官方种子至少保存 `sourceUrl`、`checkedAt`、`cliVersionConstraint`、`nativeIdConfirmed`、`effortEvidence`。它们不含账号信息，不含 verified=true。没有确认 nativeId 的展示名只在说明/候选区域出现，不成为可点击的可调用模型。

## 11. 目录解析和测试落点

每个工具至少提供以下四类夹具，放入 `tests/fixtures/model-catalog/<adapter>/`，文件名称固定使用 `help.txt`、`models-success.txt/json`、`models-failure.txt/json`、`expected.json`。实际没有 list 能力的 Claude 使用文档种子 JSON 与配置模型 JSON，不能生成假的 CLI 响应。

1. 当前支持版本的帮助和目录成功输出，已脱敏。
2. 认证失败、权限/日志目录失败、网络失败各自的最小输出。
3. 缺字段、未知新模型、隐藏模型、ANSI/分页/超长输出等结构变化。
4. 规范化输出断言，包括 source、exact nativeId、effort 集合、固定变体、default、隐藏标记，不能只有快照文件没有语义断言。

独立参数测试检查真实 spawn 的 executable/args/env，而非只比较 UI 文本：

- 正常 dispatch、pause/resume、review/retry、repair 都经过同一选择解析器。
- Windows 空字符串、含空格路径、npm shim 解析和 effort 引号保持正确。
- native-default 未解析时不发虚构参数，并明确 observed unknown。
- 目录 unknown 模型不阻止列表渲染，但不增加未知 effort。
- 不合法组合在启动模型前拒绝，调用计数为 0。
- 授权探测成功后保存准确访问键；目录缓存成功不产生任何授权记录。

真实调用验收只使用测试人员已授权的模型，限定最小调用。没有相应账号的工具必须分别报告“参数/解析测试通过，真实账号调用未验证”，不得写成八工具全部端到端通过。该限制是如实记录验证范围，不允许省略适配器实现和可重复的测试。
