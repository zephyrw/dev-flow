# DevFlow 接入 CodeBuddy CLI、模型选择与积分额度开发计划

## 一、背景与现状

DevFlow 通过原生 AI 编程工具执行规划、开发、复核和整改。此次需求是增加腾讯系工具选择、选择该工具支持的模型，并在工作流中查看额度。最初考虑 WorkBuddy；结合用户提出的编程场景，本计划建议接入 **CodeBuddy CLI（官方名称 CodeBuddy Code）**。

截至 2026-11-10，已确认以下现状：

- DevFlow 已有适配器注册、工具探测、模型目录、访问验证、角色配置和运行展示机制，但没有 CodeBuddy 或 WorkBuddy 适配器。当前普通工具选择列表开放 Codex、Antigravity CLI、Claude Code 和 OpenCode。
- 模型目录已有原生发现、缓存、手动刷新和账号作用域；运行启动时会冻结本轮选择。新增工具应接入这些机制。
- 工作流额度接口目前读取 Codex 和 Antigravity；前端主要展示周额度与 5 小时额度，现有数据结构不能完整表达积分余额和资源包到期时间。
- 本机已安装 WorkBuddy 5.9.3，安装包内有版本为 2.165.0 的 CLI。此项仅为安装文件核查，不代表内置 CLI 可以独立复用桌面登录态。当前 PATH 和常见 npm 安装目录未检测到独立 CodeBuddy CLI。
- 本轮仅调研和编写计划，尚未安装 CodeBuddy CLI、调用真实模型、读取真实积分或修改产品代码。

## 二、目标与选择理由

### 2.1 完成后的使用效果

用户可以在全局默认模型、新建工作流和任务模型设置中选择 CodeBuddy CLI，再选择当前账号、服务区域和项目配置下可用的编程模型。配置保存后，工作流实际通过该 CLI 执行，能够显示运行情况、暂停并续接原会话。

工作流规划、执行角色旁的额度入口能够展示所属账号的真实剩余积分、更新时间及可取得的资源包明细。未登录、读取失败、数据过期和外部模型使用独立额度时，显示对应状态。

CodeBuddy 的接入必须保持已有工具、角色继承、模型切换和工作流调度行为。能够出现在下拉框中，不等于已完成接入；真实模型调用和真实积分读取均属于交付目标。

### 2.2 为什么优先采用 CodeBuddy CLI

| 比较项           | CodeBuddy CLI                                                                         | WorkBuddy                                                            |
| ---------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 与本次需求的关系 | 官方定位为编程工具，包含文件编辑、命令执行、Git 与测试能力，直接对应 DevFlow 开发任务 | 面向桌面任务，也包含应用开发功能；本次不需要其办公界面和桌面操作入口 |
| 自动化接入依据   | 有公开的非交互 CLI、流式输出、指定模型、会话恢复和 SDK 文档                           | 已找到桌面内置 CLI，但独立启动、宿主认证与升级兼容尚未验证           |
| 本次实现选择     | 作为独立原生工具接入                                                                  | 保留现有安装和配置，不作为本次运行依赖                               |

因此，推荐 CodeBuddy CLI 的依据是**更适合被 DevFlow 调度，且接口依据更明确**，并不意味着同一模型在 CodeBuddy 中一定比在 WorkBuddy 中更聪明。CodeBuddy 的编程定位见[官方概述](https://www.codebuddy.cn/docs/cli/overview)，自动化接口见[CLI 参考](https://www.codebuddy.cn/docs/cli/cli-reference)。

官方国内个人版定价页说明，WorkBuddy 与 CodeBuddy 的同一账号共享积分；但共享积分不代表登录态、CLI 访问权益、模型清单和临时免费活动完全相同。开发时应核对实际账号和区域，不能直接复制 WorkBuddy 模型列表。参见[官方定价说明](https://www.codebuddy.cn/docs/workbuddy/Pricing)。

### 2.3 本次范围

本次包含工具发现与执行、动态模型目录、角色配置、会话与运行展示、积分读取和展示，以及必要测试和使用说明。支持当前 CLI 正式提供、适用于开发工作流的内置模型和已配置自定义模型；自动路由选项按原生能力开放。

本次不建设腾讯账号池、自动切号、自动签到或充值功能，不接入图片、视频等专用生成模型，不迁移 WorkBuddy 历史会话，也不增加 DevFlow 的审批状态或质量关卡。共享组件带来的群聊工具选择变化需要回归，但不扩展群聊业务功能。

## 三、总体实现思路与依据

增加独立的 `codebuddy-code` 适配器，界面名称统一为“CodeBuddy CLI”。执行继续走 DevFlow 现有子进程管理；模型和账号信息优先通过官方 SDK 的查询能力读取；积分由独立的账号额度读取模块提供。前端在现有额度入口增加积分视图。

先核实 CLI 版本、认证、模型发现和积分来源，再实现适配器及数据契约；随后接入配置和页面，最后完成隔离回归与真实账号验证。积分读取和执行互相独立：查看额度不能触发模型推理，额度查询失败也不能被当成模型调用失败。

以下依据决定实现边界：

1. **CLI 可以承担执行。** 官方说明支持 `--print`、`--output-format stream-json`、`--model` 和 `--resume`。开发时以选定版本的实际参数和输出为准，不直接复制 Claude Code 的参数、权限或事件解析。[CLI 参考](https://www.codebuddy.cn/docs/cli/cli-reference)
2. **模型目录有公开查询入口。** 官方 TypeScript SDK 提供 `getAvailableModels()`、`supportedModels()` 和 `accountInfo()`。首选验证这些接口能否在不发送推理请求的情况下读取当前有效目录；不能假设存在 `codebuddy models` 子命令。[SDK 参考](https://www.codebuddy.cn/docs/cli/sdk-typescript)
3. **模型目录受项目配置影响。** 项目级 `.codebuddy/models.json` 优先于用户级配置；同 ID 模型可被覆盖，`availableModels` 也有覆盖规则。缓存必须体现项目作用域，不能只按工具名缓存。[模型配置](https://www.codebuddy.cn/docs/cli/models)
4. **用量与余额必须分开。** `usage_update` 报告已发生的 Token、积分消耗，不能证明账号还剩多少积分；阶段事件与终态累计值也不能重复累加。[非交互模式与用量事件](https://www.codebuddy.cn/docs/cli/headless)
5. **真实余额仍需核验读取方式。** 官方介绍了官网“套餐与用量”查询入口，但本轮未确认可直接用于 DevFlow 的余额读取接口。真实余额来源是首阶段必须解决的接入问题，不能用套餐标称额度或会话消耗推算代替。[查看积分使用情况](https://www.codebuddy.cn/docs/ide/Account/usage)

## 四、开发任务与完成条件

### 4.1 核实正式 CLI 与账号能力，确定可维护的接入路径

这项工作确定 DevFlow 实际调用什么程序、使用哪个账号，以及模型和积分从哪里取得，避免界面完成后才发现无法执行或查询余额。

1. 在进入开发执行阶段后，优先复用已安装的正式 CodeBuddy CLI；确需安装时使用官方分发，记录实际 CLI、SDK 版本及入口路径。不得把 WorkBuddy 内置包认作独立 CLI，也不复制整个桌面安装包。
2. 核对服务区域、账号或企业身份、有效认证方式与 CLI 权益。认证由 CodeBuddy 原生登录或用户已有配置负责；DevFlow 不复制 WorkBuddy 凭据、不伪造登录结果。区域和环境变量遵循[官方认证说明](https://www.codebuddy.cn/docs/cli/iam)。
3. 读取真实帮助和版本，验证流式输入输出、指定模型、指定会话恢复、只读权限和停止行为。官方页面对部分权限交互能力的描述存在差异，必须以选定版本实测结果确定支持范围。
4. 验证 SDK 模型、账号查询是否可以只初始化而不提交用户消息；获取当前项目的有效模型目录，并与 CLI 原生模型选择器核对。若需 SDK，锁定版本并更新仓库锁文件，不在运行期间自动安装或升级。
5. 核实账号余额来源、认证要求、单位、精度、总额与资源包是否重叠、到期规则及更新时间。优先正式查询接口；若只能使用客户端内部接口，单独封装、记录版本适用范围，并用当前账号与官方用量页对照，不能宣称存在稳定的公开额度 API。

**完成条件：**形成简短接入结论和脱敏样例，确认独立 CLI 执行、无推理的模型查询及真实积分查询的具体路线。若余额只能显示“未知”，可以继续独立模块开发，但本需求不得按完整交付验收；需先解决数据来源或明确记录仍受阻的部分。

### 4.2 让 CodeBuddy 成为可执行、可恢复的工作流工具

这项工作把用户的工具选择落实到真实 CLI 调用，并让 DevFlow 正确处理运行、停止和异常。

- 在契约、注册表、可执行文件解析、目录识别和展示名称中加入 `codebuddy-code`。按“显式路径 → 正式 CLI 的常见安装位置及 PATH”发现工具；`cbc` 别名必须通过产品身份检查。
- Windows npm 的 `.cmd` 包装入口应解析到实际 Node 入口，通过参数数组启动。兼容带空格和中文的路径、长提示词及标准输入；禁止拼接 shell 命令传递提示词。
- 共用同一套路径解析结果完成发现、探测、模型查询和执行，避免设置页检测成功、实际启动却找不到工具。
- 按工作流用途设置原生权限：规划和复核使用经过验证的只读限制；开发、整改、测试和提交使用对应工作区权限。限制也覆盖子代理及可写 MCP 工具，不能只依赖提示词要求“不要修改”。不支持必要权限时，在启动前显示明确原因。
- 使用独立会话 ID 绑定工作流和运行轮次；恢复时只使用已记录的会话 ID，禁止用“最近会话”代替。新任务不得串接用户其他 CodeBuddy 会话。
- 解析初始化、消息、工具调用、结果、错误和会话标识，接入现有运行观察及结果回执。只有原生事件明确报告的型号才能标记为“实际模型”；请求配置不能充当实际运行证据。
- 用户停止或暂停时只处理本轮受管进程及其归属明确的子进程；等待停止确认，拒收过期回执，不结束用户手动启动的 CodeBuddy 或 WorkBuddy。
- 登录失效、模型无权访问、额度耗尽、限流、网络错误和协议不兼容分别映射到现有故障处理。原生请求用户授权时沿用现有人机交互机制；不能在无界面进程中永久等待输入。

**完成条件：**隔离工作区能够启动任务、取得结果、停止并续接原会话；只读角色不会修改代码；并发任务和用户已有会话互不干扰。

### 4.3 让模型列表与当前账号、项目配置一致

这项工作让用户看到当前 CodeBuddy 真正提供的模型，并保证选择后传入正确的原生 ID。

- 优先读取 CLI/SDK 当前有效目录，保留原生 ID、展示名称、来源和适用能力。原生目录已合并配置时，直接使用该结果，避免自行合并产生差异。
- 需要本地配置补充时，遵循项目级、用户级、内置配置的优先级及 `availableModels` 规则。读取过程只提取展示和选择所需元数据，不把密钥写入目录缓存、接口或日志。
- 官方模型、自动路由和自定义模型清楚区分。目录列出只表示“已发现”；可访问状态继续使用现有验证机制。安装包静态清单只能作为候补信息，不能标记为当前账号已授权。
- 显式选择使用完整原生 ID，不根据中文名称反推。自动路由使用原生路由 ID；内部轻量、推理场景不能直接冒充固定主模型或思考强度。
- 思考强度仅在所选版本和模型均有明确能力时开放对应档位。接口没有提供能力时显示“使用工具默认”或“不支持”，不套用 Codex 的档位。
- 缓存范围包含 CLI 路径与版本、服务区域、账号或企业、原生配置及有效项目配置。全局默认页展示用户级目录，新建和已有工作流绑定项目后重新解析有效目录。
- 首次读取、手动刷新和配置变化沿用现有目录操作及过期机制；账号、区域、项目或配置切换后丢弃不匹配缓存。刷新失败时保留同作用域旧结果并标明过期，不自动覆盖当前模型选择。
- 模型被删除、隐藏或禁用时保留历史配置供用户识别，并提示重新选择；不得静默换成首项或其他收费模型。已有通用组件中的模型名称特判需审查，避免误删 CodeBuddy 的合法模型。

**完成条件：**同账号、同区域、同项目的 DevFlow 目录与 CLI 有效目录一致；刷新、切换账号和切换项目不会串目录，配置持久化后能准确恢复选择。

### 4.4 接入默认配置、任务配置与角色使用

这项工作保证用户在各入口选择 CodeBuddy 后，工作流按相同规则运行。

- 在全局默认模型、新建任务、任务模型设置，以及复核、整改等现有角色覆盖入口中开放 CodeBuddy CLI。共用模型编辑器，避免重复维护列表。
- 保存、读取、继承和切换继续使用现有 `ToolProfile`、执行配置及模型访问验证。未安装、未登录、版本不兼容和模型不可用分别提示对应处理办法。
- 全局默认变更只影响后续新任务；已有任务保留自身配置。任务切换工具或模型沿用现有切换边界，正在执行的一轮使用已冻结参数。
- 同时处理账号和项目配置变化：不能把旧账号的验证结果继续用于新账号，也不能在续接时静默绑定到其他账号。无法确认会话归属时提示重新选择或验证。
- 检查 DevFlow 工作包、技能与 MCP 结果回传的既有接入方式，为 CodeBuddy 补齐必要客户端配置。尽量采用运行级配置；确需合并用户级配置时只改 DevFlow 管理项，保留已有模型、插件、MCP 和权限设置。
- 共享工具注册带来的群聊和状态栏变化按实际调用链回归；不得出现可选但运行端未注册、或展示为内部适配器 ID 的情况。

**完成条件：**从全局默认、新建及已有任务三个入口均能正确保存和使用 CodeBuddy；规划与执行可分别使用不同工具，覆盖角色仍按原规则生效。

### 4.5 读取并展示真实剩余积分

这项工作回答“当前所选工具对应的账号还剩多少额度”，同时避免混淆账户余额、会话用量和第三方模型额度。

**数据与计算规则**

- 增加独立的 CodeBuddy 额度读取模块，复用第 4.1 节验证的认证和查询路线。额度与模型选择绑定同一账号、区域、企业及配置作用域；只取得非敏感身份指纹，凭据不得进入浏览器或任务证据。
- 在现有额度契约中兼容增加积分数据及读取状态，保留 Codex、Antigravity 的窗口额度格式。表示剩余积分、可取得的总额和已用量、资源包类型、到期时间、来源及观测时间；实际字段见附录建议。
- 优先采用上游明确提供的可用余额。只有确认资源包互不重叠且仍有效时才能汇总；上游总额与资源包明细不能重复相加。不同币种、计量单位或计费主体不能合并。
- 总额或周期不明时仅显示已知余额，不推算百分比。到期时间和重置时间分别表达，不把月积分换算为周额度或 5 小时额度。
- 原生 `usage_update` 可用于显示本次已消耗积分；按真实事件语义去重，不与终态累计值重复相加，也不从账号余额手工扣减。账号余额重新查询后才更新。
- 同一账号的规划、执行角色可以显示同一份共享余额，标注“账号共享积分”；不得合计成两份余额。自定义模型若走外部服务，显示“外部服务额度，当前未接入”，不挂上 CodeBuddy 的积分。

**查询与失败处理**

- 页面读取复用现有工作流额度接口，并为 CodeBuddy 增加可区分的状态；不能把所有错误吞成相同的 `null`。额度查询不提交对话、不切换模型、不触发签到或充值。
- 服务端按账号作用域合并并发请求。初始建议同作用域成功结果缓存 60 秒，前端现有轮询读取缓存；超过 120 秒显示过期。真实接口有更严格限制时调整这些参数并记录理由。
- 单次请求设置有限超时；限流遵循上游重试时间并退避。手动刷新也遵循并发合并及限流，不能反复拉起后台进程或发起推理。
- 同账号查询失败时可显示旧值及原始更新时间；不得用本次查询时间刷新旧数据。账号切换或退出登录时立即停止展示旧账号积分，并丢弃迟到响应。
- 有效余额为零时显示“0 积分”；无数据、字段异常、鉴权失效、超时和不支持查询都不能转成零或满额。余额为零也不能推断所有模型不可用，免费或外部模型以实际权限和调用结果为准。
- 额度查询失败不阻断工作流；真正的调用额度耗尽仍走现有运行失败与人工处理流程，本次不增加自动切号或自动付费回退。

**界面行为**

在当前规划、执行角色旁保留额度入口，CodeBuddy 弹层显示“剩余积分”、数据更新时间和共享范围。能够取得套餐或资源包明细时再显示明细及最近到期时间；未取得的字段不虚构。

加载中、未登录、刷新失败、过期、版本不支持和第三方模型采用不同提示。已有 Codex、Antigravity 的周额度、5 小时额度、共享说明及过期提示保持原有含义。窄屏、悬停、点击固定和键盘关闭行为一并兼容。

**完成条件：**不运行任务也能取得授权账号的真实余额，并与同一账号官方用量页对应；任务执行后能刷新结果。账号切换、失败和零余额均不会产生误导数据。

### 4.6 完成回归、真实验证和交付说明

这项工作证明新增工具可以实际用于工作流，并确认公共配置和额度改动没有破坏原有工具。

先完成源码和测试整合，再按开发指南分别执行全项目类型检查、生产构建及定向测试。自动测试使用隔离 Git、数据库和 CLI 替身；真实账号测试单独记录，替身成功不能证明登录、模型访问或余额读取成功。

前端流程用真实浏览器 E2E 覆盖；执行阶段再用 OpenTabs 按人工方式操作本机测试实例。真实模型仅做已有授权范围内的最小调用，不批量消耗所有模型额度；需要登录时只请用户完成必要认证，不代填身份或复制其他工具凭据。

交付说明分别列出工具链、类型检查、构建、单元、集成、浏览器、OpenTabs、真实模型和真实额度的结果及限制。任一必需检查未完成或失败，不得概括为“已验证可交付”。具体测试与验收见下一节。

### 5.2 真实环境验收

以下结果必须有实际操作依据；不要求为了展示证据额外建设审计系统。

1. **工具能用：**独立 CodeBuddy CLI 被发现并通过真实认证，配置显示明确的工具、版本和账号作用域，不依赖 WorkBuddy 桌面保持运行。
2. **模型能选：**同账号、区域、项目下目录与原生工具一致；选择固定模型后，最小真实任务使用正确的原生 ID。原生提供自动路由时另验该模式，不把路由名当最终模型名。
3. **角色能执行：**在隔离小项目完成一次只读检查和一次小修改及测试；采用与另一工具混合的规划/执行配置验证角色路由。复核角色不得写代码。
4. **会话能接续：**停止当前运行后按记录的会话 ID 恢复，保留上下文；另一个工作流和用户手动会话不受影响。
5. **余额真实：**任务未运行时即可查询余额；在相近时间与官方同账号用量页核对余额、单位和资源包。发生真实调用后重新查询；计费延迟明确标注，不假定余额必须立即或按固定数值下降。
6. **状态可信：**未登录、网络失败、过期、零余额和外部服务模型提示正确。账号切换回归优先使用隔离夹具，真实切换仅在已有授权和可用测试账号条件下进行。
7. **原工具正常：**已有工作流仍能读取、继续运行；旧工具额度和模型配置没有因新增积分类型发生变化。

模型目录包含多个模型，不代表每个模型都已做真实调用。报告必须区分“目录已发现”“访问已验证”和“实际任务已执行”。Windows 本机通过也不能写成其他平台均已通过；跨平台支持范围按实际 CI 和原生验证结果声明。

## 六、执行顺序、交付与风险处理

### 6.1 按依赖推进

| 阶段     | 工作与交付                                                 | 前置条件                                 |
| -------- | ---------------------------------------------------------- | ---------------------------------------- |
| 接入核验 | 确定版本、认证、模型目录和积分读取路线；保留最小脱敏样例   | 进入开发执行阶段，具备所需安装和账号授权 |
| 核心接入 | 适配器、身份作用域、目录、额度契约与读取模块               | 对应原生接口已核实                       |
| 页面整合 | 默认/任务模型配置、角色展示、积分弹层与异常提示            | 数据契约和后端行为明确                   |
| 验证交付 | 正式检查、定向回归、OpenTabs、真实模型与余额验证、使用说明 | 最终源码已整合，所需账号可用             |

各项检查由执行阶段负责，规划复核、规划接管和提交角色按仓库现有职责执行。平台继续按模型结果和用户操作调度，不新增平台测试证明、审批状态或质量复核循环。

### 6.2 必须处理的限制

- **CLI 权益与模型差异：**以实际 CLI 账号为准；WorkBuddy 可用不能直接推导 CLI 可用。权益不足时显示原因，不自动购买套餐。
- **余额接口不稳定或未开放：**优先完成来源核验；内部接口封装在独立模块，版本变化可单独调整。无法取得真实余额时明确受阻，不把空弹层作为完成。
- **官方文档与安装版本不一致：**记录通过验证的版本和能力；不支持的能力明确禁用。保持现有任务参数稳定，升级在新的运行边界生效。
- **原生目录不能覆盖项目上下文：**修正查询工作目录或配置作用域；不能把全局目录冒充工作流目录。
- **源码并行修改：**调研开始时，模型编辑器、模型 API、模型展示和群聊文件存在未提交改动。开发前重新核对最新状态和差异，合并本任务改动，不覆盖或暂存他人工作。

### 6.3 交付、回退与清理

交付包括接入代码、必要测试、使用说明和简短验证结果。说明中写清安装/登录前提、工具与模型选择、积分口径和故障处理；提交、推送及发布依用户授权分别执行。

数据变化优先采用兼容扩展，旧工作流保持可读取。若回退到不认识 `codebuddy-code` 的旧版本，不能直接让旧程序解析新任务配置；需先处理 CodeBuddy 活跃轮次，并将受影响默认和任务配置按用户选择切回已支持工具，保留会话与历史记录。发布时保留必要版本、配置及最小回退材料。

开发和验证的临时产物统一放在仓库 `.local/codebuddy-integration-20261110/`，仅用于本任务隔离数据库、脱敏夹具生成和短期日志。复用已有依赖与工具链，不复制整个仓库或 WorkBuddy 安装目录。测试完成后停止本任务测试进程，核实绝对路径、归属和引用，再删除不再使用的临时文件；不跟随重解析点，不清理其他任务、主数据库、凭据或正在使用的构建产物。

正式回归夹具放在 `tests/fixtures/` 并保持脱敏；必要结论放在 `docs/test/`。真实凭据、原始认证响应、完整聊天记录和重复截图不进入交付。结束时报告实际释放空间；必须保留的材料写清用途和删除条件。本计划编写阶段只保留本 Markdown，未生成测试数据库、安装包或临时日志。

## 附录 B：积分契约与兼容建议

优先在现有额度对象中增加可选积分字段，旧 `buckets[].windows` 保持兼容。最终名称由实现确定，但必须能表达以下信息：

| 信息             | 含义与限制                                                                     |
| ---------------- | ------------------------------------------------------------------------------ |
| 读取状态与原因   | 成功、过期、未登录、不支持、失败；允许在失败时附同账号旧快照                   |
| 账号与计费作用域 | 非敏感身份指纹、服务区域、企业或提供方、当前配置身份；用于缓存隔离和拒收旧响应 |
| 积分余额         | 原生单位及剩余值；总额和已用值仅在来源明确时提供，允许小数，不用缺失值生成零   |
| 资源包明细       | 稳定包 ID、名称/类型、已知余额、到期时间；避免与汇总重复计算                   |
| 时间与来源       | 原始观测时间、刷新状态、上游来源；来源缓存不能伪装为实时数据                   |
| 共享范围         | 账号共享、企业池、特定模型或外部服务；只表达已确认的关系                       |

API 扩展必须通过正式契约验证，并更新客户端解析与测试夹具。若新增数据要持久化，旧记录缺少扩展字段时仍能读取；新字段不能改变已有窗口额度的单位或计算方式。
