# 代码变更面板横向滚动条位置修复

## 背景、现状与目标
用户在工作流详情的“代码变更”页查看文件差异时，发现横向滚动条出现在深色代码面板中间，下面仍有大片空白。用户提供的截图是本次缺陷依据，图中其他任务信息不属于本次修改范围。

代码调查发现：右侧检视器为纵向弹性布局，头部和底部状态栏之间的 `.diff-code-scroll` 已填满剩余高度且设置了双向滚动；它的子层 `.diff-table-container` 又设置横向滚动，但高度随代码内容变化。因此短内容、长代码行的横向溢出被内层接管，滚动条停在代码末尾，不能落在整个可视代码区底部。此结论来自截图与源码核对，尚未运行修改前后的浏览器复现或测试。

目标是：需要横向滚动时，滚动条位于代码可视区底部、UTF-8 · LF 状态栏上方；短内容不再出现居中滚动条，长内容可在任意纵向位置横向查看。没有横向溢出时，不强制出现滚动条。

## 总体思路与依据
统一代码区的滚动归属，让撑满可视区的容器承载横向和纵向滚动；内部代码层只负责按最长行展开，保留至少覆盖整个视口的背景和差异行样式。避免使用固定代码高度、绝对定位滚动条或同步多个滚动条，以免窗口缩放和长文件再次出现错位。

关键定位为 `apps/web/src/main.tsx` 中差异检视器结构，以及 `apps/web/src/style.css` 的 `.diff-code-scroll`、`.diff-table-container`、`.diff-lines-flow`。全屏审查使用另一个 `pre.file-diff`，但共享部分样式，须防止误伤。路径仅作定位依据。

## 开发任务

- [x] T1 让横向滚动条落在代码可视区底部。消除内容层独立横向滚动造成的错位，保留检视器剩余高度自适应、长行不换行及双向滚动；头部操作和底部状态栏不随代码滚走。核对外层布局、内容宽度与溢出传播，避免出现重复滚动条、被裁切的长行或横向撑宽整个页面。
- [x] T2 覆盖布局回归和相关交互。补齐能捕获原缺陷的浏览器回归，覆盖短内容长行、长内容长行、无横向溢出、窗口缩放、文件切换，以及加载、空差异和截断提示；保留文件树/列表切换、路径复制、差异新增删除标记、全屏打开关闭及 Escape 行为。

## 验证与验收

- 单元：本次预计只调整 CSS 滚动布局，不涉及差异解析或业务状态规则。jsdom 不执行真实布局，静态断言 CSS 文本也不能证明位置正确，因此不新增此类单元测试；若执行时确需改变解析或状态逻辑，须补其定向单元测试。
- 集成 I1：以真实差异检视组件和正式 CSS，在浏览器中验证短内容长行的滚动容器。内层不能成为独立水平滚动区；外层有水平溢出，滚动区底边紧邻状态栏上边，允许边框与亚像素误差。滚动后代码位置实际变化，标题和状态栏不移动。先确认该场景能捕获旧代码的问题。
- E2E E1：在隔离后端、真实 Git 仓库和测试数据中，从工作流详情进入代码变更，选择“代码行数少但行很长”的文件，验证滚动条位置和左右滚动可达内容两端；刷新后仍正确。
- E2E E2：选择同时超过视口宽高的差异，在纵向顶部、中部和底部横向查看；确认只有代码区承载双向滚动，状态栏和文件导航仍可用。切换为短行文件并调整桌面与窄窗口尺寸，确认无多余水平滚动、页面不被撑宽。
- E2E E3：回归文件筛选与切换、加载/空差异/截断提示、路径复制、差异行展示及全屏查看，确认共享样式未造成裁切或关闭失效。
- OpenTabs O1：独立于自动 E2E，执行模型使用已可用的 OpenTabs 工具，在隔离真实页面按用户操作顺序复核 E1/E2/E3 的关键场景，实际拖动滚动条并查看截图。此问题与身份无关，优先本地免密入口，不修改用户主服务或已有浏览器任务数据。
- 执行阶段分别完成全项目 `pnpm typecheck`、正式生产 `pnpm build` 和上述受影响定向测试，分别报告结果。使用仓库锁定的 Node/pnpm；现登记的旧验证脚本可能跳过已有前端构建，不能用其结果替代本次正式构建或全项目类型检查。
- 人工验收：用户在代码变更页选择短差异长行文件，确认横向滚动条位于深色可视区底部，左右可拖动、上下可滚动，缩放与全屏查看正常。

## 环境与失败处理
按本任务已登记方式使用独立 worktree，位置在主仓库的 `.worktrees/` 内；预览、后端、测试数据和端口均隔离。保留主服务、数据库、凭据、已有 worktree 和用户改动。本任务不需要新增依赖、数据结构或修改后端差异接口。

若修复造成横向裁切、双滚动条或全屏回归，应继续修正容器宽高与共享样式，不能通过隐藏溢出、强制换行或删除场景掩盖问题。必需验证失败或环境阻塞时明确报告，不能宣称修复完成。推送与发布另需用户授权。
