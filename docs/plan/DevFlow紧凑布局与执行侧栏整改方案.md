# DevFlow 紧凑布局与执行侧栏整改方案

方案于 2026-09-14 完成现场核实，随后用户批准实施本平台整改。整改不恢复 CRM 执行、不批准 CRM 计划。

## 1. 当前暂停的原因

当前 CRM 工作流实际状态为“等待第 2 版计划批准”，不是一次新的、原因未知的执行故障。第 2 版含 12 个模块、42 项细任务和 81 项测试用例。

北京时间的记录如下：

| 时间 | 记录 | 含义 |
|---|---|---|
| 12:19:24 | 执行进入阻塞，运行结果包含 JSON 解析异常 | 之前已修复的日志序列化问题 |
| 14:32:59 | 执行已停止 | 上轮整改期间停止原执行 |
| 14:57:01—14:57:56 | 恢复后再次停止 | 最后一次停止完成时间为 14:57:56 |
| 15:02:56 | 提交第 2 版，进入计划审批 | 细项清单变更后等待原审批流程 |

最后一次停止是上一轮整改中为迁移细项清单执行的停止操作。当前代码和历史保留，没有替用户批准新版计划。截图中的第 1 版、12 项和“如何开始新任务”按钮与当前服务不一致；可能仍停留在旧页面，不能依据截图判断服务又发生了故障。

当前停止事件只保存“执行器已停止”等布尔值，没有停止理由、发起来源或对应动作；被主动终止的运行还被记成 failed 并附笼统的执行失败文案。这是平台的状态解释缺陷。仅靠现有数据库字段不能进一步证明每次恢复的操作者身份，不能补造历史。

## 2. 页面布局

采用左侧导航、中央工作区、右侧可收起执行过程的三栏结构。

```text
┌────────────┬───────────────────────────────────────────────────────┐
│ 项目与任务 │ CRM 低代码创建开发与扩展开发 · 等待批准       [操作]    │
│            │ ●计划 ━ ●批准 ─ ○实施 ─ ○测试 ─ ○验收 ─ ○复核 ─ ○提交│
│            │ 任务 0/42 ░░░░░░   测试 0/81 ░░░░░░  最近：… [过程] │
│            ├──────────────────────────────────┬────────────────────┤
│            │ 概览 计划与图解 开发进度 测试结果 │ 执行过程     [收起]│
│            │ 代码变更 代码复核 测试环境       │                    │
│            ├──────────────────────────────────┤ 当前操作           │
│            │                                  │ 对外回复           │
│            │          当前模块的主要内容      │ 文件修改摘要       │
│            │                                  │ 测试进展           │
│ 使用指南   │                                  │ 失败原因           │
└────────────┴──────────────────────────────────┴────────────────────┘
```

### 顶部空间预算

- 任务标题使用 18—20 px，标题行约 48 px；长标题单行省略，可悬停或按需展开查看全名。
- 阶段轨道约 32 px，使用节点和连线表示已走过、当前和未到达阶段；失败/暂停在当前节点旁标记，不另起大卡片。
- 交付概况和最近活动合并为约 32 px 的一行；始终显示细项完成数、测试通过数及两条小进度条。
- 模块导航约 40 px。桌面正常状态下，从内容区顶部到模块正文不超过 160 px，1440×900 下中央正文可用高度至少 70%。
- 去掉现有大标题下的大段留白、独立大进度卡和概览中的重复交付概况卡。
- 停止或异常时增加一条明确原因的紧凑通知，不用大段功能说明撑高页面。

### 图形进度的口径

阶段轨道表示流程位置，不折算成完成百分比。不能因为走到第三步就显示“完成 43%”。

任务条按已完成细项数 / 当前批准清单的细项总数计算；测试条按当前有效的已通过用例数 / 计划用例总数计算。模块只分组，不进入分母。失败、返工、待复测通过颜色和数量表达，颜色以外保留文字和数字。

无清单时显示“尚未生成清单”，不能显示假 0%。当前新版清单等待批准时显示“待批准清单”，避免暗示已经进入实施。

### 最近活动

顶部只保留一条最新有意义的活动，最长一行并省略超长内容，显示更新时间或距上次更新的时间。点击后定位右侧对应记录。没有当前阶段活动时不展示旧运行的操作作为当前活动。

### 右侧执行过程

- 从中央模块导航移除独立的“执行过程”页签，将现有统一活动投影放入右侧栏。
- 桌面默认宽度 380 px，可在 320—520 px 内拖动；中央工作区至少保留 640 px，空间不足时侧栏转为覆盖式抽屉。
- 第一次进入正在实施或测试的任务默认展开；其他阶段默认收起。用户手动选择后优先保持该工作流的选择，刷新和切换模块不会重置。
- 收起只隐藏面板，不停止执行或丢弃后台日志。入口显示未读进展数量，发生失败时出现醒目标记，不擅自展开打断正在阅读的计划。
- 侧栏独立滚动。用户向上查看历史后暂停自动跟随，提供“回到最新”；详情、原始参数和服务日志继续按需展开。
- 切换任务时同步切换日志，取消旧任务请求或丢弃过期响应，避免其他任务的记录串入。
- 中央正文、左侧菜单和右侧输出各自管理滚动，不让输出刷屏移动正在阅读的正文。

## 3. 暂停、等待和失败的解释

统一增加可审计的中断记录：原因分类、中文说明、发起来源、发生时间、停止前阶段、需要用户做的下一步。由服务端记录真实来源，不信任执行模型自报的操作者。

| 情况 | 顶部展示 | 主操作 |
|---|---|---|
| 本次 CRM 清单修订 | 等待你确认细项清单：12 个工作包已拆为 42 项任务 | 查看并批准计划 |
| 用户主动暂停 | 你在控制台暂停了执行 | 继续这个任务 |
| 平台维护或计划调整 | 因具体维护/计划调整原因暂停，已有修改保留 | 对应的恢复或审批入口 |
| 执行错误 | 具体失败操作、可读原因和发生时间 | 查看错误 / 处理后重试 |
| 等待验收 | 实施与测试完成，等待你实际操作 | 打开验收地址 |
| 等待共享资源 | 等待浏览器或测试资源释放 | 查看排队情况 |

主动暂停的运行记为 stopped/cancelled（界面与交互统一呈现为“已暂停”），不能被正常的进程终止结果覆盖成 failed。真正失败仍保留实际异常。历史记录没有明确人工原因时显示中性文案“执行已暂停，等待处理”，全面统一为暂停与继续逻辑，不呈现强制终止式的“停止”概念。

补充页面版本检查：检测到服务已提供新界面时显示一条“界面已更新 · 刷新”提示；刷新恢复所选任务和侧栏状态，有未保存反馈时不自动刷新。

## 4. 测试环境是什么，当前做到哪里

测试环境是本次任务实际运行与验收所需的组合：前端、后端、它们连接的数据服务、测试数据和访问地址。单元测试不一定需要启动这些服务；集成测试需要相应真实依赖，浏览器测试及用户验收需要能打开的前端和后端。

平台按项目配置分配临时端口、启动指定命令、准备数据并检查服务是否可访问。服务启动命令由项目定义，因此“有测试环境功能”不意味着自动为每个项目安装和启动全套中间件。

本次现场发现：

- CRM 登记了前端和后端启动命令，平台会为它们分配临时端口并验证服务响应标识及前后端连接。
- 数据配置目前是复用外部资源并加锁，不是平台已自动创建了独立本地数据库。
- `D:/Code/crm/crm/scripts/devflow/run.ps1` 的 fixture 分支只打印初始化提示并直接返回 0，没有初始化数据。
- `scripts/devflow/environment.py` 也只有检查提示与成功返回，尚未落实容器、数据库和数据隔离；当前 fixture 分支没有调用它。
- CRM 原批准计划要求专用 MySQL 测试容器、动态连接和隔离数据，Redis/对象存储按工作流使用隔离前缀。当前配置与脚本尚未完整落实该要求。
- 环境记录目前为 stopped，服务清单为空；CRM 当前没有平台确认就绪的验收地址，也没有已登记的真实测试通过证据。

后续按原批准计划先补齐 CRM 的环境准备与校验，核实实际连接、迁移与种子数据、隔离标记、退出码和清理边界，再运行相应测试。修改项目登记配置必须随计划绑定更新，不能使原批准配置哈希悄悄失效。此项属于 CRM 执行计划中的环境工作，不能把它包装成已经完成的 DevFlow 页面调整。

### 测试环境页的用户表达

默认展示：

1. 是否可用，以及“打开验收页面”按钮；只有确实可用时才提供按钮。
2. 前端、后端、数据库等实际依赖的状态。
3. 数据来源是本任务专用数据还是受锁保护的外部测试资源，以及是否可以与其他任务同时使用。
4. 出错时显示具体未就绪的组件和原因。

环境记录、身份值、端口分配信息与原始命令放入技术详情。仅有启动文本或零退出码，不能让尚未验证的数据环境显示“已就绪”。

## 5. 实施范围与验证

| 范围 | 改动 |
|---|---|
| web 主布局与样式 | 紧凑任务头、阶段轨道、常驻指标、中央模块正文、可调整右侧栏 |
| 活动展示 | 复用现有事件投影；补充单行最新活动、未读计数、滚动跟随和任务切换保护 |
| core/runtime/API | 保存中断原因与来源，区分主动停止和执行失败，返回准确的下一步 |
| 环境摘要 | 展示服务和数据准备事实，不从提示文本推断成功 |
| 页面更新提示 | 检测新界面版本，保留阅读上下文和未保存输入 |
| 使用指南 | 同步三栏操作、进度含义、停止/恢复和测试环境说明 |

复用现有任务、测试、审批和提交门禁；不重构业务引擎，不扩大 CRM 业务范围。本轮方案不启动 middleware、不恢复任务、不执行数据库变更。

实施后的验收覆盖：

- 1440×900、1920×1080、窄窗口：标题与顶部信息不挤占正文，阶段轨道和指标不截断。
- 右侧栏展开、收起、拖宽、刷新、切换模块及工作流；过程中日志不断流且不串任务，停止入口始终可用。
- 任务、测试进度与结构化记录一致，阶段节点不伪装成工作量百分比。
- 主动停止、实际错误、等待审批、等待验收、资源排队均显示正确原因和操作；终止进程不会覆盖主动停止原因。
- 仅打印成功的 fixture 不被当作已准备好数据；后端未就绪时不提供虚假验收链接。
- 类型检查、受影响单元/集成回归和真实浏览器布局验收；真实 agy 联调验证侧栏在执行结束前显示进展、停止后原因准确。
- 保留现有 CRM 修改、两版计划和历史事件，不自动批准或恢复业务执行。
