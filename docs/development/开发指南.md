# DevFlow 开发指南

面向参与 DevFlow **源码开发**的贡献者。普通用户不需要本文：正式安装包发布后按 [安装与升级](../guide/安装与升级.md) 使用成品；当前开发预览的源码运行说明也在本页。

> 旧 [pnpm 开发与构建指南](../guide/pnpm开发与构建指南.md) 已归并至本文，避免两套开发者文档。

## 1. 工具链（与源码锁定值一致）

| 工具 | 版本 | 来源 |
|---|---|---|
| Node.js | **≥ 22.23.2** | `package.json` → `engines.node` |
| pnpm | **11.7.0** | `package.json` → `engines.pnpm` / `packageManager` |

**不需要** Go、.NET、C# 或 C/C++ 工具链来构建 DevFlow（历史说明：早期方案曾规划 Go Host / `build:host`，已移除，不要再执行 `pnpm build:host`）。`better-sqlite3`、`koffi` 为必须正确加载的原生依赖；`better-sqlite3@13.0.3` 使用 N-API 预编译（`gypfile: false`），默认无需 node-gyp。

Node 自带 Corepack 时可启用 pnpm：

```powershell
corepack enable pnpm
pnpm --version
pnpm install --frozen-lockfile
```

`packageManager` 固定 pnpm 版本，`pnpm-lock.yaml` 固定依赖版本。`pnpm-workspace.yaml` 保留精确版本保存规则，并允许 `esbuild`、`fsevents` 执行所需安装脚本（`fsevents` 仅适用平台安装）。升级 SQLite 驱动时需重新检查该配置并验证数据库读写。

不要再生成 `package-lock.json` 或运行 `npm install` / `npm ci`。

## 2. 类型检查、构建与测试分别完成

完成本轮全部源码与测试代码并整合后，先完成正式类型检查和生产构建，再执行依赖这些产物的测试。独立测试按实际受影响文件、类或用例安排，不要求各测试层整体串行：

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm build          # 前端与 Node API（含 runner、credential worker 等编译产物）
```

测试使用 `pnpm exec vitest run` 或 `pnpm exec playwright test`，每条命令明确本轮的一个目标文件、类或用例。根据改动、调用链和共享依赖选择相关单元、集成及浏览器回归，不能机械复用少数固定集成文件。涉及前端流程时落实真实浏览器 E2E，并按 DevFlow 测试职责单独完成适用的 OpenTabs 核验。

`pnpm typecheck` 检查产品代码和测试；`tsconfig.build.json` 排除 `tests` 和前端源码，前端构建由 Vite 完成。Vitest/Playwright 仅转译执行断言时不会完成 TypeScript 类型检查，生产构建通过也不能证明测试夹具类型正确。测试导入的 `.mjs` 模块需要有效的类型边界，夹具需跟随当前接口、必需字段与构造依赖更新。

`pnpm check` 当前依次执行 typecheck → build → 无筛选 Vitest 套件；DevFlow 定向验证使用上述独立检查和单目标测试，不默认以该聚合命令替代影响分析。runner/worker 测试依赖当前 `pnpm build` 生成的入口。

检查结论必须仍适用于最终待交付代码。检查后修改或合并代码时，由执行模型补跑受影响检查；不重跑未受影响的已通过目标。分别报告类型检查、生产构建、各层测试及跨平台 CI 的结果，不能用本地通过代表四平台通过。必需检查失败或未执行时不得宣称验证完成、正常交付就绪或发布验证通过；历史失败也需说明对当前候选的影响。纯文档与技能说明修改按内容、引用、格式和技能结构检查，不运行无关源码检查。

这些检查是执行阶段职责；规划复核仍只审代码质量，规划接管修复后交执行测试，提交角色不补跑测试或顺手修代码。完整约定见 [开发验证与交付边界](../../packages/skills/devflow/references/development-validation.md)，不新增平台测试证明或审计关卡。

## 3. 常用命令

| 目的 | 命令 |
|---|---|
| 后端开发 | `pnpm dev` |
| 前端开发 | `pnpm dev:web` |
| 类型检查 | `pnpm typecheck` |
| 生产构建 | `pnpm build` |
| 单元 / 集成 / 全量测试 | `pnpm test:unit` / `test:integration` / `test` |
| 浏览器测试 | `pnpm test:e2e` |
| 启动构建产物 | `pnpm start` |
| 打开工作台入口 | `pnpm open` |
| 账号服务 / 账号页面 | `pnpm start:accounts` / `pnpm open:accounts` |
| CLI 帮助 | `pnpm cli help` |

## 4. 仓库结构（开发视角）

| 路径 | 内容 |
|---|---|
| `apps/api/` | 本地 API 与工作台后端 |
| `apps/web/` | 前端 |
| `packages/process/` | Node 进程运行时、runner、平台 native（koffi） |
| `packages/agy-accounts/` | 凭据 worker 与账号模块 |
| `packages/installer/` | 安装/升级 |
| `packages/service/` | 服务启动与打开工作台 |
| `packages/cli/` | 用户 CLI |
| `packages/contracts/` | 配置契约与 schema 迁移 |
| `packages/skills/` | DevFlow Skills |
| `scripts/bootstrap/` | bootstrap 安装脚本（含开发者 `--source` 模式） |
| `scripts/release/` | 成品打包与发布脚本 |
| `scripts/install-windows.ps1` | **开发者源码安装**兼容入口（非用户默认） |

## 5. 开发者源码安装（非用户入口）

`scripts/install-windows.ps1` 仅用于开发机源码安装/更新：同步依赖、编译前后端、更新本机 Skill 与 Codex MCP，并备份原配置。它**不是** [安装与升级](../guide/安装与升级.md) 中面向用户的一行安装，也不应写进用户快速开始。

`scripts/bootstrap/install.ps1` / `install.sh` 的 `--source` / `-Source` 用于本地完整成品或源码树安装，属于开发者/高级路径；普通用户安装等 Release 资产公开并验收后再启用文档中的正式命令。

## 6. 依赖与磁盘

```powershell
pnpm add 包名
pnpm add -D 包名
pnpm update 包名
```

依赖变更时一并提交 `package.json` 和 `pnpm-lock.yaml`；构建许可变化还需提交 `pnpm-workspace.yaml`。项目使用 pnpm 本机共享存储（`pnpm store path`）；不要复制整个 `node_modules` 到另一个工作区。旧 `.cache/npm` 与历史测试证据、`.devflow` 业务状态应保留。

官方参考：[锁文件导入](https://pnpm.io/cli/import)、[共享存储](https://pnpm.io/settings/store)、[依赖构建许可](https://pnpm.io/settings/build)。

## 7. 测试与证据边界

- 自动回归使用隔离 Git、SQLite、真实后端/浏览器及外部 CLI 子进程**替身**；替身通过 ≠ 真实模型认证。
- 需要真实模型账号的 live 测试与公共 CI 分离；凭据不进日志与仓库。
- 验证分层与平台/工具声明规则见 [客户端兼容性](../guide/客户端兼容性.md)。
