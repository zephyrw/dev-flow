## 必须修复的 10 项问题

### R01 / P1：“切换并继续”没有发送续行参数

位置：apps/web/src/components/ToolModelDialog.tsx:238–243；packages/core/src/model-switch-service.ts:98、252。

点击“切换并继续”时，handleSave(true) 虽选择了 model-switch 接口，却没有发送 resume_after_switch: true。服务端只在该字段严格为 true 时恢复执行。因此原轮次停止、配置保存、弹窗成功关闭后，任务仍处于停止状态。

最小修复：按钮显式传递续行参数；普通“保存供后续使用”保持原语义，并根据真实返回状态决定关闭及刷新。

核对场景：切换后继续原阶段；普通保存不停止当前轮次。

### R02 / P1：续行失败被当成成功，重试也不会恢复

位置：packages/core/src/model-switch-service.ts:247–259；幂等重放 212–213；请求摘要 321–329。

操作先被标记 committed，之后才 resumeApproved。若因待授权、恢复前置条件等抛错，catch 直接返回原成功回执。若进程在保存后、续行前中断，也会留下 committed。相同请求重试直接返回回执，不再尝试恢复。此外新字段 resume_after_switch 未纳入请求摘要。

最小修复：分别保存配置与续行结果，续行未完成前保留可恢复状态；失败向界面返回“已保存但未继续”的实际结果和简洁原因，重试只补做未完成的恢复。续行意图加入幂等摘要，处理 dispatch 的异步失败。

核对场景：续行抛错、保存后中断、相同请求重试及重复成功请求，不重复停机或派发，不丢失原恢复点。该问题在 R01 接通后仍须单独修复。

### R03 / P1：AGY 开关混用版本号，失败后留下部分更新

位置：apps/web/src/components/AgyAccountsPanel.tsx:119；apps/api/src/agy-account-routes.ts:134–160；packages/agy-accounts/src/service.ts:472–477。

前端传 realm.revision，接口却用它校验 settings.revision。接口更新设置后，又把更新前的账号域版本传给 start，而 start 仍然校验设置版本。

已复现：内存数据库中账号域、设置版本同为 1；开启后设置版本变成 2，启动返回 409 settings_revision_conflict，服务仍 stopped。

最小修复：明确统一开关的版本契约；前后端传递对应的设置/控制版本，启动时使用设置更新后的版本。作为同一个协调操作处理设置变更与启动/停止，避免失败后留下半成功状态。

核对场景：首次开启、关闭重开、账号域版本变更、启动失败及重试，界面和真实状态一致。

### R04 / P1：全新状态下无法添加第一个账号

位置：packages/agy-accounts/src/service.ts:1169–1170、1220–1232；初始化 226–250；apps/web/src/components/AgyAccountEnrollment.tsx:31–38。

默认初始化只保存设置，不创建账号域。新增的一次性手动操作分支虽然跳过了“服务必须开启”，却先在 realm_not_found 处失败。

已复现：正常默认初始化的内存账号服务，提交 capture_current 添加请求，返回 404 realm_not_found。

最小修复：在一次性操作的受控入口幂等初始化账号域，保持自动切换关闭；处理首次创建的版本约定，继续使用锁、队列及恢复处理。

核对场景：没有账号域时可以添加首个账号，完成后自动切换仍保持关闭。

### R05 / P1：账号操作未安全收尾就释放凭据锁

位置：packages/agy-accounts/src/service.ts:1807–1812；异常分支 1731–1756、1801–1805。

临时账号锁在 finally 无条件释放，即使进程停止未确认或凭据恢复失败，操作已进入 blocked。

已复现：自动切换关闭，账号 A 下手动探测 B；模拟 PROCESS_STOP_UNCONFIRMED 后，operation=blocked、realm=blocked、活动凭据仍是 B、domainLockHeld=false。

后果：原操作及凭据尚未安全收尾，其他进程已可以取得同一凭据域，造成交叉换号或恢复竞态。

最小修复：仅在确认进程与凭据安全收尾后释放临时锁；阻塞状态将锁交由既有恢复/清理路径持有和收尾。取锁失败、取锁异常也进入统一错误处理。

核对场景：成功、取消并恢复、回滚失败和停止未确认分别检查锁状态；恢复完成前不得开放第二个写入者。

### R06 / P1：换工具却保留旧工具的执行文件与配置

位置：apps/web/src/components/ModelProfileEditor.tsx:197–205；packages/adapters/sdk/src/registry.ts:165–173。

changeTool 新增保留旧 executableRef、nativeConfigProfile 的行为，基线会清除这两个工具专属字段。执行文件解析器优先采用自定义路径。因此配置过自定义 Codex 路径后切到 AGY，验证或启动仍可能指向 Codex；新编辑器还移除了用户清理这些隐藏字段的入口。

最小修复：切换 adapter 时清除旧工具专属路径与配置，或加载新工具已保存的对应配置，不能跨工具直接继承。

核对场景：带自定义路径/配置的 Codex→AGY→Codex，验证和启动均使用当前工具的正确上下文。

### R07 / P2：猜测 AGY 家族导致候选丢失

位置：packages/presentation/src/model-display.ts:129–165、190–197；apps/web/src/components/ModelProfileEditor.tsx:225–228。

没有可信 familyId/variants 的 AGY 条目仍按 -high/-medium/-low 后缀被合并。缺少 fixedValue/variants 时，合并结果没有强度映射，只留下最后一个 nativeId。选择时又把未知强度误写为 not-applicable。

已复现：生产函数 buildModelChoices 收到 model-high、model-low 两条未知元数据候选，输出只有一个 choiceId=model、nativeId=model-low、effortValues=[]、variantByEffort={}。high 无法再选择。

最小修复：仅依赖可信家族与变体映射合并；不足以合并的候选保持独立。保留 unknown 与 unsupported 的区别，不静默清除已有强度。

核对场景：已知家族能分开选择模型和强度，未知后缀及手动候选不丢失。

### R08 / P2：账号操作取消按钮必然返回 422

位置：apps/web/src/components/AgyAccountsPanel.tsx:182–187；apps/api/src/agy-account-routes.ts:296–302。

取消请求只传 request_id，遗漏接口必需的 expected_revision，虽然面板已经持有操作版本。

已复现：按按钮请求体调用接口返回 422 VALIDATION_ERROR，错误字段 expected_revision。

最小修复：传递当前操作 id 和 revision；遇到版本冲突刷新操作状态再重试，不能静默忽略。

核对场景：等待中的账号操作可以取消，版本变化时处理正确，清理结果与界面一致。

### R09 / P2：额度汇总混淆模型来源和周期

位置：apps/web/src/components/CurrentRuntime.tsx:33–41、60–84。

非 Codex 分支沿用全部额度桶，新汇总逻辑再把所有桶写入同一组 fiveHourData/weeklyData；同周期后面的桶覆盖前面的桶，原桶标签被移除。因此模型 A 的弹层可能显示模型 B 的值。新增的周期判断还把 <=360 分钟归为 5 小时、>1440 分钟归为周：60 分钟、2880 分钟等会被错误标注。

最小修复：先确定当前运行对应的模型/账号额度来源，再严格匹配 300、10080 分钟。只对明确的账号共享额度采用共享分支；缺失目标窗口就显示暂不可用，不能用其他周期填充。

核对场景：多模型桶顺序变化不影响当前结果，缺少目标窗口时不展示其他周期数值。

### R10 / P1：审查及修复角色没有当前模型切换入口

位置：apps/web/src/components/ToolModelDialog.tsx:295–301、325–351；packages/core/src/execution-spec-view.ts:148–157。

后端会返回 reviewer/review_fixer/functional_fixer 等真实运行角色，前端的 isEditingActiveRole 却只接受 planner/executor。旧任务修改正在运行的审查或修复模型时只有普通保存，不能切换当前轮次。反过来，该判断只看全局 isDirty，修改无关 Tab 也可能出现会停止当前任务的切换按钮。

最小修复：按当前角色解析修改前后的有效配置，处理继承和显式覆盖，比较实际变化后决定切换入口。Tab 采用服务端实际角色信息，保留旧任务已有配置。

核对场景：旧任务三种覆盖角色均能切换并续行；无关 Tab 变更不停止当前轮次，继承来源变化能够正确识别。
