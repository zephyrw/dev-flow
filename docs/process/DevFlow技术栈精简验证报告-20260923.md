## 修复记录

本轮验证过程中发现并修复了以下测试夹具问题：

### 1. process-protocol.test.ts
- **问题**：测试使用旧格式 `att_1234567890_abcdefgh`，但实现期望 UUID 格式
- **修复**：更新测试使用 UUID 格式 attempt_id（如 `80766c70-8e32-4e3c-9cf9-3203cf6ea5f4`）

### 2. isolation.ts (fixture)
- **问题**：`human_origin` 使用固定端口 14810，但 `server.port` 是随机端口，触发验证错误
- **修复**：动态生成匹配的 human_origin

### 3. node-native-primitives.test.ts
- **问题**：fork runner 时未传递 attempt_id 作为 argv[2]
- **修复**：使用 `randomUUID()` 作为 attempt_id，通过 argv 传递

### 4. runner-entry.ts
- **问题**：Windows 平台 stop() 调用 `process.exit(1)` 过早，'exited' 消息未发送
- **修复**：等待 tool exit 事件后再退出

### 5. recovery.test.ts
- **问题**：使用 `setTimeout(100ms)` 等待进程启动，但新协议需要等待 ready
- **修复**：使用 `await managedProcess.ready` 等待启动完成

### 6. precommit-runtime.test.ts
- **问题**：测试期望 STOPPED 状态，但未确认停止时保持 STOPPING
- **修复**：mock runtime.stop 返回 `confirmed_not_started`

### 7. preparation-failure.test.ts
- **问题**：mock `stop: async () => {}` 返回 undefined，导致状态不转换
- **修复**：mock 返回 `{ status: "confirmed_not_started" }`
