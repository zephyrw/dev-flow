## 统一规则

1. 开发阶段：按原计划任务、模块、文件与接口边界分工，无相互依赖的部分必须多子 Agent 并行实现。主 Agent 协调接口、共享文件及整合，不另外生成替代计划。
2. 测试阶段：全部正式开发和测试代码完成并整合后，再由多个子 Agent 并行运行独立的单元、集成、E2E 目标；不要求按层先后。每条命令明确一个类、文件或用例，各 Agent 负责对应问题的定位、修复与重跑，其他无关目标继续推进。
3. 审查阶段：多个只读子 Agent 按独立模块、调用链或风险范围并行审代码质量；主审汇总去重、处理分歧并检查跨模块问题。只关注功能实现遗漏、正确性、边界和可维护性，不核验执行声明或重跑测试。

仅真实依赖或无法隔离的共享资源冲突才局部串行，需指出具体原因。公共代码问题交一个负责人修复，再由受影响 Agent 定向回归；不冻结无关工作。仍禁止无筛选全量命令、全库通配符和单次多目标拼接，已通过且不受影响的目标不重复执行。规划模型将三阶段分工与真实依赖写入计划正文。平台不增加子 Agent 数量、测试粒度或证明校验，既有两阶段计数与三次接管不变。

## CRM 脚本

修改 [run.py](C:/Code/crm/crm/scripts/devflow/run.py)，新增 [single_target.py](C:/Code/crm/crm/scripts/devflow/single_target.py) 和对应回归文件。

- 测试模式必须提供 `--test`，缺失、通配符、多目标、不存在或歧义目标在启动环境和测试前直接提示。
- Java 根据指定类定位唯一模块，可用 `--module` 消除同名歧义；支持 `Class#method`，不再把同一选择器发送到两个模块。
- 前端单测和 E2E 将指定文件传给真实框架；支持 `--case` 缩小文件内的用例范围。
- 删除整个工作区共用的测试锁；不同前端测试文件、独立前端与 Java 目标可以并行。每个调用仍只选一个目标，单调用的 worker 限制不阻止多个 Agent 并行。
- 仅同一测试目标及实际共享的 Maven 构建目录保留资源锁。冲突指出资源并返回独立的 `exit 3`，没有启动测试，不算测试用例失败。
- 前端单测不再附带全项目类型检查与构建，并关闭共享的测试结果缓存。各次调用使用独立报告目录。
- 全仓源码变化只记录，不因其他 Agent 的无关修改把测试结果改成失败；影响到当前目标的共享代码仍由 Agent 协调和定向重测。
- 保留 agy 同时新增的 S3 地址回退逻辑，以及原来的测试环境隔离和报告记录。

同一工作区的 Java 目标确实共享 Maven 构建产物，隔离并行需独立工作区、构建产物及 Maven 本地仓库；集成/E2E 使用同一 owned schema 时仍受原数据库租约保护，需隔离专属测试库后并行。只用不同类名不能消除这些实际冲突。被 CRM `AGENTS.md` 引用的协作指南也已更新，移除“默认不调用子 Agent”等冲突说明。
