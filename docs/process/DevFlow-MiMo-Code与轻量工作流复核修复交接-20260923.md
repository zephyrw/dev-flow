## 3. 修复后的确定流程

1. 执行模型首次完成开发和测试，交规划模型第一次代码质量复核。
2. 复核通过直接人工审核；有问题则输出详细报告，执行模型整改并测试一次，再由规划模型复核。
3. 第二次复核通过直接人工审核；仍有问题则规划模型直接修代码、不跑测试，随后执行模型测试、修复相关小问题并重测，完成后**直接人工审核**。
4. 人工发现功能问题，由执行模型修复并测试，交人工复测；人工确认后进入规划模型最终代码质量复核。
5. 最终复核通过直接规划提交；有问题则规划修复、不跑测试，执行模型测试和修复相关小问题，完成后**直接规划提交**。
6. 规划模型实际提交任务范围代码，平台消费已有提交完成授权的本地集成。源分支分叉时，规划模型处理相关代码后仍走“执行测试 → 规划提交”，不插入代码复核或人工重确认。

两处执行测试结束都不追加复核；测试中是否改过代码不影响这条路由。平台不计算改动大小，不核验测试真实性、覆盖率、附件或代码质量。新增关联字段、Run 冻结信息、Git 工作区绑定和租约仅用于调度及资源操作一致性。

工作树收尾遵守当前实现：**任务完成后保留工作树；清理需要显式选择**。此前报告 Q04 提到的自动清理不作为本轮实施依据。

## 5. 交执行 Agent 的验证范围

以下为待验证场景，不是已执行结果。应验证实际 Engine → Runtime → Git 调用链，单独验证纯路由函数不足以证明主流程正确。

| 场景 | 预期 |
| --- | --- |
| 初次开发后复核直接通过 | 进入 HUMAN_PENDING，不创建额外整改 Run |
| 初次失败 → 执行整改完成 → 再失败 | 只有一次执行质量整改，接下来真实启动 planner_takeover |
| 规划修复完成，人工前 | 真实启动 executor_test，完成后直接 HUMAN_PENDING |
| 人工功能问题循环 | functional_fix 使用 executor，完成后交人工，不自动关闭人工问题 |
| 最终复核通过 | 真实启动 planner_commit，避免仅断言 queue/outbox 存在 |
| 最终复核失败 | planner_takeover → executor_test → planner_commit，无中间复核或人工重确认 |
| 测试期间修改代码、报告 changed/uncertain 或无附件 | 不增加代码复核、测试证明或人工确认关卡 |
| 连续两份整改报告、旧 assignment、无关 implement 完成 | 下一模型接收本轮报告，无关完成不消耗首次整改机会，历史报告不覆盖 |
| 首次和恢复提示 | planner_takeover 无测试/构建/lint/typecheck 要求且可写代码；executor_test 无“完成交复核”；planner_commit 无“禁止提交”冲突 |
| 四种新用途暂停、need_user、额度重试、重启 | 保留用途、人工前后阶段、assignment；额度重试保持冻结模型/调用配置 |
| 完成一轮后在下一轮派发前暂停 | 恢复下一动作，不恢复已完成的复核或修复用途 |
| 过期 outbox、重复完成、失败退出和停止后的旧回调 | 不覆盖新用途，不错误提交或推进当前任务 |
| repositories 经不同原生结果入口传入 | 信息保留到 completion；缺省时按当前任务工作区的实际 Git 对象处理，无新提交也可表达完成 |
| existing_workspace 提交收尾 | 不重复生成提交；保留用户工作区和 index |
| new_worktree 包含多个任务提交 | 主分支包含完整任务历史，回执目标为登记的源工作区/分支 |
| 源分支已分叉 | 不 cherry-pick 最后一个提交；进入规划修复 → 执行测试 → 规划提交 → 集成 |
| 源分支绑定改变、源工作区有未提交改动或另一任务持锁 | 停留可恢复状态并保留现场，不 reset/stash/强推或删除工作树 |
| 多仓库部分成功、收尾中断、再次重试 | 保留每仓库结果及原候选提交；只继续原集成，不调用旧证据门禁或再生成候选提交 |
