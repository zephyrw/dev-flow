## 交给执行模型的定向测试

继续在上述原 worktree 工作，不改主工作区其他任务。本轮没有增加验证工具或独立测试脚本。使用以下现有目标，按实际接口补充必要用例；各目标独立运行，不扩成全仓回归。

1. `tests/integration/cli-session-adoption.test.ts`
   - 经真实 adopt API 验证：ExecutionSpec.revision 与 ToolProfile.revision 不同仍能按正确 profile_ref 接管；planner/executor 都能精确选择。
   - 未知 profile ID、错误 profile revision 不得自动使用执行配置；解析结果 resolved=false 必须拒绝。
   - 底层直接调用的成功用例须明确传入完整服务端身份；缺身份应失败，不能恢复生产代码的固定默认值去迎合旧 fixture。
2. `tests/integration/project-asset-migration-recovery.test.ts`
   - 两仓库任务移动非主仓库：主 cwd 保持不变，完整 workspace identity 和查询键更新，binding ID/conversation ID 不变。
   - apply、resume、rollback 都保持相同规则；已存在不同 binding 的目标键不得被覆盖。
3. `tests/integration/cli-session-migration.test.ts`
   - 旧 `.codex` 等目录简称与当前绝对配置域使用一致的键；已有绝对配置目录按同一规范处理。
   - 账号环境覆盖优先级与运行端相同；确实缺账号的候选不可应用，不生成 local/default-account 占位绑定。
4. `tests/integration/project-material-ownership.test.ts`
   - 新计划按 material_id 读取；旧数据无 material_id 时，输入版本 N 的已完成规划 Run 对应第 N+1 版材料。
   - 不同 Run 的同版本材料不能靠首条顺序选取；明确关联缺失、原件丢失或修改不得显示旧缓存。
   - 真正没有项目材料记录的历史计划仍可使用原兼容路径；pending 逻辑保留。没有 design_ref 的计划也检查 material.source_hash，原始字节 hash 与规范化正文 hash 分别按现有语义处理。
